- **Heavy local phases run under the machine-wide slot semaphore.** `pnpm heavy <cmd>` (equivalently `python3 scripts/with-heavy-slot.py -- <cmd>`) takes one of N flock'd slots in `/tmp/fx-heavy-slots` and then `execvp`s into the command, so the command IS the wrapper process: the caller sees its exit status unchanged, the environment is untouched apart from one reentrancy marker, and a crash — SIGKILL included — releases the slot at process death with zero cleanup code. This exists because roughly nine concurrent arcs, each individually well-behaved and each free to run a full suite, exhausted this machine's memory on 2026-08-10 (12 `vm-compressor-space-shortage` JetsamEvents, hard reset, ~2 h of wall clock lost across every live arc); no other layer imposes admission control ACROSS worktrees. Classification is by INVOCATION SHAPE, never by alias.

  **MUST wrap** — any full-suite vitest run: `pnpm test`, `pnpm test:fast`, or any `vitest run` not scoped to an explicit file list. Any non-interactive playwright run: `pnpm test:e2e` and its scoped-config aliases, any `playwright test` without an interactive flag, plus the screenshot captures `pnpm screenshot:gallery` and `pnpm screenshot:help` (their config runs an inner 8192 MB build, `playwright.screenshots.config.ts:128`). Any build: `pnpm build`, direct `next build`, or a `next build` run through `scripts/with-admin-dev-flag.mjs` — that script's own build lock is WORKTREE-LOCAL, because `ROOT = process.cwd()` (`scripts/with-admin-dev-flag.mjs:42`) and the lock file lives under that root (`scripts/with-admin-dev-flag.mjs:97-98`), so it bounds nothing across worktrees. The mutation harness: `pnpm mutation:guards`, any `--project mutation` run, one slot per concurrently-running shard batch. **Transitive shape rule:** a command is classified by what it TRANSITIVELY launches, not by its own surface shape, so an explicitly-scoped or non-suite outer command whose body spawns a heavy phase is wrapped at its own outermost entry. Current known members: `RUN_BUILD_ARTIFACT_GATE_TEST=1 pnpm vitest run tests/admin/build-artifact-gate.test.ts` (scoped vitest, but its helper runs `pnpm build` twice, `tests/admin/build-artifact-gate.test.ts:73`; the env gate is load-bearing — without it the suite is `describe.skipIf(!RUN)` at line 103 and stays unwrapped) and `node scripts/share-link-flash-adversary-matrix.mjs` in full mode (it runs non-interactive playwright, `scripts/share-link-flash-adversary-matrix.mjs:1014`; the mode is load-bearing — `--quick` spawns none and stays unwrapped, line 1215). The derived cover is the sweep `rg -n -U 'execFileSync\("pnpm",\s*\["build"\]|execFileSync\("pnpm",\s*\["test:e2e'` over `tests/` + `scripts/` — rerun it when authoring changes to either tree rather than trusting that member list.

  **MUST NOT wrap** — any INTERACTIVE playwright invocation, identified by shape: `--ui` (including the `pnpm test:e2e:ui` alias), `--debug`, or a `PWDEBUG`-set environment. These are unbounded-lived and a slot held indefinitely starves every other arc; run them unwrapped and sparingly. Scoped vitest runs with an explicit file list, `pnpm typecheck`, `pnpm exec eslint .`, `pnpm format:check`, codex dispatches, CI polling, git/gh operations, and spec/plan authoring all stay unwrapped — wrapping them would put the phases that dominate arc latency behind a queue they never needed. Long-lived servers start OUTSIDE the wrapper: `next dev`, `next start`, and pre-warmed dev servers hold a slot for their whole lifetime, and the suite hitting them is the heavy phase, not the server.

  Wrap the OUTERMOST command only — an inner wrap under a live holder passes through with a surfaced notice instead of self-deadlocking, so it is harmless, not correct. Closeout and CI-stage runs set `FX_HEAVY_PRIORITY=1`, a best-effort bias toward the nearest merge rather than a queue position. NEVER set `FX_HEAVY_SLOT_DIR` in a production session: two dirs are two independent semaphores and the divergence is undetectable by design (tests point it at a per-case tmpdir, which is why the suite is safe to run under the wrapper). Capacity changes go through `python3 scripts/with-heavy-slot.py --recreate --slots <N>` ONLY — editing `config` by hand or `rm -rf`ing a live slot dir hand-builds the recreation races `--recreate` exists to prevent.
