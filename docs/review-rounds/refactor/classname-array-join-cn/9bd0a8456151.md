**Examined:** all 42, classified by whether the finding named a way the proof could pass while the
migration changed rendered output (a REAL false pass) or a way the proof was merely imprecise.

Thirty-five were real false passes. That number is the story, and it is not a story about
enumeration: the arc's whole claim is "36 sites were rewritten and nothing rendered differently,"
and every one of those 35 was a concrete input where the proof said yes and the output moved. A
sample, each probed by the reviewer with the escaping input:

- The baseline oracle was cast, not validated: `NaN > 0.5` is false, so three correctly-named EMPTY
  objects accepted any geometry at all.
- `--base` was required but never verified, so the stale pre-rebase anchor — the exact value the
  script's own header warns about — passed silently.
- Operand normalization collapsed whitespace INSIDE string literals, making `"a  b"` → `"a b"`
  compare equal in the proof built to catch precisely that.
- The base separator was never compared: `cn` emits one ASCII space, so a base joined with `"\t"`
  had identical form, identical operands, different output.
- Identifier operands were compared by SPELLING, so `const base = "class-a"` → `"class-b"` passed.
- A declared C1–C6 delta could rewrite a conditional's DISCRIMINATOR, selecting a different branch.

**Mechanizable** — one candidate, and it is the reason this stage took five rounds rather than one:

**An equivalence proof needs a mutation gate, not a review loop.** Every round followed the same
shape: the reviewer constructed an input, ran it through the shipped script, and showed the script
reporting OK while the rendered string changed. That is mutation testing performed by hand, one
mutant per round, at roughly 25 minutes of dispatch per mutant. This repo already has the
machinery — `tests/mutation/source/registry.ts`, `pnpm mutation:guards`, spec
`docs/superpowers/specs/ci/2026-08-04-source-mutation-guard-gate.md` — and AGENTS.md already says
that for an enrolled surface the convergence criterion becomes "mutation score plus an empty
unaccepted-survivor set," both machine-computed. **These two scripts were not enrolled, and that is
the defect.** Enrolling them would have moved 35 findings from five review rounds into one ~90s
local run, and would have replaced "name an input the guard misses" — which does not terminate —
with a closed operator set over a finite program, which does.

The self-test grew 10 → 27 rejection paths plus 6 reconcile premises across these rounds, which is
the same information the mutation gate would have produced, obtained the expensive way.

**A second, sharper instance of the same lesson closed at R5.** `isInClassNamePosition` — the
predicate deciding whether a join feeds a `className` — was extended in three consecutive rounds:
R3 added variable bindings, R4 added alias chains, R5 arrived with late assignment, function
declarations, parameter defaults and destructuring. That is unbounded by construction, because
className-ness is a DATAFLOW property and a lexical walk can always be routed around by one more
hop. Rather than patch a fourth time, the predicate was DELETED and the exemption key replaced with
one that is closed: `<file> :: <enclosing function> :: <operand signature>`. It ranges over a finite
program instead of an open set of routing shapes, and escaping it now requires reproducing the data
join's operand signature inside the same named function — at which point the "escape" is code that
renders `leg.date` as a CSS class. **Three rounds on one vector is exactly the trigger this repo's
own rule names; the fix was to change the question, not to widen the answer.**

Filed rather than built here: enrolling a one-shot script surface is a registry change with its own
before/after numbers, and building it inside a lint-coverage migration is the scope blowout
class-sweep exception (c) exists to prevent.

**Judgment** — three calls where a rule would not have helped:

- **The threat-model fence held, and then I chose to cross it.** R3 raised a locally-shadowed
  `Boolean` and a locally-shadowed `cn`. Both are pathological rather than ordinary authoring, and
  my brief fenced deliberate obfuscation out. But the walked set is 18 declared files, so proving
  their absence cost one loop and removed the argument permanently. Fencing was defensible;
  closing was cheaper than defending. That is a judgment about the cost of an argument, not about
  the threat model.
- **The inert-connector disposition.** C1's `max-w-[60px]` is 0-width at every viewport for a
  structural reason, so its rect comparison is `0 == 0`. Keeping both baseline keys as a
  regression tripwire that ASSERTS the 0-width state — rather than deleting them or pretending
  they discriminate — is the honest option, and R2 and R4 both examined it and agreed. R2 then
  found the real gap underneath it: the token proof was not bound to the production site, so
  `max-w-16` would have passed everything. The disposition was right and incomplete.
- **`x`/`y` recorded but not compared.** A locally-captured sub-pixel position verified on a Linux
  CI runner is the byte-comparison lesson in miniature; width/height carry the whole claim for a
  `max-w` and a `min-h`. Two rounds examined it and neither disputed it.

**Infra:** two events, one costly.

The first three dispatches of R1 all returned `no_verdict` with `failureShape: no_o_file` after 3
attempts each. This was NOT the documented silent-death/reaper pattern — the reaper log was clean
and every attempt failed identically and immediately with
`ERROR: You've hit your usage limit ... try again at Aug 11th, 2026 6:21 PM`. A second Codex account
at `~/.codex-ship-prefetch` turned out to have a REVOKED refresh token, so the run escalated once
and set `blockedOn`. The limit then cleared on its own well before the quoted reset, and a
`--stage task` probe confirmed it in ~10s. **Lesson: probe the account before believing a quoted
reset time**, and record `no_verdict` as an infrastructure fault rather than a review outcome —
which the corpus does, so those rows correctly do not count as rounds.

The second: at a measured load average of 57 (several arcs ship concurrently on this machine) the
eslint coverage pair failed with `Atomics.wait() failed: timed-out` inside the plugin's synckit
worker. A scheduler failure that says nothing about the rule. Raising `SYNCKIT_TIMEOUT` took the
test from a reproducible 50s timeout to 7.8s green.

**What I would do differently, concretely:** enroll `scripts/verify-cn-operand-parity.mjs` and
`scripts/audit-cn-operand-kinds.mjs` in the source-mutation registry BEFORE the first diff dispatch.
The brief already carried a consequence bound and a threat-model fence, and they were not enough —
because for an equivalence proof the closable criterion is a mutation score, and stating one in
prose does not compute it.
