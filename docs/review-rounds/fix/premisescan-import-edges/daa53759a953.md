## plan — 6 rounds

Declared findings by round: **14 / 10 / 8 / 10 / 6 / 2**.

**Examined:** all six Codex plan verdicts and the repair commit for each (`3295d5ec6`, `1bf4fe6a0`, `4fd2126e0`, `e1bf94c3e`, `514f91fea`, and this one). The round-1 count is explained by the plan not having been reconciled with the spec's six rounds; the rounds after it are not, and they have a single dominant cause worth naming.

**The repairs were the defect source, and twice the repair mechanism was.** Round 2's finding 5 was a P0: Task 1 implemented five production behaviours whose failing tests lived in Tasks 2-5, breaching TDD invariant 1 on every one. Re-cutting the task boundaries fixed it and immediately produced round 3's findings 3, 4 and 6 — three ownership gaps opened by the cut itself (E2's forward branch with no owner, a `resolveExport` that could not reach `factsFor`, a hook call site left comparing `Reach` to `string`). Round 3's repair of the reason-assertion gap was performed with a multi-line non-greedy regex, and that regex produced round 4's finding 1: thirteen call sites left as `expect(actual, {...})` with no matcher, asserting nothing at all. **A regex whose terminator recurs in the document is how both of this arc's silent deletions happened** — the same shape had already removed §4 limits 6-14 during a spec round.

**Mechanizable:**

1. **A plan's test blocks should be COMPILED, not read.** This is the strongest finding of the stage and it arrived late. Round 4 found 13 assertion-free `expect(` sites; round 5 found 59 TypeScript diagnostics in the same blocks — a duplicate helper definition, 43 calls to a helper the previous repair had renamed out of existence, and 13 malformed assertions. Every one is what a compiler reports instantly, and every one was found by a reviewer instead. The repair built that oracle: splice the fenced `ts` blocks into one virtual file in front of the module surface they assume, and run `tsc`. It went from 15 diagnostics to zero in three passes and is now Task 0's gate, so the implementer inherits it. **A plan that ships executable test code should be typechecked by the same pipeline that typechecks code.** Filed as `BL-PLANLINT-ASSERTIONLESS-EXPECT`, widened to the compile check.

   Round 6 then showed the oracle was itself narrower than its advertisement: six `expect(classificationWithModules(…)).toBe("environment-…")` sites compare an OBJECT to a STRING, which `toBe` accepts, so they typecheck cleanly and fail at runtime on every case. The oracle now carries shape checks beside the compiler and reports them on a separate counter, because "the typecheck was green" was itself a claim wider than its artifact — the arc's signature defect, committed one last time by the tool built to stop it.
2. **Bulk edits to a spec or plan should not be made with multi-line non-greedy regex.** Two silent deletions in one arc, both from a terminator that recurs. The cheap rule is a post-edit invariant check — section-number continuity, `it(` count, fenced-block balance — run after any scripted edit to these documents. Filed as `BL-DOCEDIT-POSTCHECK`.

**Judgment:** where each moved behaviour's failing test belongs, and the graduation-versus-review ordering — the whole-diff review must examine the diff that merges, while the IN PROGRESS marker must come off in the last commit, and satisfying both meant landing everything of substance before review and leaving the marker deletion alone afterwards.

**Infra:** none this stage. The read-only sandbox blocked the reviewer's `/tmp` writes in rounds 1 and 4; it worked around them and said so, and probe scratch belongs under the gitignored worktree directory in any case.
