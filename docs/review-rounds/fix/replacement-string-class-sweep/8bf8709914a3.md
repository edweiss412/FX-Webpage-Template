## spec — 4 rounds

**Examined:** all four spec rounds on `fix/replacement-string-class-sweep`
(`docs/review-rounds/fix/replacement-string-class-sweep/8bf8709914a3.jsonl`), declared findings
1 / 4 / 3 / 1, covering the replacement-string judge, the capture-preserving audit that classifies
its repairs, and the probe record that carries both their numbers.

**Mechanizable:** three shapes surfaced, and all three are **declined** — not for lack of value,
but because this repo has already measured the obvious repair as the losing move.

- **A derived count written as a literal schedules its own staleness.** *declined: the repair is a
  practice, not a detector.* The population figure went stale three times across four rounds —
  1201/496, then 1204/498, then 1206/499 — because every artifact this arc commits is a `.mts`
  file containing `.replace` calls and joins the corpus it measures. The tempting arm is a
  `spec:lint` advisory when a spec asserts a cardinality for a population it also names a
  derivation for. That is recognizer growth on a doc scanner, which
  `BL-SPECLINT-DOC-BARE-LINE-NUMBERS-UNCOVERED` records this repo measuring as the losing move,
  and whose own conclusion is that the durable repair is a PROHIBITION rather than a recognizer.
  This arc applied exactly that prohibition — §2 states the probe domain as a command and no
  cardinality at all, and every quoted block in the probe record carries the sha it was run at —
  which removes the cause instead of detecting the symptom.

- **A command inside a fenced block can name a deleted file and nothing notices.** *declined: same
  cause, same owner, already filed.* Round 2 F4 was a reproduction command pointing at a
  superseded script (`ERR_MODULE_NOT_FOUND`); round 3 F3 was a whole quoted OUTPUT block standing
  under the surviving script's name. `CITATION_FILE_MISSING` would catch either in citation form,
  but the parser deliberately skips fenced spans, correctly, since fenced content is quoted rather
  than asserted. This is the same blind spot `BL-SPECLINT-DOC-BARE-LINE-NUMBERS-UNCOVERED`
  already owns — claims inside fences and prose rot where the oracle cannot look — and that row's
  first scheduled step already asks where the prohibition should live. A second row for a second
  symptom of one cause would split the work, not advance it.

- **Two independent derivations of one number are worth keeping.** *declined: a design rule, not a
  task.* The round-2 repair introduced an early `return` that skipped recursion into a chained
  call's receiver, reading 54 offenders where the judge reads 56. No test existed, review had not
  seen it, and the only signal was `count-capture-cover.mts` disagreeing with
  `count-conservative.mts` on a total they compute by different routes. Round 3 then showed no
  acceptance criterion would have caught it either — a return-after-any-match classifier reports
  44 of 56 and satisfies both AC-1 and AC-6. The generalisation is that **a suite exercising
  classification of individual nodes cannot see a traversal that stops early**, so pin the total
  against an independent derivation rather than against the walker's own output. That is now
  AC-1b in this arc's spec; it is guidance for the next guard author, with nothing left to
  schedule.

**One class, three placements, three rounds — the arc's sharpest economy lesson.** Transparent
wrapper resolution was found missing in the ARGUMENT (round 2), in the CALLEE (round 4), and in
const BINDING INITIALIZERS (found by sweeping after round 4, never reported). Each instance was
individually small and individually correct to fix. Together they cost two rounds that one
placement decision would have avoided: resolution belongs in a named helper every kind test
passes through, not at each call site where the next author forgets it. The repo had already paid
for this once — `premiseScan.ts` shipped a hand-written wrapper list covering three of six kinds
and review found a false certification through `satisfies` — and the spec CITED that precedent
while repeating the mistake in a different position. Citing a precedent is not applying it.

Generalisable: **when a resolution step is correct to apply at more than one place, count the
places at authoring time.** If the answer is more than one, the resolution is a helper, and the
review question becomes "does every test go through it" rather than "is this particular test
right", which is a question that terminates.

**Judgment:** the substantive design gaps were three, and all three are one question — what does
a static judge do with an input it cannot resolve — asked at three different depths.

Round 1 asked it of the judge and the answer was a spread: positional indexing stops meaning
anything, so decline and report. Round 3's first finding asked it of the AUDIT that classifies
repairs, and the answer was harder, because the audit had been treating its own silence as a
clean bill: 45 of 56 sites it could say nothing about were folded into "takes the ordinary wrap",
which is true of nearly all of them and is not the same claim. Round 3's second asked it of the
SUITE, and found the acceptance criteria could not distinguish a judge that classifies correctly
from one that stops walking.

Round 4 added a fourth instance of round 2's wrapper class rather than a new question, which is
why the count stopped here rather than continuing.

Each answer was a NARROWING — decline and report, read before wrapping, pin the total
independently — and never a wider recognizer. That is the repair direction the round-economy rule
prescribes, and it is why the accept-set at round 4 is the accept-set from round 1 plus one
refusal. The two widenings a reviewer could have pushed for (resolve spreads; resolve
cross-file and computed const bindings) were declined three times between them and fenced in the
do-not-relitigate list, which is the only reason the round count is four rather than open-ended.

Worth recording honestly: one round was spent on a correction this arc had already found and did
not land. The personalization overclaim was identified during round 2's dispatch, written down,
and then not included in the round-2 repair commit — so it stayed in the spec through round 3.
The lesson is not about review at all. **A self-review finding made while the tree is frozen has
to be carried in the marker's `next`, not in a scratchpad note**, or the next repair commit will
not know it exists.
