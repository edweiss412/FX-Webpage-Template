**Judgment:** rounds 3 and 4 are one question a probe cannot answer, and the interesting part
is the repair direction rather than the findings.

- **R3** planted an ordinary `cookies().set(...)` in each of the three exempt bodies. All
  three stayed accepted: both registries still said read-only, the `scanBody` tripwire stayed
  clear, reconciliation passed.
- **R4** did the same one position earlier — a call-valued DEFAULT PARAMETER, body untouched.
  All three stayed accepted, because exempt units are excluded from the walk before
  `parametersAreInert` runs and the frozen digest covered only `fn.body`.

The obvious repair for R3 was to teach the tripwire `cookies().set`, which invites `signOut`
next, then a filesystem write, then a delegation — the non-terminating question the spec's own
round-3 narrowing had already stopped asking, and the ratchet `AGENTS.md`'s repair-direction
rule exists to refuse. The repair that shipped stops deciding whether an exempt body mutates
and FREEZES it: a whitespace-normalized digest of each exempt body, pinned. It decides nothing
about mutation, only whether the body is still the one whose read-only claim was ratified — so
it cannot be defeated by a verb nobody modelled, and needs no widening when someone invents a
new way to write state. A legitimate edit reds the walk until the pin is updated, and updating
the pin is the moment the claim gets re-reviewed. **That cost is the feature**, and §7 already
named "review of that change" as the process; the freeze makes it executable rather than
hopeful.

R4 is the same move applied to the span rather than the mechanism: an exemption is a claim
about a BODY, and it never said the signature may execute arbitrary code ahead of that body.
`parametersAreInert` now applies to exempt units exactly as to gated ones, and the digest
covers the parameter list too. Notably R4 is **not a new class** — the accept-sets already
pinned that exact execution position for gated units, so it was an inconsistency inside one
walk rather than an escape the design had never considered.

**The transferable finding is that all four rounds are one shape, and the shape has a name
this repo already uses.** Every finding was a recognizer claiming a totality it did not have:
R1/R2 over the forms a function can take, R3/R4 over the positions code can execute in. R1's
repair set the direction and every later repair kept it — **narrowing, never grammar growth**.
The walk carries two deliberately dumb counters that are total over their domain (every
function-like body opening with the directive; every exported VALUE name of a `"use server"`
module) and fails BY NAME on any surplus; `ts.isFunctionLike` replaced a four-way kind check
so a getter or a static class method or whatever form TypeScript grows next is covered without
this file naming it; the whole leading run of string-literal statements replaced index 0; a
recursive `BindingName` walk exhausts TypeScript's two binding-pattern kinds. Four rounds is
one over the trigger, and the honest read is that R1 through R4 were **finding the boundary of
one claim**, not four separate design gaps — the finding rate went 1, 3, 1, 1, 0 and the fifth
round, dispatched with the closed criterion stated and no fresh axis named per the late-arc
brief rule, returned zero on both halves.

**What would have collapsed them: run the repair protocol as a pre-dispatch sweep.** Each of
the four repairs proved itself with a REAL live-tree mutant — a paren-wrapped export added to
`lib/onboarding`, an anonymous JSX action added to `IdentityChip.tsx`, the reviewer's exact
cookie write in all three exempt bodies, a call-valued default parameter on all three exempt
signatures — each redding the live assertion with a clean baseline. That is precisely the
operation each reviewer ran to FIND the defect. It was applied four times as a repair proof and
zero times as a sweep. The walk is a test file and so is not source-mutation-registry
expressible (the runner overlays a target only when a suite imports it, and here the guard IS
the suite), which is why this is the honest form of that gate rather than a symbolic enrolment:
enumerate the execution positions and export forms the walk CLAIMS to cover, plant one live
mutant per position before dispatching, and let the ones that do not red be the round-1 brief's
contents. The arc's own fixtures now do this going forward — nine escape families plus four
negative fixtures at R2, five more at R3, three at R4, each behind a premise asserting the
shared engine still fails to discover it, so a future engine improvement reds the premise
instead of silently voiding the fixture.
