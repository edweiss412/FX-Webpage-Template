**Mechanizable:**

1. **A line-keyed registry re-keys itself, or every unrelated edit above it pays.** `tests/adminAlerts/alertProducerScope.registry.ts` pins alert producer sites by `file:line`, so an eight-line insertion above three untouched `upsertAdminAlert` calls failed the registry in BOTH directions — a full CI round for zero semantic change. This is the second recorded instance on this repo (`2935b4339` re-keyed the same registry after the sync-observability round-1 shifts), and two instances across two arcs is the base rate that makes it mechanizable rather than bad luck: key on a stable anchor (enclosing symbol + code) instead of a line, or have the meta-test print the corrected rows so the repair is a paste rather than a hand-count.
2. **Run the shard CI names, not the suite.** The failure surfaced as `unit-suite-nodb (2)`; `pnpm exec vitest run --project=parallel --shard=2/3` — the workflow's own command — reproduced it in about two minutes, while `pnpm heavy pnpm test` took over an hour behind a loaded machine semaphore to say the same thing plus two failures CI did not have.
3. **A mutant scaled from the constant under test lands on the boundary.** The first two mutants against the new age-gate guard (`maxDuration = 3600`; the gate shrunk to 2h) both landed exactly on the `× 24` boundary and passed — inconclusive, and briefly readable as "the guard does not discriminate". Off-boundary values (7200s; a 1h gate) killed it immediately. Whenever the safety factor is a round multiple, pick mutant values that clear it by a non-multiple.
4. **A guard's own header is a claim, and claims get mutants — this is the whole lesson of rounds 2-4.** Four findings across three rounds were one shape: the guard promised "moving snapshot uploads into a long-running worker reds this test" while successively its root set (R2: API routes only, missing server actions), its detection (R3: a call-site symbol scan, evaded by calling an existing `lib/` wrapper), its file discovery (R3: `.ts`/`.tsx` only, so a `.mjs` worker vanished), and its exemptions (R4: granted per filename, so an exempt script could gain a direct sync call and stay green) each failed to deliver it. Every one was found by a reviewer writing the mutant the header described. The mechanical habit that would have collapsed three rounds into zero: **write the promise as a mutant before writing the guard** — author `scripts/worker.ts`, watch it red, delete it — and repeat for each phrase in the header. The final form needs no call-site recognizer at all, which is the tell that the earlier ones were fighting the wrong problem: containment targets the adapter MODULE, so any edge to it counts however the caller spells the symbol, and the exemption rows are re-checked against the behavior they were granted for.
5. **State a recognizer's blind spots in the recognizer.** The guard now carries a WHAT THIS CANNOT SEE paragraph (runtime-computed specifiers, subprocess spawns) naming them as documented limits under an explicit ordinary-contributor threat model. Absent that, each round re-derives them as findings; present, the fence is in the artifact where the next reviewer reads it rather than in a brief they never see.
