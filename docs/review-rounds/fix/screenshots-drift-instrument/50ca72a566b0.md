# Review-round economy — fix/screenshots-drift-instrument @ 50ca72a566b0

Arc subject: the `screenshots-drift` byte gate, which failed on captures that changed no render input.
Two ledger rows, `BL-SCREENSHOTS-DRIFT-CAPTURE-NONDETERMINISM` and
`BL-SCREENSHOTS-DRIFT-SINGLE-FAILURE-UNEXPLAINED`.

## spec — 5 rounds

**Examined:** every finding raised across spec r1 (5), r2 (3), r3 (3), r4 (1) and r5 (0), plus plan r1 (7)
and plan r2 (7), classified by whether a mechanical check could have caught it before dispatch. Counts are the reviewers'
own declared `FINDINGS:` lines, as recorded in the sibling `50ca72a566b0.jsonl`.

**Mechanizable:** one arm, proven by an incident on this arc and executed before filing rather than
proposed.

`spec:lint` checks marker→AC but not AC→marker. `TASK_AC_UNRESOLVED`
(`lib/specLint/taskContract.ts:376`) fires when a marker's `ac=` id appears nowhere in the plan's text.
Nothing fires when a plan DECLARES an acceptance criterion that no task marker claims. On this arc the plan
declared AC-2, no marker referenced it, `spec:lint` reported **0 hard**, and plan r1 raised it as BLOCKING.
An unowned acceptance criterion is an assertion nobody is scheduled to write.

Filed as `BL-SPECLINT-AC-UNCLAIMED`. The check is the existing traversal read in the other direction and
was run against this arc's own plan before filing — it reproduces the finding on the pre-repair document
and reports clean on the repaired one.

**Judgment:** the other eighteen findings are design defects no lint reaches. Three shapes, each invisible
from inside the design:

1. **The observer inside the observed** (spec r2). Fault branches replace the very selector the capture
   waits on, so the fault class the gate exists for arrives in the one form that unmounts every instrument
   the gate adds. The consequence bound had been written two rounds earlier and was false the whole time.
2. **A denylist wearing an accept-set's name** (spec r2, r3; plan r1). The recognizer was keyed on
   comparison spellings, so a `catch`, a `switch` case, and an IMPORTED type-guard predicate were invisible
   by construction. Repair: key the accept-set on the rendering construct, resolve predicates through their
   declaration rather than their name, and assert that unknown forms are REPORTED — the only assertion that
   separates an accept-set from a denylist.
3. **Assertions that cannot fail** (spec r2, r3, r4; plan r1). A route mutant that could not distinguish
   the parser defect it targeted; an AC with no owning task; a "proven on a real dispatched run" naming no
   command; and AC-2, which took **four rounds and three repairs** to actually assert anything.

   AC-2 is the one worth recording in full, because each repair looked sufficient and the next round showed
   it was not. A directory count passes because the fourteen baselines are already on disk. Completion
   events emitted when the capture function returns pass, because deleting the single `writeFile` leaves it
   returning normally. Reading the file back after writing ALSO passes, because a healthy capture
   reproduces the committed baseline byte-for-byte — the criterion's own premise — so the pre-existing file
   satisfies both the length and the hash check.

   The lesson generalises past this arc: **no assertion over an output path can prove a run produced it
   when the correct output is byte-identical to what is already there.** Three rounds were spent looking
   for a better assertion when the defect was structural. The repair is structural too — capture into a
   directory created empty at the start of the run, so file existence means this run wrote it.

**Infra:** none. Every dispatch returned a verdict — no `no_verdict`, no reaped run, no wrapper fault.

### Why the rounds were not a ratchet

The finding rate DID decay on spec — 5, 3, 3, 1, and BLOCKING to NEEDS-ATTENTION at r4 — and the residue
at the cap is a single finding on one acceptance criterion rather than a spread. The distinction from a
ratchet is worth recording because a raw count alone cannot show it:

- **No vector repeated.** Each round found a different class, and none was "the guard does not pin what it
  claims" against the arc's own suite — the ratchet's signature.
- **The deliverable changed shape twice** on the strength of findings (layer 0 for the replacement class;
  the accept-set inverted from comparisons to rendering constructs). Those are design discoveries, not
  guard growth.
- **No recognizer widened per round.** The accept-set gained forms, but by moving to a structural key that
  subsumes them, not by accreting one grammar corner per round.
- **The arc's own derivations corrected reviewer enumerations twice**, in the direction that reduces
  rounds: a replacement branch (`admin-checkpoint-infra-error`) that an enumeration missed, and a mutant
  proven vacuous because all seven live manifest routes share the `/admin` first segment, so a quote-only
  parser and a complete one derive identical roots.

The honest reading: the subject's failure mode was genuinely unknown at draft time — both ledger rows named
two candidate mechanisms and the replay refuted all of them — so rounds 1-4 were the discovery, which is
where the convergence criterion says genuine design gaps live.

### Disposition at the cap, and the fifth round

Round 4 returned NEEDS-ATTENTION with one finding, on AC-2, repaired structurally rather than by a fourth
assertion. The arc reached the cap with a converging rate and a single open axis, not a widening one.

**A fifth round was authorized and spent, scoped to that one criterion.** The reason is a rule this
session applied twice already: a design change made AFTER a verdict does not inherit that verdict, because
the approval attaches to a document that no longer exists. Self-certifying the structural repair would have
been the artifact-moving-under-a-claim shape, and it was the criterion three prior rounds had each failed
to get right — the last thing worth self-certifying.

The round was bounded to §5's structural-provability paragraph and §9's AC-2, declared terminal, and
instructed to approve plainly on nothing admissible. It returned **APPROVE with 0 findings**, confirming
the criterion directly: deleting the live `writeFile` leaves the fresh directory with zero or thirteen
identities, so the fourteen-identity equality fails, and any passing run must populate all expected
identities in a directory that began empty.

**Cost accounting.** One extra round bought the difference between a shipped self-certification and a
verified one, on the arc's most-repaired assertion. That is the round the cap exists to make deliberate
rather than to forbid.

### What a future arc on this surface should copy

Replay the incident before speccing. Both rows called their artifacts unrecoverable; both were inside
retention, and the replays refuted the filed mechanisms and separated the two rows into different classes.
Roughly twenty hours of retention remained on the older one.
