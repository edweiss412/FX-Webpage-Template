**Judgment:** R1 through R3 are the documented same-axis recurrence pattern, resolved as AGENTS.md prescribes, by narrowing rather than by widening the recognizer. Copying the third predicate column would not have closed the class: the batch and the CAS flip are separate HTTP calls over state that changes between them, so any batch-time destiny is a prediction rather than an observation. The owner reversed his original design choice on that argument, and spec §2.1 fences it in both directions.

Two things worth recording against the tidy version of that story.

Narrowing did not end the findings. R3 and R4 each found a false claim in what remained. Removing the over-reaching class stopped the per-round treadmill; it was not a substitute for reading the code.

And the narrowing was not free of judgment risk in the other direction: R4's finding exists precisely because the spec kept the name claim. Keeping one claim means owning its truth conditions, which here meant a route repair (§3.1b) in an arc whose whole premise was that it would not touch the route beyond a rename.

**Mechanizable:** None of the four findings was reachable by a lint, and the honest diagnosis for two of them is not a missing tool.

R1 and R2 were both cases of asserting a SQL predicate's contents from memory of a grep whose output was already in this session. The full three-column predicate had been printed verbatim earlier in the same arc, and the spec still described it as "the flip's own two columns", twice. A tool that checks a spec's paraphrase of a predicate against the predicate is not worth building. Quoting the predicate verbatim instead of paraphrasing it is free and would have prevented both rounds. Recorded as a habit, not a backlog row.

R3 (an event's timing versus a label's tense) and R4 (a field rebound at one site but read at another) are semantic and cross-file. They are what adversarial review is for.

The wrapper refused the unreadable brief and exited without dispatching, so no `result.json` and no corpus row were written and no round was consumed, which is why this file shows four rounds against five dispatch attempts. ## plan — 4 rounds

**Examined:** R1 NEEDS-ATTENTION/6, R2 NEEDS-ATTENTION/6, R3 NEEDS-ATTENTION/3, R4 NEEDS-ATTENTION/3. One artifact,
`docs/superpowers/plans/2026-08-29-step3-finalize-progress-scope.md`. Unlike the spec stage, which decayed 3-2-1-1, the plan stage held flat then halved: 6-6-3-3.

The reason it did not is the finding worth recording: **three of R2's six findings were defects the
R1 repair commit introduced.** The R1 fix for the missing meta-test inventory declared "this plan
creates NO structural meta-test" while, in the same commit, the fix for the invalid Task 3 red
created one and the fix for the missing transition audit created another. A repair commit contradicted
itself across three of its own six repairs.

**Judgment:** This is `docs/agents/writing-plans.md:23`'s fix-round regression budget failing in
practice rather than in principle, TWICE. Between R1 and R2 I wrote six repairs in one pass and
committed without reading them against each other. I added a self-consistency sweep for R3 — and R4
then found two more stale artifacts of the R3 repair, because that sweep was keyed to the words I had
just written (`grep "three families"`) and the surviving text said "three MUTATION families".

That is the precise failure the rule already names: a grep keyed to the terms a round just changed
cannot see a forward reference phrased differently. The R4 sweep is keyed to the CONCEPT instead — a
regex over number-words followed by `famil(y|ies)`, and a separate one over "who retargets the
assertion" — and it found two more stale counts on its first run. Cost of learning this the slow way:
two rounds, roughly fifteen minutes of dispatch plus repair time.

The generalisable form: after a repair round, sweep for the CLAIM, not for the sentence. Every count,
every ownership assignment, every "N families" is a claim that can be phrased three ways, and the
repair only rewrote one of them.

**Mechanizable:** Partly, and it is worth being precise about which half.

declined: LIM-INDEX-RESTATEMENT-DRIFT, the intra-document variant — a repair round rewrites one
statement of a claim and leaves its restatements elsewhere in the same document. Process-facing under
the 2026-08-25 mint freeze, and its done condition is a property of the linter rather than a number a
product arc would notice moving, so it files here rather than to the open queue. Re-file trigger: a
product-facing arc measurably blocked by the gap.

The contradictions that cost R2 and half of R4 ARE mechanically detectable: a plan declaring "creates
no structural test" while its own task bodies create two, or declaring a guard has three families in
one sentence and six in another, are claim-versus-content and claim-versus-claim mismatches of the
shape `spec:lint`'s universal-claims arm already looks for. Whether that is worth an arm is a question
this arc does not answer, and under the 2026-08-25 process-mint freeze it files no row for it.

The rest is not mechanizable, and it is the majority. Task 3c's invalid RED; the framer-marker
oracle's blindness to CSS transitions, then to standalone `motion.*` and inline styles, then to
stylesheet-driven class names; the nested-duplicate-mount escape; the non-equivalent `display_name`
fallback; a task whose command did not run the suite it edits. Every one is a semantic judgment about
whether a test can fail for the reason it names. Four rounds found four successive holes in ONE
oracle, each a mechanism this repository actually uses, and the convergent repair was not a sixth
pattern but a DERIVED cover parsed from `app/globals.css`. That progression is the round economy's
argument for itself.

**Infra:** The Vitest sandbox limitation reported at spec stage persisted: the reviewer could not
execute the suites it reasoned about, so every RED/PRESERVATION classification was verified by reading
literals. That is a real bound on what a plan-stage review can confirm, and it is the reason the plan
now states the concrete failure each RED catches rather than asserting that it fails.
