**Examined:** a four-row polish arc on the wizard's finalize progress surface: theme the
finalize progress bar, add a noun to the compact count, and two CAS-phase changes the
owner ruled on mid-arc. Rounds returned BLOCKING/10, BLOCKING/8, BLOCKING/4, then APPROVE/0 at the cap.
Every finding across every round was accepted; none was disputed, and none was reversed
by a later round.

**Mechanizable:** nine of the twenty-two findings are one class — *a task's `red=`
command does not transitively execute every assertion the task body promises* — and it
survived being named. The arc wrote a Red coverage matrix after round 2 stating the rule
and deriving its table from the markers; round 3 then returned four fresh instances of
the same class, because the matrix declared the rule while the commands still did not
implement it. That is the useful datum here: a prose rule about commands, written into
the document the commands live in, did not bind them.

Two sub-shapes, both mechanical:

1. *Suites named in prose that the command never runs.* For each marker, extract the
   suite paths from `red=`; for each task body, extract the files it names as carrying
   new cases; report any promised file absent from its own command.

   **The discriminator this needs, found by running the check against this plan:** a
   suite cited WITH a line range is a precedent being pointed at ("following
   `tests/e2e/blocked-row-resolver-transitions.spec.ts:65-125`"), while one named
   WITHOUT a range is being claimed as a place new cases will live. Without that rule the
   check reports one false positive on this plan; with it, zero. Both halves are already
   parseable — the marker grammar is closed, citations are already extracted by
   `lib/specLint/citations.ts`, and the corpus has 130 enrolled plans to calibrate
   against before the arm is turned on.
2. *A multi-suite command whose conjuncts cannot all run.* `spec:lint` ALREADY emits
   `RED_CONJUNCTION` for this, as an advisory. Round 3 executed the arc's closeout
   command and found Vitest never started behind a failing shell gate. The advisory was
   right and was read as noise for two rounds. The cheap change is not a new arm but a
   rule about the existing one: under a plan's own red-contract enrolment,
   `RED_CONJUNCTION` on a command that names more than one suite is not advisory.

**Infra:** the reviewer could not run browser probes — the sandbox refuses `mkdtemp` in
the system temp directory — so every round accepted this arc's recorded engine
measurements rather than reproducing them. That is a standing limit on cross-model review
of any per-engine claim: the opposing model can reason about a CSSOM result but cannot
reproduce it. The arc compensated by recording each probe's command and full output,
including the control read that refuted its OWN earlier assertion, and by leaving that
refutation visible in the document rather than quietly replacing the claim.

**What no round found:** no finding in any round disputed the design, the probes'

round-economy measurement predicts and the reason the cap exists.

**Infra, second entry: two of round four's three dispatches were SIGTERM'd before Codex
produced anything.** Both recorded `status: no_verdict`, `failureReason: "interrupted"`,
`error: "signal SIGTERM"`, and both rows are in this directory's JSONL rather than being
tidied away, because the wrapper writes the row at completion precisely so a killed run
is not invisible. The codex reaper was NOT the cause: it ran within seconds of each kill
and GATED (`gated: 4 live codex tree(s) active; no orphans`, four seconds before the
second), and its kills log's newest entry predates the arc by two days. Another session's
`codex-guard` ran through the same window untouched, so the cause is specific to one
session's background tasks and correlates with that session's turn ending. The dispatch
succeeded only once it was double-forked into its own session and process group
(`ppid` 1), where a group teardown cannot reach it. `setsid(1)` does not exist on macOS,
so the obvious one-liner fails with `command not found` and consumes no attempt. The cost
of the workaround is that a detached run sends no completion notification and must be
polled.
