# Review-round economy — `fix/help-tour-grid-and-settings-card` @ `e7751f61de2c`

## spec — 4 rounds

**Examined:** all four spec rounds (2 / 2 / 4 / 1 findings, NEEDS-ATTENTION throughout), their
briefs, and the repair commits `a014ac4f3`, `98f8257d6`, `bdad0c682`, `3cb4b6518`.

**Judgment:** one vector produced a finding in every round, and it was the same mistake each time —
a claim about layout computed from a model of the container that was missing a term the real page
has. R1 missed that `.help-prose` caps the column. R2 missed that `auto-fit` is continuous, so a
five-viewport matrix reported a worst case of 31.2ch when the true worst was 27.6ch at a switch no
sample touched. R3 missed two terms at once: the shell drops 240px of sidebar plus a 24px gap into
`main` at `md`, making the container NON-MONOTONIC in viewport width, and the errors `nav` is not
bled so its own 704.4px cap made a two-column state unreachable at every viewport — a permanently
collapsed grid that AC-1b and AC-1c would both have passed, because one column neither wraps nor
overflows.

Each round's repair was arithmetic corrected by more arithmetic, and each corrected model was
missing a different term. The findings did not decay through three rounds: 2, 2, 4.

R4 fell to one, and that one was the same vector again — the pre-`md` window, 752 to 767, where
`main` is 720 and the cap binds by 15.6px. Every earlier draft had said the cap binds "only at
1024px and above", read off a table sampling 390 / 768 / 900 / 1024 / 1280 that steps straight over
that window. The §2.3 sweep measures at 4px and had the data; the §2.2 table it fed did not carry
the row, so a claim derived from the table stayed wrong while the measurement beneath it was right.
The lesson is narrower than "measure instead of derive", which R3 already learned: a measured sweep
does not protect the prose that summarises it, and the summary is what reviewers and implementers
read.

That round also found the one place where a criterion contradicted the design it was accepting.
AC-1a said no viewport's measure may regress, and at 752 the baseline is a single 65.8ch column
against the proposed 30.8ch two-column state. The decrease IS the change — a scannable grid instead
of one wide column of cards — so as written the criterion would have failed a correct
implementation. It now says nothing crosses the 28ch floor, which is what it was for.

What closed it was not a better model. R3's repair replaced derivation with measurement — the
proposed CSS injected into the real page and swept 320 to 1440 at 4px, reading computed column
counts rather than predicting them. That is the same lesson `test/modal-wait-helper-adoption`
recorded at its own R4 ("the re-analysis produced a prose table, and a prose table over a live tree
is the format that had already failed three times"), reached here one round later and by the same
route.

The cheapest round to have avoided was R1's second finding. The four pre-dispatch mutants that
`docs/agents/writing-plans.md` mandates for presence guards include exactly the case R1 found — the
expected content present but not live, which for the completeness guard is `/help/admin/settings`
named in prose with no card. Those mutants are specified as a PLAN-stage obligation. Run at spec
time they would have cost minutes and removed a round.

**Mechanizable:** two classes, both declined below.

*Intra-document section references.* R3's fourth finding was a `§2.3` cited before that section
existed, plus two sections numbered `§1.1` since the first draft, which made every ratification
citation ambiguous — including the ones in this arc's own review briefs. `spec:lint` validates that
a cited `path:line` exists and makes no claim about section references.

declined: LIM-CROSS-DOC-SECTION-RESOLVE, whose parked shape is the cross-document form of exactly
this defect; this arc names the intra-document variant, where a spec cites its own section numbers.
The process mint freeze admits a process-facing row only under invariant or product-blocked and
this is neither — the defect is loud the moment anyone follows the reference, and it cost one P2
finding inside a round that was already running for other reasons.

*Layout claims derived rather than measured.* The dominant vector, and not a lint arm: no
recognizer can know that a model of a container omits a term the real page has. The rule that
already covers it is the mandatory empirical spike in `docs/agents/spec-self-review.md`, whose
trigger list names component lifecycle, close/navigation races, optimistic state and undocumented
framework behaviour, and does not name responsive layout. Four rounds say it should.

declined: the repair is one sentence added to a rule that already exists, which is a rule-text
change rather than a mechanized gate, and the process mint freeze does not admit a row for it.
Recorded here so a later arc naming this shape can cite two namings rather than one.
