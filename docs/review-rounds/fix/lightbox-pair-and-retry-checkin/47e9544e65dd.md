## spec — 4 rounds

**Examined:** R1-R4, 17 findings (5, 4, 5, 3), every round BLOCKING. The rate did not decay, and
the last round refuted the structural repair written for the vector that produced most of it. The
stage stopped at the cap without an APPROVE; the re-scope is the orchestrator's call, not this
filing's.

**Mechanizable:**

- **Out-of-render snapshot reads of React state.** R1 finding 3, R3 findings 1 and 2, R4 findings 1
  and 3. Five of seventeen, in three of four rounds, and it is the axis the stage ended on. Code
  scheduled during render (a `setTimeout` callback, a passive effect, a subscriber registered once)
  reads the state of the render that scheduled it, so any rule this spec evaluates during render
  cannot govern it. Two repairs were written and both were refuted:

  1. An intersection making stale writes "inert by construction" (R1-R2). True of rendering, false
     of everything else; R3 showed a queued callback outliving the reconciler and poisoning the next
     retry, and an announcement effect holding a pre-`onLoad` snapshot.
  2. A ref mirroring `retrying`, synced in a passive effect, consulted by every out-of-render reader
     (R3 repair). R4 refuted it on ordering: React flushes pending passive effects before the next
     render, so the announcement effect and the ref-sync effect are both pending from the same
     commit and the ref has not learned about a removal that has been queued but not rendered. A ref
     helps only if it already knows, and this one does not.

  R4 also showed the reader inventory fails open: it named five readers and missed the Embla
  subscriber (`GalleryLightbox.tsx:559`, cited in the very next paragraph as the pattern), both
  components' `<Image>` `onLoad`/`onError` (`Gallery.tsx:749`, `GalleryLightbox.tsx:1319`), and the
  Restart handler. AC-17 was scoped to "readers named in §3.2a", so the omissions were invisible to
  the criterion written to catch them.

declined: LIM-OUT-OF-RENDER-SNAPSHOT-READ, a new slug for this shape. A lint would have to decide,
for every function reachable from an effect, a timer or a subscriber, whether a value it reads is a
render snapshot and whether acting on a stale one is observable. That is dataflow over an open input
space, and the process mint freeze admits a process row only under `invariant`, `product-blocked` or
`recurrence`: none applies, since this blocked no product arc and both hits are inside this one arc,
which the recurrence exception excludes by name. The freeze's admission test also asks for a done
condition that is a number outside the process, and this has none. What the corpus should carry
instead is the shape of the two refutations, because both were plausible and both were wrong in the
same way: a mechanism that learns about a removal on the same schedule as the reader it is meant to
protect protects nothing. The candidate the rounds did not test is the writer-side twin, where every
`setRetrying` call site updates the mirror synchronously rather than an effect mirroring the state
afterwards; that set is CLOSED and greppable, unlike the reader set, but no round proposed it and it
is not adopted here. Re-file trigger: a second independent arc measuring this class as its
non-decaying one.

- **A spec citing a mechanism or symbol that does not exist.** R1 findings 4 and 5, R3 finding 5.
  A connectedness guard credited to shipped code that ships on neither success path; a claim that the
  timing scanner cannot parse a numeric separator when `tests/docs/interactionTimingScan.test.ts:69`
  asserts it can; `nameOf` claimed as a shared helper when it exists only in `Gallery.tsx:401`, with
  zero occurrences in the lightbox. R4 added a softer instance: the ref citation overstated
  equivalence, since the shipped `retryingStateRef` mirrors raw `retrying` while the proposed one
  mirrored `sweptRetrying`.
declined: LIM-CITATION-WELLFORMED-BUT-WRONG, the existing slug, which covers this shape exactly. Its
stated mitigation is the one that would have worked here: verify from the CODE side, open the cited
line and ask whether the sentence is true of it, rather than reading the sentence and looking for
confirmation. This arc's instances decayed after R3, so this is a naming rather than a trigger fire,
and it mints nothing.

- **Normative text contradicting a rule stated in the same document.** R3 findings 3 and 4, R4
  finding 2. An invariant written as a universal over every write, which would have obliged two
  shipped handlers to remove from a set that cannot contain the id; a state table reading `checkedIn`
  raw two paragraphs above the rule saying it is read only through its intersection; and, in R4, two
  paragraphs of §3.2a giving the timer callback mutually exclusive instructions, because the round-3
  repair added the new rule without deleting the sentence it replaced.
declined: LIM-INDEX-RESTATEMENT-DRIFT, the existing slug, at document scale rather than index scale.
That entry's own finding applies here: the class lives in the derivation step rather than in a
location, so sweeping the sites a round names does not close it. R4's instance is the sharpest
evidence in this arc, because it was created BY a repair rather than surviving one.

**Judgment:** R1 finding 1 and R2 findings 1 and 4 were design work and are why the rounds were
worth their cost. R1F1 killed a Restart that bounced through `failed` and exposed a control saying
the diagram could not be loaded while the request was pending, with focus moved onto it. R2F1 caught
that the repair for R1F1 added to `restarting` without leaving `retrying`, so the replacement request
would have carried no deadline: the defect this arc exists to close, reintroduced by its own fix.
R2F4 was a criterion rather than a design, and AC-10 was restated as three observable facts.

**Infra:** none. Four dispatches, four verdicts, no reaped runs and no `no_verdict`.

**What the rounds bought, and the transferable part.** Criteria grew 13 to 20, and six of the seven
added exist because a real finding was invisible to the criteria as written. Two were invisible to a
criterion that COUNTS rather than observes: AC-1 counts live timers and cannot see a window being
restarted, and nothing could see a stale `checkedIn` write until AC-16 asserted it on the NEXT retry,
which is the only place it surfaces. That generalises past React: **a criterion that counts instances
of the right thing passes on an implementation doing the wrong thing at the right cardinality.**
