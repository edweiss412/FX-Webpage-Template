## spec — 4 rounds

**Examined:** 5 spec rounds across both bases (1 at `ae8e9544b55a`, 4 here), 19 findings, every one taken. Not one was refuted, which is itself the summary: the arc arrived with an implementation and a thin spec, and review was doing the spec's own job for the first two rounds.

**Mechanizable:** declined: Eric's 2026-08-25 directive binds this arc to file no `BL-`/`DEF-` row of any facing, so both gaps below are recorded here and on their owning surfaces rather than minted. Neither needs new tooling in any case; both are existing commands nobody ran.

Two of the four rounds were spent on things a command already in this repo would have said for free, before any dispatch.

- **Round 1 F5, the spec-lint gate had never been run.** `pnpm spec:lint` reported 41 hard findings on the first artifact submitted for review: 34 path-less continuation citations, 4 dead file paths, 3 missing required sections. A reviewer spent part of a round enumerating what a gate reports in two seconds. The repair is not a new guard; it is running the existing one before the dispatch, and the same applies to the plan.
- **Round 1 F1 and round 3's whole first finding, the guard that did not discriminate.** `tests/help/walker-routes.test.ts` was RED when the first implementation commit landed, and nobody looked. Worse, when it went green it was trusted to mean the advisory lock was covered, and it does not: the reviewer's probe showed it is equally green with the lock deleted. **The lesson is not "run the suite", it is "read what the green guard actually ranges over".** A guard's PASS is a claim about its own predicate, never about the invariant you hoped it stood for.

**Judgment:** Two findings were genuinely review's class and could not have been mechanized.

- **Round 1 F3, the venue §8.3 gap.** The spec had recorded a live spec violation as though §8.3 permitted it ("revisit if §8.3 is amended"), which had the direction backwards. Catching that needed someone to read the canonical spec against the product, and then it needed an owner, because repairing it arms invariant 8 and the placeholder's wording is itself unsettled. Escalated and ruled on the same day.
- **Rounds 3 and 4 on the lock proof, which is the one axis that actually cost rounds.** Round 3 walked four unsafe transactions through an index-based analyzer. Round 4 walked six more through the whitelist that replaced it. The second repair was the wrong SHAPE of repair, and that is the lesson worth keeping: **a guard that a reviewer escapes twice is not one pattern short, it is the wrong instrument.** The third version has no recognizer at all — it drives the real callers through an injected executor and compares the emitted SQL character-for-character — so the input space went from all of SQL to one string, and the ten known escapes plus every unknown one fail by construction. Two rounds is what it cost to stop widening; AGENTS.md's round-economy rule says to reach for the narrowing at the FIRST recurrence, and this arc reached for it at the second.

- **Plan round 2 F3, the untested join.** The proof composed `lockedStatement` with a body by hand, so it never exercised which key `copyShowLocked` and `deleteShowsLocked` CHOOSE, nor that `runLocked` forwards it. A drift there locks the wrong show while both writes succeed and every lexical guard stays green. Only a call-graph probe finds that; no lexical check would.

**Infra:** None. Every dispatch returned a verdict; no reap, no `no_verdict`, no wrapper failure.

## diff — 4 rounds

**Examined:** 5 diff dispatches across two tight per-surface scopes (test surface, CI-and-guard surface); 4 counted, one reaped mid-run and recorded as `no_verdict`. Six findings, all taken. **Both surfaces ended APPROVE with zero findings.**

**The diff stage is where the review paid for itself, and the contrast with the spec stage is the point.** Spec and plan rounds were mostly repairing the artifacts' own description of the work; the diff rounds found things that were actually wrong with the shipped code:

- A fixture leak nobody had reasoned about: `makeCopy` committed a show, then registered it for cleanup only once the token lookup and reservation copy had also succeeded. The reviewer probed all four downstream failure paths and every one left a committed show with an empty cleanup registry. Ownership now begins where the row does.
- An execution oracle that could certify a partially dark parameterized run, because its case identity omitted the enclosing describe path while the app sibling already carried it. Both the oracle AND its paired resolution counter had the blind spot, which is worse than either alone: a floor and its verifier that share one agree with each other and with nothing else.
- Two documented limits that misstated their own numbers, including one that named a helper as a navigator when it posts through `page.request.post` and never replaces the document.

**Judgment:** three of the four rounds went to a single axis, the executable proof that the fixture lock is held, and the SHAPE of the repairs was the defect. Round 3 mutated the code beneath an injected `SqlExecutor`; the repair moved the seam to a `Spawn`. Round 4 mutated the closure beneath THAT; the repair moved the seam to Node's own `execFileSync`, where there is no project-owned code left below it. **Each intermediate wrapper was one more untested bottom, and moving a seam down one level is not a fix, it is the next round's target.** The rule to carry: when a reviewer escapes a proof twice, stop moving the boundary and remove the layers, then state what remains as a documented limit. Here that residue is Node's `execFileSync` and Postgres's own semantics, both covered by the live e2e run rather than by a unit test.

**Mechanizable:** declined: the same no-new-rows directive. Nothing here needed new tooling; the leak, the oracle identity and the seam were all reachable by reading the code against its own claims.

**Infra:** one dispatch pair was reaped mid-run by an external kill and returned `no_verdict`. Per AGENTS.md that is an infrastructure fault rather than a reviewer finding nothing, so the rows are kept and the round was re-dispatched.

### What would have made this arc shorter

Run `spec:lint` and the guards that own the touched surfaces BEFORE the first dispatch, and for each guard, read its predicate rather than its verdict. That alone accounts for the majority of the findings above.
