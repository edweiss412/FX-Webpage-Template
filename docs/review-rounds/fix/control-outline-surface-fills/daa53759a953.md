Two sub-classes are worth separating because they need different mechanisms. **Cross-document
numeric parity** — the same quantity stated in a spec, a design doc, two ledgers and a plan — is
tracked as `BL-SPECLINT-ENUMERATED-UNIVERSAL-PARITY`, filed by this arc at the spec stage for
exactly this arm; R4's five instances are added evidence for it. **A quantity taken from a
reviewer's prose rather than recomputed** is the narrower half and is the one that actually cost
the round: the 1.15 figure came from the invariant-8 critique's report and was propagated to four
documents without being recomputed, while the citation pass that ran over the same diff verified
that every `file:line` resolved and that the load-bearing ones matched their claimed content. A
ratio is a claim like any other; the pass checked citations and not arithmetic. The derived form
is the one this arc now states in its briefs: **every ratio in the diff is recomputable from
`app/globals.css`, so recompute rather than compare against prose.**

**Judgment:** three findings could not have come from any sweep.

R2's P0 — the archive/marker-removal commit was no longer the PR's last commit — is a process
contract that no test can see, because `tests/docs/_metaLedgerInProgress.test.ts` enforces the
SAFETY property (no in-flight entry reaches main, which never broke) and not the TIMING one that
invariant 12 also states. The repair was to reorder rather than argue: reopen the entry, commit
the other work, re-archive at the tip, with `git diff --stat <base> -- BACKLOG.md
BACKLOG-archive.md` empty as the proof that only the timing moved. That happened once per review round that required a repair — a count this filing deliberately does NOT state as a literal, because the act of committing the correction adds another re-lay and invalidates any number written in that same commit. Whole-diff R8 caught it at six when the history already held seven; R9 caught it at seven when it held eight. The count is `git log --oneline origin/main..HEAD --grep 'reopen the control-outline entry' | wc -l`, and the reason it grows is the whole point:
because each subsequent round required a correction, and each correction would otherwise have
landed past the ledger step. The cost is real and the alternative was worse: the guard cannot
distinguish "archived early and nothing re-added the marker" from "archived last", so a reviewer
reading the contract literally is right every time, and only the author can see that the content
is identical.

R1's P0 — both invariant-8 P1s were deferred to `BACKLOG.md` with no `DEFERRED.md` entry — is
judgment for the same reason. Invariant 8 names `DEFERRED.md` specifically, the two files serve
different purposes (an open deferral queue with un-defer triggers, versus a speculative backlog),
and nothing checks that a gate's P1 dispositions reached the right one. The repair added both
entries with their un-defer triggers and made §12's disposition column name the mechanism rather
than the queue row alone.

R7's mount-rationale finding is the third, and it is the one a sweep would have INVERTED. Two e2e
harnesses said the real `PerShowAlertResolveButton` "cannot mount — no Next runtime, useRouter".
Both specs alias `next/navigation` to `_nextNavigationStub.ts`, so it mounts fine, and an esbuild
probe finds it in the bundle. A sweep keyed on the false sentence would have deleted the local
stand-in and mounted the real component; the stand-in is CORRECT and only its stated reason was
wrong — the label has to come straight off `resolveActionLabels(?code=)` with no server data or
router behaviour in the way, which is what makes the measurement a label measurement. Fixing the
reason and keeping the structure needed reading the harness, not matching a pattern.

**This filing is itself an instance of the class it describes, and that is recorded rather than
quietly fixed.** Its R7 revision carried four typed numbers that the corpus contradicts — a
finding total, a prose-finding count, a re-lay count, and a round attribution for commit
`00833735e`. Whole-diff R8 caught all four. Every count above is now derived: finding totals from
summing `findingCount` across the corpus rows over rows with a real verdict, the re-lay count quoted as its `git log --grep` command rather than as a number — a re-lay count written into a commit that is itself followed by a re-lay is stale on arrival. A document
ABOUT stale cross-document numbers is exactly where a typed number is least defensible, and it
took an eighth round to notice.

**A postscript on the re-lay count, because it is the sharpest instance of this filing's own
subject.** R8 flagged it at six when git held seven; the seventh was created by the very commit
that wrote "six". R9 flagged it at seven when git held eight, for the same reason. A quantity whose
value is CHANGED BY the act of recording it cannot be recorded as a literal at all — the only
stable form is the command that computes it. That is stricter than "derive, don't retype", which
still assumes the derivation survives being written down, and this arc needed nine rounds to find
a case that breaks the weaker rule.
