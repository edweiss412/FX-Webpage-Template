## spec — 4 rounds

**Examined:** the derived cover (`scanInteractiveElements` filtered for `border-border-strong`)
and whether it is a cover; the exemption predicate for switch tracks; the consequence bound's
quantifier; the census counts and per-ground ratios; the transition inventory; the dimensional
invariants; the probe domain and threat fence.

**Mechanizable:** four of the twelve findings across R1–R4 were **stale or false universals** that
a mechanical sweep catches — "every one of the 21 lands on a neutral ground" (R1 F3, twenty do),
"every swapped control carries `transition-colors duration-fast`" (R1 F4, nineteen do), "hover
changes the fill, not the outline" (R3 F3, true on twenty). Each was one grep away. `spec:lint`'s
`NUMERIC_NOUN_MISMATCH` does not reach them because the quantified noun is a class token, not a
number. The generalisable arm: **a spec asserting a universal over an enumerated population
should carry the command that enumerates it**, and this spec now does — §3.2, §6 and §9 each
state their population with the probe that produced it, and §2 now restates NO ratio at all —
§6 is the single source. That last move is the one that actually closed the class: four rounds
ran on a universal in one section contradicting a measurement in another, and re-wording the
universal never worked. Removing the duplicate did. R2 F2 (a corrected count that had not
reached normative text) is the same shape one level down and is what the class-sweep rule
already mandates; it was missed because the sweep was run over the sections that stated the
count, not over the sections that CONSUMED it.

**Judgment:** the load-bearing rounds were R1 F1, R2 F1 and R3 F2 — all one vector, the
exemption predicate, and all genuine design work that no lint could have done. The predicate
went single-token → existential two-branch → universal accept-set, and each form was broken by
one ordinary edit: a replaced token, an appended branch, a conflicting same-branch token. R3 F2
is where it became clear the derivation is not soundly achievable at all — exactness requires
deciding which of two paint tokens on one branch wins the cascade, i.e. a CSS evaluator inside a
test helper. The repair was the AGENTS.md narrowing rule applied literally: kill the derived
predicate, enumerate a five-row registry, and narrow the guard's claim to something decidable by
token presence alone. **The cost of learning that was three rounds, and the honest read is that
two of them were avoidable** — the trajectory (one new input family per round) was visible after
R2, and the rule that names it was already written. The trigger to apply it should be "the
second round on one recognizer", not the third.

R1 F1 was the other genuine one: the cover is not a cover. `<input>`/`<textarea>` are absent from
the scanner's element vocabulary entirely, and an outline painted on a nested child leaves the
interactive element's own class list clean. That is a property of `interactiveScanCore` that no
amount of reading this spec would surface — it took a probe — and it is why the arc's bound is
now quantified over what the cover can see, with the residue filed rather than claimed.

**Infra:** none. Four dispatches, four verdicts, no `no_verdict`, no reaped runs, no wrapper
faults. `lintArm: present` on every round.

**Note for the next arc that builds a class-string guard.**

The three broken predicates are kept in spec §5.2 as a table with their mutants, specifically so
the derivation is not re-attempted without them. The short version: **a predicate over Tailwind
class strings can decide token PRESENCE soundly and cannot decide EFFECTIVE PAINT soundly**,
because effective paint is a cascade question and the class list does not carry the cascade. Any
guard whose claim needs the second is the wrong shape, and the round count will say so one input
family at a time.
