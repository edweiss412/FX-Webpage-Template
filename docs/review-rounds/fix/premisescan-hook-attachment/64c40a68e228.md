### Implementation note, recorded here because it is this arc's sharpest finding

Not a review round — found by the implementation session running the plan's own pre-dispatch mutants
before any diff dispatch, and recorded because the plan INSTRUCTED the defect.

The plan required the expected reason to be built by CALLING the shipped formatter, "never by
re-typing it", on the sound reasoning that a re-typed expectation had already been wrong once. Doing
exactly that puts BOTH SIDES of the comparison on one source: a drift in the wording moves the
expectation with it and the assertion can never disagree. Measured, not reasoned — with the
expectation built from the shipped formatter, a mutant that EMPTIED the reason and a mutant that
APPENDED "and the suite was resolved," (the exact claim the spec's R2 forbids it from making) both
survived all twelve cells.

The witness is now hand-written in the suite and the shipped formatter is asserted against it once,
per cell inputs. Two sides that can actually disagree, and the same treatment was applied to producer
B's wording before its cells were authored rather than after.

The general form is already in the corpus as the rule that derivation is the right answer for a COVER
and the wrong answer for BOTH SIDES OF A COMPARISON. What this arc adds is that the instruction to
derive can arrive from a ratified plan, and that only the mutant tells you which one you have.
