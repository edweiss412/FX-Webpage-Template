## spec — 1 round

**Examined:** the design for `BL-MUTATION-BROWSER-CHILD-LIFETIME` — a per-child wall-clock ceiling for
the browser mutation gate, derived from a measurement this arc took rather than from the source
harness's constant.

**Judgment:** one round at zero findings is the outcome the measurement bought. The spec's contested

## diff — 3 rounds

**Examined:** the whole diff — the call-site swap, the executed timeout proof, the fallback
assertion, the four repaired peers, and the derived disposition guard.

**Judgment: the round that paid for the stage was round 3, and its finding was not a guard finding
at all.** `timeoutMs: number = 0` on `runChild` was invisible to every shipped proof, because both
production call sites OMIT the argument and every test supplied it explicitly, while the constant
test pins only the export. A `0` ceiling bounds nothing — measured, a 200 ms child under it ran to
completion. **The plan had named that exact cover** ("spy on `spawnBounded` and call `runChild` with
NO explicit ceiling") and its neutralization pass had already explained why AC-3 could never reach
it. So the plan was right, the fixture audit had nothing to audit, and the defect lived only in the
gap between a designed cover and a built one. That gap is now closed by a mechanical check recorded
above, derived from the plan's own table rather than from recall.

**Mechanizable: none of the remaining findings, and that is the honest answer rather than a
comfortable one.** Rounds 1, 3 and 4 all landed on ONE axis — the disposition guard's fidelity — and
each repair pointed the same direction, which is why the stage closed at 3 rounds instead of
ratcheting:

- **Round 1:** a file-keyed row disposed of every hit in its file forever, so "a new site fails by
  default" held only for files with no row. Repair: each row kind's claim made executable.
- **Round 3:** the forward bracket scan could be fooled by a paren inside a string, crediting a later
  call's ceiling to an earlier unbounded one. Repair: **delete the need for the parser rather than
  write a better one.** A MEMBER file must carry one accepted ceiling per spawn hit — an equality
  between two counts, where a new unbounded call moves the hits and not the ceilings, and neither
  count needs to know which options belong to which call. A NON-MEMBER row pins a DIGEST of its exact
  hit lines, because a COUNT is defeated by SUBSTITUTION: the probe that proved it swapped a comment
  hit for a real child with the count identical at 1 while only the digest moved. Count answers "did
  something new appear"; digest answers "are these the same things". Both are held without parsing.
- **Round 4:** the shape set was hand-enumerated at three names and missed four of node's spawn API.
  A cover gap, not a classification question, so it was repaired — by DERIVING the names from
  `node:child_process`'s own exports. Its other half, a child whose argument text spells the guard's
  ceiling tokens, needs a string-literal reader and is fenced as spec §6 limit 7.
