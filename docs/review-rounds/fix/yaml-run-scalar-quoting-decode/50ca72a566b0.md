## spec — 2 rounds

**Judgment:** the one finding was worth the round and would not have been found mechanically. AC-4
positively tested a psql site only for the single-quoted style, so an implementation correct on
single quotes and blind on double quotes satisfied every AC — every double-quoted assertion expected

self-consistent, lint-clean, and wrong.

**Mechanizable:** none. What made the finding cheap was the probe record the spec already carried —
the reviewer could run the three spellings and see for itself. The census (zero quoted executable
scalars repo-wide) and the AC-5 digest were both restated by command in round 1, and neither drew a
challenge in either round.

**Judgment:** the first three are one mistake made three times — enumerating what is FORBIDDEN over a
surface nobody can enumerate by hand. This project's accept-set rule predicts exactly that ("a
denylist accepts whatever it did not model"), and I reached for the denylist anyway because the
requirement was phrased as a prohibition: do not touch the delimiter walk. The requirement's phrasing
is not the check's design. What closed the class was inverting the question to what this arc MAY
touch — five named declarations, everything else denied — which needs no model of the seam at all
and made all three earlier holes unreachable rather than patched.

The fourth version's hole is the same rule one level in: an unowned statement class is an exemption
wearing a different name. Default-deny means every class is owned.

**The fifth version's hole is the rule one level in again:** ownership is not a function, it is a
relation. Picking one owner of a line is picking wrong half the time when two declarations share it,
and the fix is to fail if ANY owner is forbidden rather than to choose better.

**The other instrument, the claim sweep, took four rounds to learn to assert.** It began as two
greps that required a fixture and its zero-assertion on the SAME LINE, and in the motivating instance
they are four lines apart — so it reported "no other assertion" for the wrong reason. Repaired into a
windowed matcher that self-tested against known instances, it then gated on its own EXISTENCE: five
known claims must be FOUND, which the entirely unrepaired tree satisfied. Repaired again to require a
supersession marker per hit, it became UNSATISFIABLE — 13 of 26 hits were false positives in
unrelated files where "quoted", "limit" and "zero" co-occur, and no edit in this arc could ever mark
them.

Repaired a third time to gate a finite declared list, it then omitted one site from that list and
suppressed every undeclared hit in a declared FILE — so a live claim in the very file the arc was
editing could not even be reported. Naming part of a file had exempted the rest of it.

The third failure is the one worth banking: **two rounds had gone into tightening a prose recognizer,
and the next round would have gone into it too.** The repair-direction rule says a recognizer that
widens per round should NARROW instead, and the narrowing here was to stop gating on the recognizer
at all. The gate now ranges over six DECLARED sites — finite, exact, satisfiable — and the matcher is
demoted to a discovery arm that must still find all six or abort. Its over-matching is now a stated
documented limit rather than a target.

**Infra:** the review-corpus row count disagreed with the orchestrator's dispatch count, because a
killed dispatch writes `no_verdict` rows that do not count. Reading the corpus rather than counting
dispatches settled it, and the filing threshold moved by two rounds as a result.
