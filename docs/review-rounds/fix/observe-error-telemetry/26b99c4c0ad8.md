Each was repaired by asking a resolver instead of adding a case: the TypeScript symbol table for the first two, the type checker for the last two. The fourth is the sharpest instance, because the third round's repair was *already* semantic and still too narrow — it named a type MEMBER (`string`) where the closable question was the type CATEGORY (is it an object). A rule that lists members grows once per member somebody thinks of; a rule that asks the category does not. The same shape appears once more on the client side, where a rendered label was doing a job only type identity can do (R1 F4, R2 F4, R3 F1 — thirteen collision pairs across three rounds, closed by a runtime type tag plus a `String()`-at-the-leaves writer).

So the mechanizable arm is a spec-time question, and it is cheap: **when a guard spec names a syntactic form — "an object literal with X", "an imported Y", "a bare identifier" — ask whether the compiler can answer that question semantically. If it can, the syntactic version is a recognizer that will be widened once per round.** This repo already forbids parser growth under same-axis recurrence; what it does not yet say is that the alternative is usually sitting in `node_modules/typescript`. Three of the four rounds here would have collapsed into one.

The corollary that cost the most: an accept-set looks complete precisely because it is exhaustive over the forms its author thought of. Nothing in the artifact signals the gap. Only a probe does — and a probe only closes the axis if its fixtures span the *category*, not the instances that happen to have been raised. Round 4's probe scored `0/9` on a fixture set that was entirely string-flattenings, which is how a green measurement can still be measuring the wrong thing.

**Infra:** all three rounds lost their runner. Every one hit `ERR_PACKAGE_PATH_NOT_EXPORTED` for `estree-walker`, because the brief's verification command was `node --import tsx node_modules/vitest/vitest.mjs run <file>` — the node form the fleet rule prescribes for `tsx` *scripts*, applied to vitest, where it loads the config through tsx and trips the export map. `pnpm exec vitest run <file>` works in this worktree and was verified directly. The reviewer compensated by hand-writing AST probes each round, which is why the findings held up; it is also three rounds of rebuilding a runner that was working the whole time. The fleet rule is about `pnpm tsx` and `pnpm exec tsx` and does not extend to `pnpm exec vitest`. Briefs in this repo should say which is which.
