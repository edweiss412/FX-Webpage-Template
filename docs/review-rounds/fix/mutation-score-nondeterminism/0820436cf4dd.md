## diff — 4 rounds

**Examined:** every finding across four paired dispatches (two scoped reviewers per round at base `0820436cf4dd`, dispatched together, so a round is a pair), split by whether the repair changed shipped behaviour or the suites that certify it. **28 findings, none refuted**: 8, 9, 7, 4 by round, with 4 / 2 / 2 / 1 of them against deliverable behaviour. The deliverable curve fell and then flattened rather than reaching zero, and the cap round still returned a real one — a registry row with no deciding suites produced two completed `SURVIVED` observations and exit 0 from a run in which no child executed. Perfect reviewer precision across 28 findings is why each round was authorized; the flat tail is why the cap held anyway.

**Mechanizable:** three of the eight deliverable findings are one shape a check could own — **a step that reports success having observed nothing**. The CI upload was green while uploading nothing (hidden files excluded by default); the adapter exited 0 having delivered 65,536 of 159,926 bytes; and two of my own kill-probes were no-ops that read exactly like passing tests. The generalisable guard is not a lint for any of the three instances: it is that **an assertion whose subject is an absence needs a positive control one delta away**, which this repo already states as the premise rule and which none of these three sites had. The probe case is the sharpest, because it is a guard-on-guard: two of this arc's kill-probes were NO-OPS that read exactly like passing tests (a fabricated `durationMs` against children that really do take 0 ms; a `.replace` that hit the first of two matching call sites), and a no-op probe reports "the test survived" for a mutation that never existed. **declined: no new arm and no new row.** The rule this belongs to is already written — a guard states its premise executably (`tests/_shared/premise.ts`, `BL-GUARD-PREMISE-REACHABILITY`) — and a probe is an ad-hoc script rather than tracked code, so there is nothing for a walker to scan; the durable form is the existing premise rule applied one level up, to the probe rather than to the guard, which is what the in-arc repair does by asserting the match before reading the outcome. Minting a second row for a discipline the first row already states would split it.

**Judgment:** the provenance findings are not mechanizable and should not be. Rounds 2 and 3 each found a real way for the stamp to describe bytes that did not run — an undeclared corpus read, then an A→B→A revert — and the correct disposition differed each time: NARROW the claim and document the limit for the first (what a suite reads is unbounded), TIGHTEN the mechanism for the second (stamping around each run is finite and cheap). A rule that said "always narrow" would have missed the second; "always tighten" would have grown a filesystem watcher into the measurement path of the thing being measured. Which side a finding falls on is a judgment about whether the input set is closed, and it was worth a round each time.

**Infra:** the reviewer sandbox could not run vitest in any round (`EPERM` on the transform cache), so every finding arrived as an in-memory predicate replay rather than an executed suite. That is why two findings were about what a test's predicates ADMIT rather than what the suite does, and it is also why the round-3 probes had to be re-run against real weaker implementations before their results meant anything. Separately, GitHub REST exhausted user-wide mid-arc, which cost one poll cycle and no rounds.


**What the cap bought, stated so the next arc can price it:** rounds 1 and 2 found the defects a careful author would expect (a wrong default, a sorted digest, a substring match). Rounds 3 and 4 found the two that no local gate could: an adapter that truncated its own output and exited 0, and a registry row whose population looked healthy while every observation observed nothing. Both are the same shape as this arc's SUBJECT — a channel reporting success having observed nothing — which is the argument for reviewing an instrument past the point where the finding rate looks flat, and equally the argument for stopping once the axis is named rather than chasing its next instance.
