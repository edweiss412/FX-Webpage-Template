# fix/local-e2e-validation-pooler — base 60dece4d5722

## spec — 4 rounds

**Examined:** whether a spec for pinning the Playwright `webServer` database env, plus a
correction to the `pnpm preflight` warning that misdirects readers about it, was sound before
implementation. Four rounds at one base; three returned one BLOCKING finding each and all three
were accepted in full and repaired.

**Mechanizable:** two of the three findings are one mechanizable class, and it is not the class
the findings appeared to be about. Both r1 and r2 were "the guard ranges over a narrower set than
its claim" — r1 over config FILES, r2 over `@next/env` load MODES — and in both cases the wider
set was already derivable from something on disk: the config files exist in one directory, and
the two load modes are readable off the configs' own `command` strings. A guard whose domain is
*written down* invites this finding once per axis; a guard whose domain is *derived from the
artifact it guards* cannot be narrowed by an author who forgot an axis, because there is nothing
to forget. The repair in both rounds was the same move, applied to a different axis. Something
that walked a guard's domain and asked "is this set enumerated or derived?" would have caught
both before dispatch.

**Judgment:** r3 is the round worth keeping, and it is not mechanizable. It found that every
probe and every planned test arm loaded the hoisted root `@next/env` (16.2.4) while the server
under test runs the copy `next` 16.3.0 resolves — different files, different loader bytes. No
domain check finds that: the set was right, the binding was wrong, and the guard would have been
green about a package no webServer executes. It took a reviewer willing to ask which artifact the
measurement actually touches. Re-probing before accepting it also mattered: precedence turned out
identical on 16.3.0, so the finding moved what the guard measures without moving the repair, and
accepting it wholesale as a behavior change would have been wrong.

**Infra:** two dispatches were lost to wrapper usage errors before round 1 landed — `--stage spec`
requires a `--lint-doc`, and the artifact then had 19 hard `spec:lint` failures, 16 of them one
shape: a backticked bare-port shorthand (`` `:3004` ``) parses as a citation with an empty path.
Both were the wrapper telling me something true, and both cost a dispatch to learn. Linting the
artifact before the first dispatch, rather than discovering it through the gate, is free.

**What the round count does not show.** Four probes run BEFORE dispatching anything each removed a
defect that would otherwise have been a round: the override-vs-scrub negative control, the T1
oracle, the `loadEnvConfig` in-process contamination that falsified T2's first design outright, and
the `--no-db` warning-flush check. The in-process one is the instructive case — the design was
plausible, self-consistent, and wrong, and no amount of re-reading would have shown it. Cost about
ten minutes total against roughly twelve minutes per review round.
