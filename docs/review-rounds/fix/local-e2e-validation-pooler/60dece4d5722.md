## spec — 4 rounds

**Examined:** whether a spec for pinning the Playwright `webServer` database env, plus a
correction to the `pnpm preflight` warning that misdirects readers about it, was sound before
implementation. Four rounds at one base; three returned one BLOCKING finding each and all three
were accepted in full and repaired.

**Mechanizable:** declined: LIM-HAND-LISTED-POPULATION-SET, 2nd naming, whose trigger is a 3rd
distinct arc; and under the 2026-08-25 process mint freeze a process-facing class does not enter the
open queue. Two of the three findings are one instance of that class, and it is not the class they
appeared to be. Both were "the guard ranges over a narrower set than its claim" — over config FILES
in one round, over @next/env load MODES in the next — and in both cases the wider set was already
derivable from something the tree can be asked for: the config files are a directory listing, and the
two load modes are readable off the configs' own command strings. A guard whose domain is written
down invites this finding once per axis; a guard whose domain is derived from the artifact it guards
cannot be narrowed by an author who forgot an axis, because there is nothing to forget. The repair
was the same move twice, on a different axis. This arc's instance is now derived on both axes, which
is the repair that slug records as the one that holds.

**Judgment:** r3 is the round worth keeping, and it is not mechanizable. It found that every
probe and every planned test arm loaded the hoisted root `@next/env` (16.2.4) while the server
under test runs the copy `next` 16.3.0 resolves — different files, different loader bytes. No
domain check finds that: the set was right, the binding was wrong, and the guard would have been
green about a package no webServer executes. It took a reviewer willing to ask which artifact the
measurement actually touches. Re-probing before accepting it also mattered: precedence turned out
identical on 16.3.0, so the finding moved what the guard measures without moving the repair, and
accepting it wholesale as a behavior change would have been wrong.

**Infra:** two dispatches were lost to wrapper usage errors before round 1 landed — `--stage spec`
requires a `--lint-doc`, and the artifact then had 19 hard `spec:lint` failures, 16 of them one
shape: a backticked bare-port shorthand (`` `:3004` ``) parses as a citation with an empty path.
Both were the wrapper telling me something true, and both cost a dispatch to learn. Linting the
artifact before the first dispatch, rather than discovering it through the gate, is free.

**What the round count does not show.** Four probes run BEFORE dispatching anything each removed a
defect that would otherwise have been a round: the override-vs-scrub negative control, the T1
oracle, the `loadEnvConfig` in-process contamination that falsified T2's first design outright, and
the `--no-db` warning-flush check. The in-process one is the instructive case — the design was
plausible, self-consistent, and wrong, and no amount of re-reading would have shown it. Cost about
ten minutes total against roughly twelve minutes per review round.

because the habit was never the instance. What ended it was not a fifth count but changing what the

**Judgment:** the two oracle rounds are the pair worth keeping, and they are one lesson. Round 2

## diff — 4 rounds

**Examined:** whether the shipped change actually stops a Playwright-booted app server from
resolving the validation pooler, and whether the three guards written for it hold. Ten findings
across four rounds, all accepted, nine closed and one fenced. The finding rate did not decay.

**Mechanizable:** declined: no row, and the class is one this filing can state precisely because
it recurred three times in one stage. Every oracle in this diff started as an ANCHORED REGION and
each repair moved its blind spot rather than removing it. The stderr comparison went: a
continuation-rule block (missed anything past a blank, column-zero or single-space line), then a
slice from the anchor to the end (missed anything inserted BEFORE the anchor), then whole-stream
equality (correct, but red in CI, because `.env.local` is untracked and preflight says so on
stderr first). The command check went the same way in miniature: a `\sNAME=` assignment pattern
that missed `env "NAME=..."`. What ended it in both places was not a better region but no region:
compare the whole stream and assert BOTH halves around the one legitimate variable prefix, and ask
whether the variable NAME occurs at all rather than whether an assignment grammar matches. An
anchored region always has an outside, and the outside is where the next finding lives. The
mechanizable form of this would be a lint that flags an assertion comparing a SLICE of a captured
stream, and it is not filed as a row under the process freeze; it is recorded here because the
diagnosis is worth more than the rule would be.

**Judgment:** round 3's first finding is the one worth keeping, and no static reasoning would have
produced it. The whole-stream oracle was CORRECT and would have gone red in CI on correct code,
because `.env.local` is untracked and a clean Actions checkout gets a two-line notice on stderr
that no local run ever sees. That is the local-passes-CI-fails class landing on a guard rather
than on product code, caught by a reviewer reading the script's other branches instead of the
branch under test. The repair accepts the notice explicitly and asserts both halves, and it was
verified by hiding the symlink and running both paths, with a positive control proving the
absent-file path actually exercises the notice branch rather than passing for some other reason.

Second: the ambient `DATABASE_URL` finding in round 1. The pin resolved a bare
`process.env.DATABASE_URL`, which moved the hole one variable to the left rather than closing it,
and it had been that way on the pre-existing :3004 entry since before this arc. Copying a form
that already shipped is exactly how a defect survives review; the round-1 reviewer read what the
form DOES rather than where it came from.

**Infra:** the reviewer sandbox could not run Vitest at all -- every suite failed with `EPERM`
creating its temporary `ssr` directory -- so all four rounds were argued from no-write probes
against the configs, the script and the installed packages. That is worth knowing before reading
the verdicts: nothing here was settled by executing the suite on the reviewer's side, and the
executable evidence in this arc is the implementer's, in the commits.

**The stage ended at NEEDS-ATTENTION, not APPROVE, and that is the recorded state.** Round 4
returned one copy-accuracy finding: the warning called every non-loopback host "the VALIDATION
deployment" when the check establishes only that it is not loopback, and said anything honouring
the variable "writes to validation" when the two allowlist rows say in their own reasons that one
reads only and the other always rolls back. Both claims were inherited from the copy this branch
replaced, and both became this branch's the moment the copy turned into the deliverable. Fixed,
committed and verified on both `.env.local` paths.

No round 5 was dispatched, by orchestrator ruling: a verified one-claim copy correction takes the
mechanical acceptance class, since it cannot generate a next finding, and spending a round to
convert a recorded fix into a cosmetic APPROVE is the spend the round economy exists to refuse. So
the last verdict on this stage is NEEDS-ATTENTION with its finding repaired, rather than an APPROVE
that would have cost a round to say the same thing.

**Verification this stage rests on.** The discriminating end-to-end run, deliberately with NO
`TEST_DATABASE_URL` export, since exporting one would mask the very thing under test:
