**Judgment:** three of the eight findings could only have come from reading the corpus against the
mechanism, and each was worth its round. All three are the same shape at three depths: a claim that
some input is safely handled, refuted by looking at what actually renders.

- **R1's P0 is the round that earned the arc.** The spec declined to follow a component invocation and
  filed that as a documented limit, naming the one switch-track instance it knew about. The reviewer
  enumerated the class (six weak-painted component definitions reached through seven calls) and found
  the one that is not chrome: `EventRow`'s `role="button"` wraps nothing but `<CronRunSummaryCard>`,
  whose root paints the weak token, so the "limit" was hiding a live control-outline defect. The repair
  also produced the acceptance check the ledger row itself had set, `count("switch-track")` 3 to 5
  rather than 3 to 4. Nothing mechanical separates a documented limit from a silent hole; a reader has
  to look at what the component renders into.
- **R3's P0 is the same shape one level down.** `EventFilters`' input paints through
  `className ?? "<weak default>"` and both call sites supply their own, so the weak string the
  transcript named is dead. Repairing exactly what the red named would have deleted the only readable
  weak token, cleared `isResidue`, and left both rendered controls at 1.27:1 behind a green guard.
- **R4's P0 refuted R3's own repair.** That repair merged the caller's className into a strong base and
  claimed the residual was conservative, because an unreadable prop leaves the element `unresolved`.
  False: `isResidue` is `weakSides(...).length > 0` and `weakSides` reads only readable tokens, so an
  element with no readable weak token is not residue at all. With `cn` merging nothing, a caller
  passing `!border-border` overrides the base with the guard seeing nothing. The repair stopped
  merging and removed the prop.

That last one is the pattern AGENTS.md names as a review defect chargeable to a probe-less acceptance:
R3's repair was accepted on an argument about `unresolved` that one read of `isResidue` refutes. The
cheap round here was R4's P0, and it was cheap only because R4 probed rather than argued. The lesson is
narrow and worth carrying: **a claim that a guard "stays conservative" is a claim about the guard's
code, and it is settled by reading that code, not by reasoning about the scanner's output.**
