## diff — 4 rounds

**Examined:** 4 counted diff rounds at this base (rounds 1-4; a fifth dispatch, numbered 3, died `no_verdict` on a Codex usage limit and is recorded but uncounted). 14 findings across the four: 3 NEEDS-ATTENTION, 3 NEEDS-ATTENTION, 5 BLOCKING, 3 NEEDS-ATTENTION. All 14 accepted; none refuted, none relitigated a fenced decision. The product defect itself — a typed report draft destroyed when the wizard review modal closes — was found, fixed and pinned in the FIRST commit of the arc, before round 1.

**Mechanizable:** The dominant class is not a defect class at all, it is a TEST-STRENGTH class: an assertion that reads as a pin while being satisfiable without the behaviour it names. Seven of the 14 findings are that shape.

- R2 F2: an `"x".repeat(n)` fixture that cannot distinguish prefix truncation from a suffix, from filler, or from boundary corruption, because every candidate answer is the same string.
- R2 F3, R3 F4, R4 F2: a test whose prose promises a behaviour (submission survives throwing storage) while the body stops before exercising it.
- R3 F2, R3 F3: fixtures with no discriminating property — a 500 standing in for a 410, an unpadded string standing in for the trimmed-versus-untrimmed distinction.
- R4 F1: assertions all true in the pre-action state, so deleting the action under test leaves them green.

There is a mechanical test for six of the seven, and it is cheap: **delete the action under test and confirm the assertions go red.** R4 F1 is exactly that check applied by a reviewer to a test I had written, in the same round, to close R3's instance of the same class. The one that mechanisation would miss is R2 F2, where the fixture is wrong rather than the sequence — that needs a fixture whose characters differ, which no runner can infer.

This is a candidate for the anti-tautology rule in `docs/agents/writing-plans.md` to state as a PROCEDURE rather than a principle: for every new test, delete its action and re-run before committing.

R3 F1 is a third kind again: a plan-wide invariant (invariant 8's `DEFERRED.md` requirement) that I applied to the wrong ledger, which is a rule-reading error, not a test gap.
