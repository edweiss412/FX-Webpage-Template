**Every finding landed on the guard, never on the product code.** Three rounds, three findings,
all three against `tests/log/noDoubleSerializedLogError.test.ts`. The four production guards, the
catalog triple, the 18 repairs, and the archive drew ZERO findings across all four rounds. That
is the shape this corpus exists to make visible: the shipped behavior converged at round 0 and
the rounds were spent on the recognizer that guards it.

**Mechanizable:** the R1 and R2 findings were the same defect class — a recognizer that
classifies the GRAMMAR of a value instead of asking a closed question about it. R1 named three
spellings (`as`, `satisfies`, `&&`-spread); R2 named four more (`?:`, `&&`, `||`, `??` as
initializer carriers) one round later. Both were correct, and patching R2 the way R1 was patched
would have set up R3 on the same axis. What ended it was replacing the parser with containment:

```
mentionsWrapper(initializer, wrappers)  // does the value's SUBTREE mention a serializeError binding?
```

A closed question over a finite tree in place of an open question over a grammar, SMALLER than
the code it replaced, and covering every future syntax by construction. The generalizable rule,
already in AGENTS.md and confirmed again here: **under same-axis recurrence the repair direction
is narrowing, and the tell that you have narrowed correctly is that the recognizer got smaller.**

The cost of learning it late is measurable in this corpus: R2 exists only because R1 was repaired
by widening. Had R1 been repaired by containment, R2's four carriers would have been covered
before they were probed, and this arc would have been a 2-round diff.

**Judgment:** R3 was a genuine finding on a NEW axis that correctly did NOT become a fifth round.
It observed that four repaired sites still persist `"[object Object]"` because they forward plain
objects (Supabase returned-errors) and `serializeError`'s non-`Error` branch is `String(value)`.
The observation was true; the "four repairs failed" framing was not, and a probe settled it
rather than an argument — at those sites a plain object produced `"[object Object]"` both before
AND after the repair (identical), while an `Error` went from `"[object Object]"` to a full
`{name, message, stack}`. Strictly non-regressive, strictly better for `Error` values. It exposed
an independent pre-existing helper defect instead of causing one, so it was filed with the probe
as `BL-SERIALIZE-ERROR-NON-ERROR-BRANCH-STRINGIFIES` under disposition (c) and the refutation was
written into the archive entry so no later reader re-derives it. Scope was not expanded.
