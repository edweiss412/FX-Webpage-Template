## spec — 8 rounds

**Examined:** all eight spec rounds (8 / 8 / 6 / 4 / 2 / 3 / 2 / 0 findings; BLOCKING,
BLOCKING, NEEDS-ATTENTION for R3–R7, APPROVE at R8), their briefs, and the repair commits
`fe2fcb3b8`, `5c7a33e12`, `3d7e89570`, `5deb48706`, `af35d91a0`, `f506eead1`, `43479ba6a`.

**Mechanizable:** two of the four rounds were spent on work a pre-draft pass already
mandates and this arc skipped.

- **R2's BLOCKING was the mandated detector corpus pass** (`docs/agents/spec-self-review.md:23`
  — "run the candidate rules against the full fixture corpus … and put the hit/miss table in

  36px target no reviewer round had named and no amount of prose would have found. Had the
  pass run before drafting §5, R2 would not have existed.
- **R1's two LOW findings and R4's three internal-consistency findings** are the
  self-consistency sweep (`docs/agents/spec-self-review.md:18`) applied after each repair
  round rather than only at draft time. Every one was a stale claim left by MY OWN previous
  round's edit: a "five consumers" count the repair superseded, `28px everywhere` after
  adding a 36px control, a pre-change-baseline requirement after restating the invariant as
  baseline-free, a `DI-1…DI-13` range after adding DI-14/DI-15. The rule already says the
  sweep is "NOT draft-time-only"; it was not run between rounds.

**Judgment:** the genuinely irreducible findings clustered in R1–R2 and were design gaps a
document cannot mechanize — the `before:-inset-2` recipe being refuted by measurement, the
hover/focus rewiring that a class-relocation implies, `HelpTooltip` matching two recipes with
no precedence, and the live-entry boundary for two private components. R3 and R4 raised **no
new design ground at all**: every one of their ten findings was an integration residue of a
previous repair. That is the signature of missing between-round sweeps, not of an unstable
design.

**Infra:** none. All five dispatches returned a verdict on the first attempt; no
`no_verdict`, no reap, no retry.

**R5–R7 addendum.** The pattern held and sharpened. R5/R6 were integration residue of
earlier repairs (the between-round sweep, again). R7's two findings split cleanly: the
MEDIUM (DI-2 contradicting `HelpTooltip`'s Class-B-only recipe) is one more
self-consistency miss — a quantifier ("each repaired summary") left stale after the
dual-class precedence rule landed in an earlier round. The HIGH is a different lesson: the
spec PRESCRIBED a live-entry bundle path for `MeShowSections` that was never probed — the
reviewer bundled it and it dies at module scope (`AsyncLocalStorage` under an empty
builtin stub). The empirical-spike rule was applied to the RECIPES (probes P1–P6) but not
to the HARNESS prescription, which is equally a factual claim about what runs. Repair
probed the replacement seam (extraction; probe P7) before prescribing it.

**Carry-forward for the plan stage:** run the self-consistency sweep as part of each repair
commit, not as a draft-time step — grep the document for every count, range, and superseded
claim the round's edit could have staled, before dispatching the next round. On this arc that
alone would plausibly have collapsed four rounds into two. And extend probe-before-argue to
every prescribed test-harness path: a bundle/mount prescription is a behavior claim and gets
probed like one before it goes in the document.

## diff — 4 rounds

**Examined:** nine dispatch rows, seven with a verdict. Split tight-scope from the start per
the large-diff default: brief A over the thirteen production UI files, brief B over the
harness, tests and ledger edits. Brief A ran NEEDS-ATTENTION (1) → NEEDS-ATTENTION (1) →
**APPROVE (0)** and is closed. Brief B ran 2 → 3 (BLOCKING) → 2 → 2. Two round-1 rows are
`no_verdict`: both dispatches hit the Codex account's usage ceiling
(`try again at Aug 11th`) and returned `nonzero_exit` on all three attempts. That is an
infrastructure fault, not a review outcome, and neither row counts.

**Mechanizable:** the dominant shape is one class of finding, and it IS mechanizable. Eleven
of the twelve findings were "the guard does not pin what it claims", and every one arrived
with an exact production edit the committed suite failed to catch — a rotation with no glyph,
a glyph with no ink, a name that is non-empty but contradicts the wordmark, a radius that is
equal-and-non-zero but no longer a circle, a margin that no longer cancels, a centring class
that can be dropped without moving a single measured number. That is precisely the
source-mutation registry's job (`tests/mutation/source/registry.ts`,
spec `docs/superpowers/specs/ci/2026-08-04-source-mutation-guard-gate.md`): enrolling this
spec would turn "can you think of another way to defeat it?" — which does not terminate — into
"is the unaccepted-survivor set empty?", which does. Every one of the eleven was reproduced
locally as an isolating mutant and reverted, so the operator set is already written down in
the commit messages; it just is not machine-run. **Filed as
`BL-TAP-TARGET-SPEC-MUTATION-ENROLMENT`.**

**Judgment:** two, and both were worth the round. Brief A's round-3 P1 — the brand link had NO
accessible name below 360px, because its only always-rendered child is a decorative icon and
both text spans are `display: none` — was a pre-existing defect that no mechanical check on
this diff would have surfaced, found because a reviewer looked at the element the branch was
repairing and asked what a screen reader would say. Brief B's round-2 BLOCKING — the
invariant-8 gate record predated three later UI commits, so its "whole diff" claim described
an earlier tree — is a process fact a mutation score cannot express.

**Infra:** three. The two usage-limit rows above, plus a self-inflicted one worth recording:
`git checkout --` on the spec file to drop two debug probes also discarded four uncommitted
repairs. Committing before probing, or reverting by hand, would have cost nothing.

**Carry-forward:** when the subject is a guard suite, enrol it in the source-mutation registry
BEFORE the first review dispatch, and state the mutation score plus an empty
unaccepted-survivor set as the convergence criterion in the brief. Four of these rounds were
spent hand-discovering mutants that `pnpm mutation:guards` would have enumerated in one run,
and the brief's prose bar ("an exact production edit the suite fails to catch") kept every
finding admissible without ever making the set closable.
