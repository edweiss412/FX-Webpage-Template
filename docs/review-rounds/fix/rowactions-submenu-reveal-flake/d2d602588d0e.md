**Judgment:** vector 1 is not mechanizable and did not repeat by accident. `red=` and the GREEN prose are two different surfaces — one a machine-read marker the red-contract lint executes, one free text a human writes at the end of a task — and nothing structurally forces them to be the same string. Each round's repair edited the half the reviewer pointed at and left the other half to drift. The authoring-side lesson: write the task's command ONCE, then let both halves REFERENCE that one string — Task 1 has said "GREEN on the same command" since round 1 and drew no finding in five rounds, while every task that restated the command drifted. And the class-sweep rule has a scope the R4 repair got wrong: when a finding lands on a task, the sweep ranges over every task, not over every instance within the task the reviewer named. R5 F1 cost a full round to establish exactly that. The related discipline, from R4 F1's second clause: a task's RED half must author every test that discriminates any production change the task makes — if a pin lands in the GREEN half, the implementation it pins can be written before it, and the red was never observed.
