# Review-round economy — `feat/backlog-quick-wins` (arc C, base `59cdc8407814`)

## diff — 11 rounds

Threshold is 4, and the arc's plan set the cap at 4. It went to 11, deliberately: R4
returned a P0, and the merge gate requires an APPROVE over the final diff. Between "stop
at the cap" and "do not merge unreviewed", the second wins. The overrun is one round and
it is recorded here rather than absorbed silently.

R11 is the one round that is not part of that train. The review record closed at R10, and
R11 re-verified the final diff after close; it returned APPROVE with 0 findings and changed
nothing. It is counted because the corpus counts dispatches, not decisions — a re-verify
that found nothing still cost a dispatch, and hiding it would understate what the arc spent.

**Examined:** all eleven dispatches (`docs/review-rounds/feat/backlog-quick-wins/59cdc8407814.jsonl`),
their briefs, and every finding's disposition in
`docs/superpowers/plans/2026-08-06-arc-c-quick-wins/closeout.md` §15.

Verdicts: R1 NEEDS-ATTENTION (1), R2 APPROVE (0), R3 NEEDS-ATTENTION (1 P0),
R4 P0, R5 two P0s, R6 P0, R7 P0, R8 P0, R9 BLOCKING P0, R10 APPROVE (0),

**Ten findings, ten accepted, zero refuted** — across eleven rounds, since R11 raised none.
That is the number worth looking at. This
corpus's documented failure mode is rounds spent relitigating refuted claims; none of
that happened here. Every round found something real and the arc changed because of it:

1. R1 — the new e2e case leaked its seeded show every run and every CI retry.
2. R3 — the first repair for a failing structural pin RAISED the pin's frozen count to
   accommodate exactly the write the pin exists to reject.
3. R4 — the invariant-2 proof was one regex per file, so a second helper inherited a
   proof it never earned.
4. R5 — that repair checked the lock's PRESENCE but not its ORDER, so a lock moved below
   the UPDATE stayed green.
5. R5 — and its discovery filter was case-sensitive, so an uppercase third helper was
   never walked while the `>= 2` floor was satisfied by the two that were.

Rounds 3 through 9 are one guard growing under review, which is this corpus's documented
ratchet — and the diagnosis is sharper than "too many rounds", because those seven split
into three kinds with three different lessons:

- **Structural (R4, R5a, R5b, R6)** — the guard could not SEE the property. Four repairs,
  each recognizing one more paraphrase of a per-helper transaction block. That is the
  ratchet proper, and no amount of care in writing the next regex would have ended it.
  It ended when the second copy of the shape was DELETED: one shared
  `runLockedCrewUpdate`, so there is nothing left to paraphrase.
- **Vocabulary (R8, R9)** — the guard SAW the property but knew one spelling of it.
  Terminating, because the spellings are a documented finite grammar. **R9 was avoidable
  and is charged to the author:** R8's repair added the synonym the reviewer had just
  named rather than reading the PostgreSQL documentation, so R9 reported the next one.
  One synonym per round is the drip this project already charges to reviewers; it costs
  exactly the same when the author does it.
- **Verification (R7)** — no mutant at all. The reviewer read the TREE and found it did
  not match the commit message: a `git checkout HEAD -- <file>` during an unrelated
  investigation had silently discarded the uncommitted collapse. Cheapest finding of the
  train and the most valuable.

The final guard kills seventeen declared mutants and closes one documented grammar. That
is a closable criterion; "no escaping input exists" would not have been.

**Mechanizable:** two of the four are the same defect at different altitudes, and both are
mechanizable.

- **A guard whose premise is satisfied by an unrelated part of its own subject.** R4's
  finding, R5's second finding, and the arc's two false greens in Q2 (a drive that reached the reopen 3931ms
  into a 1600ms window; a single mutation that only bought the modal's baseline and armed
  nothing). Three instances in one arc of "the assertion could not have discriminated
  where it ran". The existing shape for this is `tests/_shared/premise.ts` /
  `premiseHolds`, and the general rule already lives in `docs/agents/writing-plans.md`
  under the anti-tautology rule. What this arc adds is that a **per-file** assertion over
  a multi-export module is a recurring instance of it: the walk must be per unit, and it
  must assert it found units. Worth a lint or meta-test that flags a `readFileSync` +
  single `toMatch` over a file exporting more than one function.
- **A repair that adds the reported instance instead of its class.** R8→R9 is the whole
  pattern in two rounds: a synonym is reported, the author adds that synonym, the next
  synonym is reported. The project already tells REVIEWERS to enumerate a class per round;
  the symmetric rule for authors — when a finding names one member of a documented finite
  set, close the set — is not written down anywhere and cost a round here.

- **A structural pin's frozen-count registry has no field for WHY a count moved.** R3's
  finding was possible because raising a number is as easy as fixing the code, and the
  diff of a raise looks like the diff of a legitimate exemption. A registry entry that
  required a reason keyed to an existing exemption class — rather than a free comment —
  would have made the wrong repair harder to write than the right one.

**Judgment:** R1's leak and R3's disposition are ordinary review value, not mechanizable.
R3 in particular turned on reading the helper's own header, which stated the contract the
raise violated; no tool infers "the author of this helper already decided this".

**Infra:** none. All eleven dispatches returned a verdict on the first attempt; no
`no_verdict`, no reaped runs, no rollout scrapes.

### Note on the briefs

Every brief carried a consequence bound with the literal "never silently wrong", a
threat-model fence, and an explicit rejection of the closure-set framing. R5's brief went
further and named the mutant as the admissibility standard for a
guard-does-not-pin claim — which is what the discipline asks for, and it is why R4's
repair shipped with three executed mutants rather than an argument.
