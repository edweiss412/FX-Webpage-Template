## spec — 3 rounds

**Examined:** every finding across the four rounds against what would have caught it earlier.
Findings by round, using the arc's running numbering: 4 (r1, dispatched twice — 3 and 4 findings), 3 (r2), 1 (r3), 0 (r4, APPROVE).
All accepted and repaired; none argued away.

**Judgment:** every one of the eight findings was ONE class, and naming the class early would
have been worth more than any individual repair. **Each was an evasion of a claim that tried to
prove an EXECUTION property** — something true only of a program as it RUNS — inside an artifact
whose only evidence is source text:

- sink dominance (r1 F1, r2 F1) — does the pass run before the send;
- invocation counting (r1 F2, r2 F2) — how many times a read is reached;
- sink discovery through arbitrary bindings (r2 F3) — which callee is really the sink;
- the derivation exemption (r3 F1) — "the initializer is evaluated once per pass".

The first three each got a repair that WIDENED the analysis, and the next round defeated the
wider version with a wider evasion. That is the ratchet this repo's repair-direction rule names:
a recognizer growing one corner per round, each widening a bigger target for the next.

**What actually converged it was narrowing, and the measurement is unambiguous.** After round 2 the
design stopped defending the claims and WITHDREW them: dominance deleted, call-graph traversal
deleted, analysis reduced to occurrences of a binding classified in the source text. Round 3 then
produced one finding instead of three, and round 4 produced none. Rounds 1-2 (widening) yielded
seven findings; rounds 3-4 (after narrowing) yielded one.

**The r3 repair is the case worth copying.** It was also on the same axis, and the round cap said
stop. It was applied anyway because it was SUBTRACTIVE — it deleted an exemption and reused a
predicate that already shipped, adding no mechanism and leaving §2.3 shorter. The generalizable
rule: **the cap exists to stop the ratchet, so what it should measure is the DIRECTION of the
repair, not the round number.** A cap that kills a shortening repair enforces its own words against
its purpose. The guard against abusing that: the exception was spent once, declared spent, and the
next same-axis finding was pre-committed to ship-and-fence regardless of direction.

**Mechanizable:** none — and this is a deliberate finding, not an empty field.

The tempting mechanization is a lint that rejects execution-property language ("evaluated once",
"runs before", "is reached N times") in a spec whose subject is a static analyzer. It is declined:
those phrases are correct and necessary when a spec DESCRIBES runtime behavior, and this arc's own
§4 limit 3 uses them legitimately to say what is NOT verified. A recognizer over that vocabulary
would fire on the sentences that correctly disclaim the property — the same use-versus-mention
error the convergence gate had to be repaired for. The durable artifact is the design rule already
written into the spec instead: an exemption must rest on something readable in the source text, and
§2.3 now states its exemption positionally for exactly that reason.

  `tests/mutation/source/expectedLedgerKinds.ts:24` and consumed by
