**Examined:** 27 findings across three tight-scope tracks (sync / route+loader / UI). R1 (10: sync BLOCKING 5, route NEEDS-ATTENTION 2, UI NEEDS-ATTENTION 3), R2 (6: sync BLOCKING 2, route BLOCKING 2, UI NEEDS-ATTENTION 2), R3 (6: sync APPROVE 0, route BLOCKING 3, UI BLOCKING 3), R4 (3: route APPROVE 0, UI NEEDS-ATTENTION 3), R5 (0: UI APPROVE). Splitting by surface was the right call for a diff this size — the sync track converged at R3 and stopped consuming rounds while the route track was still finding real authorization defects.

Dominant classes:

1. **Guard applied to one branch of a two-branch decision.** The route's key-shape gate landed on variants (R2) and left ORIGINALS matching by bare equality (R3 P0) — the same defect one step over, in a function I had just rewritten. Same shape as the sync track's hop census, which covered `runPhase2`'s first snapshot call site and missed its second (R2 P0), so first-seen auto-publish and first-seen retry could commit a snapshot while its failure row vanished. Both are the class-sweep rule failing at sub-function grain: I swept for "other files with this bug" and not for "other branches of the thing I just changed."

2. **A repair that moves the problem instead of closing it.** Round 1 encoded the variant key in the emitted URL; round 2 showed the route decodes before matching, so the encoding never reached the boundary that mattered, and the matched path was normalized by Supabase Storage (`v?x.webp` signs `.../v`). The close was to reject at the ACCEPT-SET — the authority — rather than sanitize at the URL layer. The same lesson repeated inside the impeccable gate: the outset focus ring was clipped by `overflow-hidden`, the `ring-inset` repair was then occluded by the absolutely-positioned fill image, and only moving the ring to the cell itself closed it.

3. **Tests that assert a proxy rather than the property.** Six rows across R1-R4 shipped green while the thing they named was unproved: `focus-visible:ring-inset` present but invisible, `sizes` compared for inequality rather than for which tier it selects, and a transition audit whose "swap" never swapped because Embla only emits `select` after real layout. Round 4 found three more of exactly this shape after three rounds of repairing it: a reverse tier swap asserted a COUNT that both candidate states satisfy, a browser back-navigation predicate accepted any active slide that decoded (so a no-op passed), and intrinsic dims were pinned on the active branch only. Each was caught by a reviewer probing the runtime rather than reading the assertion — and the recurrence across four rounds is the finding: "the test passes" and "the property holds" came apart repeatedly in this diff, and only an outside prober closed the gap.

**Mechanizable:** two candidates, both real. (a) **Stale line-keyed registries.** `alertProducerScope.registry.ts` pins producer sites by `file:line`, and hoisting one emit invalidated 19 rows across three files — a CI-only failure with a purely mechanical fix. Keying on an enclosing-function name plus code fingerprint instead of a line number would remove the class; filed as an observation. (b) **Result-shape test doubles.** Adding one required field to `SnapshotAssetsResult` broke four hand-written doubles across four suites, discovered one CI run at a time. A shared `makeSnapshotAssetsResult()` factory in `tests/_shared/` would have made all four free. Both are worth more than they cost; neither is implemented here.

**Judgment:** the highest-value catches were the two P0s that no local gate could have produced — the Storage-normalization probe (a reviewer ran `createSignedUrl` against the installed client and read the resulting URL, which our mocked route suite records as a string and never parses) and the first-seen hop (a call-chain trace four files deep). Both are exactly what the cross-model round exists for, and both were invisible to a green suite. The round count was NOT driven by relitigation: every round found new, probe-backed defects, and the three round-1 findings that were pre-existing (recovery cleanup deleting live bytes, upload-throw orphans, promotion counting rather than identifying) were filed rather than argued, and not re-raised.

Neither is a review-economy cost, but both cost wall-clock and both are documented here because the next arc on this machine will hit them.
