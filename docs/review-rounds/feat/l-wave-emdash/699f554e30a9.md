# Review-round economy — `feat/l-wave-emdash` (L-wave unit W-EMDASH)

Base: `699f554e30a9`. Corpus: `699f554e30a9.jsonl`.

## diff — 4 rounds

**Examined:** four whole-diff dispatches plus the impeccable dual gate that preceded them. Findings:
2 (gate) + 2 + 2 + 4 + 7 = 17, every one verified against the code before repair, every one real.
Verdicts: FAIL / FAIL (gate), then BLOCKING ×4.

**Judgment: the round count is honest, and the shape of it is the finding.** Fifteen of the seventeen
were the SAME defect — *the guard does not pin what it claims* — and the sentinel rule alone was
rewritten five times:

| v | the rule | defeated by |
| --- | --- | --- |
| v1 | `text.trim() === EM_DASH` | `{" — "}` between siblings |
| v2 | + "parent must not build a string" | `const SEP = "—"`; `[…].join(" ")`; a nested `<span>—</span>` |
| v3 | "a `??`/`\|\|` fallback, or `aria-hidden`" | `{sep ?? "—"}` between prose; `aria-hidden` hides from the a11y tree, not from sighted readers |
| v4 | a per-file COUNT | relocation inside the file: move the glyph to a visible label, demote a real sentinel to `-`, count unchanged |
| v5 | the exact enclosing EXPRESSION text | the same expression relocated verbatim; and a ratchet that searched raw source, spoofable with a comment |
| v6 | AST-consumption counts, exactly once per registered anchor | — |

**Every one of v1-v5 described a SHAPE, a QUANTITY, or a STRING. Only v6 describes what the compiler
actually did.** That is the transferable lesson, and it generalizes past em dashes: when a guard tries
to answer a semantic question ("does this render as prose?") from syntax, each fix narrows the shape
and the next author's ordinary idiom walks around it. The question was only closable by asking the AST
what it consumed and pinning that to an enumerated site list with exact counts.

The same pattern repeated in the markdown and CSS scanners at lower cost:

- **CSS** went from a line-local `content:` regex (six demonstrated escapes: a value on the next line,
  `var()` indirection, a comment-looking string, `list-style-type`, `quotes` + `open-quote`,
  `@counter-style symbols`) to *all non-comment text*, with a string-aware lexer — because
  enumerating rendering properties is the same losing game. **The strict rule is also the simpler
  one**, which is usually the tell that it is right.
- **Markdown** went from shape-matching fences and delimiters to GFM's actual rules (fence character,
  length, info-string validity, three SPACES not `\s`, per-cell delimiter grammar, odd/even backslash
  parity), under a rule that ambiguity SCANS rather than passes. Conservative in the direction the
  consequence bound demands: a false positive is surfaced, a false negative is silent.

**Mechanizable:** partly, and the cheap part is large.

- **The extension gap was pure mechanism.** `\.tsx?$` silently excluded `.mts`, `.js`, `.jsx`, `.mjs`,
  `.cjs` in a repo with `allowJs: true`. One regex, found in round 4, findable in round 0 by asking
  "which extensions does this project compile?" rather than "which do I expect?".
- **The CSS gap likewise**: the scanner selected `.ts`/`.tsx` and markdown and simply never opened a
  `.css` file, while `content:` renders text. A coverage question ("which file types can carry
  rendered copy?") answered by enumeration at design time would have caught it before round 1.
- **What was NOT mechanizable** is the sentinel semantics. No checklist produces "aria-hidden removes
  content from the accessibility tree, not from sighted rendering" — that is a fact about the platform
  that an adversarial reader supplied.

**Infra:** the reviewer's sandbox denied Vitest its temporary `ssr` directory in all four rounds
(`EPERM ... mkdir .../ssr`), so it extracted and executed the scanner functions in memory and used the
project's own `@mdx-js/mdx` + `remark-gfm` to establish rendered behaviour. Worth recording twice
over: the probes were executable rather than static reads, and the limitation was declared every
round rather than quietly worked around. Every suite run in this arc was mine, on the writable tree.

**One finding was left unactioned and is not a defect:** `lib/parser/warnings.ts` reads "as a email
address". It is pre-existing, is explicitly acknowledged in that suite's own comment as out of scope
("grammar fix is a separate copy change, deliberately not smuggled into this diff"), and the reviewer
agreed it is not merge-blocking.

**Would fewer rounds have been better?** Rounds 1-4 each found a bypass a contributor could have
walked through, and three of them were in code the previous round had just "fixed", so stopping early
would have shipped a guard that looked green and was not. The honest saving was available before
round 1, not during: **the dual gate found the first bypass by MUTATING the guard, and every later
round found its bypass the same way.** Running that mutation pass at design time — plant the glyph in
each idiom the codebase actually uses, in each file type it actually compiles — was always the cheap
substitute for five rewrites, and it is the practice the W-PUSH filing arrived at independently.
