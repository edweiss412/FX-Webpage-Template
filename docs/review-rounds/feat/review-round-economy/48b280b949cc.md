Three mechanizable rules come out of it, all cheap and all applied here:

1. **A recognizer bounded by a NUMBER will be found by the next reviewer.** The emphasis matcher's cap went one delimiter, two, three; round 2 removed the cap and round 4 still found a shape, because the next cap was positional. Round 5 found one more, because the positional fix was anchored by a backreference — an *identity* constraint where CommonMark's is a *mirror*. Each repair that named a shape got found; the one that finally held derives the closer from the opener, so nesting depth and composition are handled rather than listed.
2. **A key that can ALIAS is not a clock.** Count recency cost three rounds keyed on the wrong thing (the attempt, then the session) before landing on a monotonic per-attempt ordinal.
3. **A per-site sweep of a value-domain defect does not converge; a derived one does.** The unsafe-integer defect recurred in rounds 3, 4 and 5 — five call sites, three review rounds, each repair fixing the site it was shown. It stopped when the test stopped naming sites: the row-schema test now derives its field list from the fixture, so a numeric field added later is covered by default. That is the same fail-by-default posture the corpus walk already uses, and it is what the class-sweep rule in `AGENTS.md` should mean in practice — sweep to a *derivation*, not to a longer list.

That third rule is the sharpest thing this arc measured, because it is the class-sweep rule in `AGENTS.md` failing three times running on the arc that cites it. Finding the class is not the hard part; the hard part is that a sweep verified by enumeration re-opens the moment someone adds a site.

**Judgment:** Whether to keep repairing at all past round 2. Each round's findings were genuinely in the losing direction — a lost verdict files a completed review as an infrastructure fault, and a restated count puts a number in the corpus the reviewer never wrote — so the consequence bound admitted every one, and none was a "the guard does not pin what it claims" ratchet. Continuing was right, but only because the bound held; the moment findings turned into "here is one more shape that leaks", `BL-CODEX-GUARD-COMMONMARK-PARSE` was already filed to take them.

The honest counter-reading, recorded because it is the one a later reader should weigh: five rounds on two recognizers is a lot, and each round's repair was *sound* yet incomplete in the same direction — toward the shape it was shown. A reviewer that can keep producing one more shape is a signal the REPAIR is the wrong kind, not that the reviewer should stop. Rounds 2 and 4 should have reached for the derived form immediately rather than a wider pattern.

Also judgment: a mutation probe, not the reviewer, found the round-3 repair's own gap (writer 4 never placed its attempt on the clock), and another found round 4's row-schema check to be unpinned defensive code. Probing each repair with the mutant that should kill it caught two defects five review rounds had not, at a fraction of a round's cost. Worth doing before the dispatch, not after.
