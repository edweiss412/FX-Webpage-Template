# Review-round economy — `feat/l-wave-push` (L-wave unit W-PUSH)

Base: `a0e41551c059`. Corpus: `a0e41551c059.jsonl`.

## diff — 4 rounds

**Examined:** four whole-diff dispatches, one finding each, verdicts
NEEDS-ATTENTION ×3 then BLOCKING. Every finding was verified against the code before repair and every
one was real. The subject was small — a footer link in five notify templates, ~7 files.

**Judgment:** four rounds on a footer link looks like over-review. It was not, and the reason is worth
recording: **the feature was correct in round 1 and never regressed. Every finding was in the TEST.**

| Round | The escape | Mutant that proved it |
| --- | --- | --- |
| R1 | label and URL asserted independently, so four shapes passed on their pre-existing `Open the dashboard: ${origin}/admin` line | footer reduced to a bare label: 3 failed, **4 passed** |
| R2 | `toContain` has no RIGHT boundary, so an appended suffix still matched | href + `/does-not-exist`: **7 passed** before, 7 failed after |
| R3 | assertions read SERIALIZED HTML, so a commented-out anchor still matched | footer wrapped in `<!-- -->`: **7 passed** before, 8 failed after |
| R4 | the shape CENSUS was wrong — `renderRealtimeProblemBatch` takes a `group` and mixed member kinds, so "the batch shape" is two more shapes | footer only for `sync_problems`: **7 passed** before, shape 8 fails after |

All four are one defect class: **an assertion that constrains less than it appears to.** R1-R3 are
boundary failures (left, right, representation); R4 is a coverage failure — the accept-set was
enumerated as "seven shapes" and production has nine, because
`lib/notify/deliver.ts:306-309` routes ingestion candidates to a `stuck_files` batch and everything
else to `sync_problems`, and the tested fixture was an all-show `sync_problems` batch.

That is the finding with transfer value: **this branch's own spec insisted the accept-set was "render
SHAPES × body CHANNELS, not source files" — and got the shape count wrong anyway.** Correcting from
"files" to "shapes" caught three of the shapes; it did not catch that a single exported function with
a discriminating parameter is itself several shapes. A census is only as good as the axis you
enumerate it on, and there was more than one axis.

**Mechanizable:** yes, and this is the concrete lever.

Every finding here was found by MUTATING the implementation and observing the suite stay green. Three
of the four were found by the reviewer doing that; the fourth (R4) too. **None was found by reading
the test.** The tests looked correct — the file's own header cites the anti-tautology rule.

So the cheap mechanization is not a better reviewer prompt, it is running the mutants yourself before
dispatching: for a guard whose whole job is "this string appears in this output", try (a) the empty
value, (b) a value with the expected content plus a suffix, (c) the content present but not live
(commented, escaped, in an attribute), and (d) each discriminating parameter of the function under
test. Four mutants, minutes to run, and they would have collapsed four rounds into one. This branch
now runs (a)-(d) and records each result in its commit.

**Infra:** none this unit. All four dispatches completed and returned parseable verdicts. The
budget-discipline block carried over from W-LDOCS (naming the large spec/plan documents NOT to read,
inlining the ratified context) and no dispatch died. The reviewer could not run Vitest under its
read-only sandbox (`EPERM` on the transform cache) and bundled the real renderers in memory instead,
which is worth knowing: its probes were executable, not static reads, despite the harness limitation.

**Would fewer rounds have been better?** Only by front-loading the mutants. Each round found a real
hole a contributor could have walked through, and stopping at R3 would have shipped a regression
contract that two live recipient shapes (`stuck_files` batches, mixed show+global batches) were not
covered by. The convergence signal here was never "findings decayed" — it was one per round, four
times — it was that R4's finding changed CLASS, from boundary to census, which is what said the
boundary work was actually done.
