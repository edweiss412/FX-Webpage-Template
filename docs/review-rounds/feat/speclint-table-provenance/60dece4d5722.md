# Review rounds — `feat/speclint-table-provenance`, base `60dece4d5722`

## spec — 5 rounds

**Examined:** all 5 counted spec rounds (R1 4, R2 5, R3 4, R4 6, R5 1), plus one uncounted
`no_verdict` (`total_timeout`, both attempts SIGTERMed, re-dispatched at the same stage and round
per the wrapper contract). Every finding was accepted; none was disputed or argued down. The arc
declines to build the lint its row asked for, so the rounds were spent almost entirely on whether
the evidence for declining is true, not on what to build.

**The arc became the twelfth naming of the class it was declining to mechanize.** That is the
finding worth carrying forward, and it cuts against the reflex to read it as vindication for the
row. Across four rounds the reviewer charged, repeatedly, exactly two shapes:

1. **A figure stated with nothing producing it.** R1 F1 (the census printing a retyped "6 rounds
   across four namings" while the spec's methodology claimed every figure came from that command),
   R2 F2 (the §8 population measured by a scratch script that had been deleted), R2 F5 (a quoted
   precedent with no `file:line`), R3 F2 (eight of eleven repair rows carrying a quotation and no
   location).
2. **A universal claimed wider than its evidence.** R1 F3 ("every paying arc removed the
   hand-written table" — one kept it and committed the command's output beside it), R2 F1 ("six of
   eleven shipped a repair" — all eleven did, and "shipped EVIDENCE" does not cover deletion).

**Round 4 charged both shapes again, and one of them for the third time on the same argument.** F1 was
an off-by-one inside the census itself: fence spans were 0-based array indexes compared against 1-based
mdast table lines, so every adjacency figure was quietly wrong (10/23/55/99, not 12/22/53/98; the pure
population 11/3/8 was unaffected). Silent corruption inside the declared probe domain, in the probe
whose subject is unverifiable numbers. F2 retired the second argument's third draft as tautological.

**The F1 bug is the strongest argument this document makes, and it is worth stating as such.** The
census exists to measure a class of numbers nobody can check. It carried four wrong numbers for four
rounds, inside the declared probe domain, and no reader caught them — a reviewer caught them by reading
the code and re-running it with the index base corrected.

Follow what that does to each repair shape in turn, because it does not land where the row would want.
Those adjacency figures were PRODUCED, not retyped. They satisfied the convention the corpus converged
on and that this spec endorses, and they were wrong anyway, because the producing code had an off-by-one
in it. So "produce the number instead of writing it down" is necessary and not sufficient: it moves the
defect from the transcription into the producer, where it is harder to see, not easier. A marker
binding that table to that command would have pointed, accurately and uselessly, at the command that
generated the wrong numbers.

That is the same shape as the structural argument one level down. A pointer records where a figure came
from; it cannot record that the figure is right. Neither can a producer, if the producer is wrong. What
caught this was a person reading the code against the data it claimed to describe, which is the one
thing none of the mechanisms under discussion do.

**It does NOT vindicate the marker, and the reason is the whole spec in miniature.** Not one of
those defects would have been caught by a `<!-- table: cmd=`…`` -->` marker. Most were prose
figures and stale counts, which no table-bound marker sees; the one genuine table-versus-command
instance, the census's own hardcoded sentence, was caught by a reviewer reading the document, not
by any check. What DID fix them is the shape the canonical spec's §5 records — and that section says
the eleven arcs did NOT converge on one repair, which this paragraph originally claimed and whole-diff
review round 4 finding 3 caught. They split three ways: seven made the table an output, two deleted it,
two kept it and committed the command's raw output beside it. The partition is stated once, in §5, and
is not restated here. The naming population is now emitted by
the census and classified in the spec; the §8 candidate population likewise. Both had been hand
enumerations, and both were wrong while they were.

**Mechanizable:** the class these rounds hit is `LIM-NUMERIC-TABLE-PROVENANCE` itself, whose
mechanization this arc measured and declined.

declined: recording it as newly mechanizable here would be the arc contradicting its own §5 in its own
paperwork. The measurement is in `docs/superpowers/specs/ci/2026-08-28-table-provenance.md` §5 and §6,
and the slug's `docs/review-rounds/LIMITS.md` entry carries the disposition with a narrowed re-file
trigger.

Stated precisely, because an earlier version of this paragraph got it wrong in two ways that plan
review round 1 finding 5 caught. The ratified repair is NOT "a producing command": the convention at
`docs/superpowers/specs/ci/probes/README.md` under `## Stating a figure` is explicit that "naming the
producing command is not by itself a binding" and requires **the command AND an immutable revision**.
And this arc added no claim that the practice is common — round 5 withdrew exactly that, leaving one
demonstrated instance and an explicit disclaimer of prevalence. What this arc actually contributes is
narrower: one arc that followed the practice and drifted anyway, which is a reason not to mechanize the
practice rather than a new thing to build.

**Round 5 was scoped over the cap and pre-declared terminal, and it ended the argument by subtraction.**
The orchestrator authorized one round bounded to the round-4 delta, on the condition that anything
beyond a repair-regression would NOT be repaired but would come back with subtraction as the default
disposition — the reasoning being that a refutation record terminates by making fewer claims rather
than better ones. Its single finding was the second argument again, overstating in the opposite
direction from before: having withdrawn "no arc reached for a pointer" as tautological, the replacement
claimed the practice is "already widespread", which the records do not support either. Only one cited
repair explicitly places a producer beside its table, and the census measures adjacency and purity, not
prevalence. The argument was cut to that one instance, and the reviewer confirmed the conclusion
survives subtracting even that.

**Five rounds took one argument from a claimed convergence, to a claimed absence, to a claimed
prevalence, to a single demonstrated instance.** Each step was smaller and each was correct to make.
The lesson is not that review was wasteful — every one of those findings was right — but that the
argument was written at a size the evidence never supported, and the cheapest true version was
available at round one. The finding rate across the capped four did not decay (4/5/4/6); it fell to 1
only when the round was BOUNDED. That is a fact about scoping the review, not about the artifact
converging.

**Judgment:** the disposition, and it moved twice under measurement without changing. Three of the
four drafted arguments weakened or inverted during review — the cost leg inverted outright once the
naming count was derived rather than counted from slug citations (4 arcs to 11, 6 rounds to ~20),
the population leg became an upper bound, and the adoption leg turned out to rest on a marker three
days old. The spec now opens with a ledger saying so. What none of that touched is the structural
argument: a producing command is not a binding, so a marked table can satisfy the check and be
exactly as drifted. An expensive problem is not a reason to ship a mechanism that cannot solve it,
and that call is the judgment the rounds did not mechanize.

**Infra:** one, and it changed the process rather than the artifact. Round 1's first dispatch
returned `no_verdict` / `total_timeout` after spending its entire budget re-running the census, at
roughly 90 seconds a run, once per figure it wanted to check. Treated as an infrastructure fault
and re-dispatched at the same stage and round to a fresh out-dir. The repair was to paste the
census's full output into the brief and tell the reviewer to run it at most once; every subsequent
round returned a verdict on a single attempt in about 370 seconds. A reviewer asked to verify by
re-measurement will spend its budget measuring.

## plan — 4 rounds

**Examined:** all 4 counted plan rounds (R1 5, R2 6, R3 8, R4 4). Every finding was accepted; none was
disputed. The plan implements no code, so the rounds were spent entirely on one question: does anything
actually decide the criteria this plan declares?

**One class produced every round, in four escalating forms, and each repair minted the next round's
finding.**

1. **R1 — criteria with no command at all.** Four of five findings. AC-4 and AC-5 had no verification
   entry; AC-3's mapped suite reads one level below `specs/` and never opens the probes README; AC-6's
   red/green accepted three different states including the correct one.
2. **R2 — commands that could not fail.** The census is a PRODUCER, exiting 0 for any population, so a
   stale figure could not red it. `grep -c <filename>` passed when an index ROW was deleted but the
   name survived in prose. A hand-rolled archive check had its exit codes backwards, reporting failure
   at green because `grep -c` returns 1 on a correct zero count.
3. **R3 — a checker narrower than its own claims.** The assertion script written to answer R2 was, in
   five separate ways, narrower than the criteria it claimed to settle, and every repair implied
   widening it. Rate rose 5, 6, 8 on a surface the arc had invented one round earlier.
4. **R4 — guards that decide LESS than claimed.** Same-commit atomicity is not machine-decided (both
   guards inspect final state, so two commits producing the same tree pass identically);
   `Mechanizable: none` is legal without a `declined:` reason; the mint bar scans open ledgers only and
   leaves the row's jurisdiction the moment it is archived, making that criterion vacuous; and the plan
   claimed fenced blocks the analyzer says it does not have.

**The terminating move was subtraction, twice, and the second one is the record's point.** R3's repair
deleted the arc-authored checker rather than widening it a fourth time, keeping only criteria a SHIPPED
guard decides. R4's repair then narrowed the surviving criteria to what those guards actually deliver
and DELETED one that nothing decides post-archive. Five criteria remain, each naming a guard, plus a
titled section recording what is deliberately not decided.

**Why that is the right answer here and not an evasion.** A checker written to bind ONE document's
numbers to a command turned out narrower than its own claims in five ways. That is the spec's argument
about the ledger row's marker, demonstrated by this arc against itself: a mechanism that records where
a figure came from does not thereby hold the figure true, and neither does a mechanism that checks the
recording. Documenting the limit is what the corpus already ratified for the general case; doing the
same for the arc's own paperwork is consistency, not exemption.

**Mechanizable:** none.

declined: every candidate this stage surfaced was a check on one document's own consistency, which is
the class the canonical spec measures and declines at corpus scale. Building it here for a single
plan would contradict that ruling in the same PR, and R3 measured the cost of trying.

**Judgment:** what a criterion is FOR. Three drafts treated acceptance criteria as a description of a
finished state, which is why each read as satisfied while deciding nothing. The version that survived
treats them as a question a named, already-shipped mechanism answers, and everything else as prose the
reader checks. That distinction is not in the writing-plans guidance in this form, and it is what four
rounds bought.

**Infra:** the reviewer could not execute Vitest in its read-only sandbox (`EPERM` creating temp
directories) and said so, using read-only source and in-memory probes instead. Its findings were
reproduced locally before repair in every round; none depended on running the suites it could not run.

## diff — 4 rounds

**Examined:** all 4 counted diff rounds (R1 4, R2 2, R3 2, R4 3). Every finding was accepted; none was
disputed. The diff ships no code — docs plus one `BACKLOG_GRADUATED` registry row — so every round was
spent on whether the shipped documents tell the truth about themselves and about the census.

**One class produced all eleven findings: a corrected number that did not propagate.** Not a wrong
number, in most cases. A number corrected in one place and left standing in another.

- **R1 (4):** a `file:line` claim about a repair table spec round 5 had destroyed; eleven survivors
  called "repo-local" when three read outside the repo; `LIMITS.md` saying eleven arcs while the filing
  said twelve; the plan claiming fenced blocks round 3 had deleted.
- **R2 (2):** the purity screen reading a command's SEARCH TEXT as shell, so `rg -e "insert into …"`
  was excluded as mutating — and excluded SILENTLY, which the stated acceptance posture forbids; and a
  "14 documents" adoption figure that measured phrase occurrence, one of whose hits was a filing
  REPORTING the defect rather than an adopter.
- **R3 (2):** §1 still claiming every population figure is printed by the census when R2's corrected
  13 / 10 are hand-derived; and the downstream chain still reading the pre-R2 arithmetic.
- **R4 (3):** two more stale copies of that arithmetic, a self-referential "five corrections" count
  that each round made stale again, and this filing repeating a convergence claim the spec had
  withdrawn.

**The repairs got structurally better as the class repeated, and the last one is the useful record.**
R2's repair was to PRINT the census's exclusions rather than teach its regex shell quoting — correcting
toward the recognizer would have contradicted the spec's own argument in the same PR. R4's was to stop
DUPLICATING figures across documents at all: `LIMITS.md` now points at the spec's §6 for the reach
chain instead of restating it, this filing points at §5 for the repair partition instead of restating
it, and the corrections list is deliberately unnumbered because a running total of one's own errors is
itself a number that goes stale. Three rounds of propagation failures are cured by having one copy, not
by propagating more carefully.

**The direction of every numeric error is worth recording.** The purity screen under-reported, which
made the reachable population look SMALLER, which argues harder for the conclusion this document
reaches. It was found by review, not by the arc. A record that only ever errs in its own favour is one
nobody should trust, so both the direction and the finder are named in §6 rather than quietly fixed.

**Mechanizable:** none.

declined: the class here is one document set disagreeing with itself, which is the class the canonical
spec measures and declines to mechanize at corpus scale, and which the plan stage separately declined
to mechanize for a single document after building a checker that proved narrower than its own claims in
five ways. Building a third version inside the diff stage of the same arc would contradict both.

**Judgment:** what a correction owes. Each round's repair was correct where it was applied and left the
same fact wrong elsewhere, because a document set has no mechanism that makes a correction propagate.
The answer that finally held was not more diligence; it was removing the duplication that made
propagation necessary. That generalises past this arc and is why it is recorded here rather than in a
commit message.

**Infra:** the reviewer could not execute Vitest in its read-only sandbox (`EPERM` creating temp
directories) in all four rounds, said so each time, and used read-only probes and `node --import tsx`
instead. Every finding was reproduced locally before repair; none depended on the suites it could not
run.
