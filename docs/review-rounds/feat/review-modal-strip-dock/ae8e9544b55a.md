**Mechanizable:**

1. **An acceptance criterion that re-lists a declared probe domain.** A spec that declares
   `PROBE DOMAIN:` and then writes criteria enumerating viewports holds two lists that nothing
   compares. It drifted three times here — under-covering (r1), covering four of twelve (r2), and
   finally contradicting the defense that was supposed to fix it (r3). A `spec:lint` arm could flag a
   document containing both a `PROBE DOMAIN:` declaration and an acceptance table whose rows repeat a
   literal from it. The shipped repair is a taxonomy rather than a single name — REAL / REPLICA /
   DEGENERATE / STRUCTURAL, with an axis column on every criterion — because the criteria did not all
   range over the same kind of thing, which is why naming one domain was not enough.

2. **A hand-maintained transcript of a command's output.** Three rounds found three defects in one
   blast-radius table, in three different directions: narrower than claimed, then a repair that
   dropped a held site, then a table naming a file the command does not produce while omitting two it
   does. Nothing compared the table to the command. The mechanizable form is a section that states
   its cover as a runnable command and its CHANGED set as a claim the diff settles
   (`git diff --name-only origin/main...HEAD`), with everything else asserted unchanged and proved by
   its own suite. Two checkable claims replacing one uncheckable one.

   **declined: process-facing under the same freeze**, same reasoning and same re-file trigger. Worth
   recording that the shipped repair needed no tooling at all — deleting the transcript was enough,
   and a lint arm would have policed a construct that should not exist.
