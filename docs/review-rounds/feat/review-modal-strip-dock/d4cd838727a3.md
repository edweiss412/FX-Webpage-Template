**Judgment:**

- **Six of the four rounds' P0s were a red that could not fire, in six different disguises.**
  Not one was a wrong assertion or a missing test; each was a gate that would have reported success
  while the task did nothing. The general test is one line — *if the red is satisfied by any change
  that does not implement the task, it is not a red* — and this arc failed it three ways before
  writing it down.
- **The mandatory-task rules and the invariants can conflict, and the plan is where that surfaces.**
  `writing-plans.md` mandates a transition-audit task; invariant 1 requires every task to go red then
  green. For a subject another task creates, no ordering satisfies both. The resolution — fold it into
  the task that creates the states, serve the rule's purpose, and state the deviation — is a judgement
  a checker cannot make, which is the argument for review over more lint.
- **The bidirectional changed-set gate earned its keep on its first outing.** It caught a task editing
  a path the set omitted AND the set requiring a path no task claimed, in the same round. That gate
  exists because three spec rounds went on a hand-maintained blast-radius table; it found in one round
  what the table format hid for three.
- **Zero refutations across 39 findings, spec and plan.** The consistent lesson is not that the
  documents were sloppy — they lint clean at every round — but that *claims about coverage and about
  gates are exactly the claims a document cannot check about itself*.

- **The whole-tree GREEN criterion is the one repair that closed a class rather than an instance.**
  Four rounds found task boundaries leaving the tree red, and the first three repairs were the same
  move: find the suites the task breaks, list them, fix them there. Each list was incomplete in a way
  the next round found. The fix was to stop treating the task's own red command as its green criterion
  — a conflation nobody had written down and everybody was making. Round 4 then found the first
  version of that rule was itself underivable, and the fix was to ENUMERATE the arc's e2e suites once
  rather than derive them per task, because a default-config suite exercises the app without importing
  the changed component and no reference search can see it.
