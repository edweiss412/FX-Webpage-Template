**Judgment:** two of the nineteen findings landed on repairs made in the immediately previous
round, and both are worth naming because they share a mechanism: repairing by ANALOGY with an
existing code path, without checking whether the analogy's premise holds.

Round 1's repair had the retry write `demotedRef`, by analogy with the ratified demote path
which writes it. `demotedRef` has no clear path anywhere in the component and
`markZoomIntent` early-returns on it, so that would have made the re-pinch the spec promises
permanently impossible for the rest of the lightbox session. The analogy failed because
`demotedRef` guards a mid-gesture fetch loop, and no gesture can be live on the retry path —
a failed slide does not mount the zoom wrapper at all.

Round 2's repair specified the in-flight control as `disabled`, by analogy with
`components/admin/RetryWatchButton.tsx:42`, which is correct at ITS site. The analogy failed
because that button is never the focus origin and this one always is.

The general form: **an analogy transfers a mechanism, not the premise the mechanism rests
on.** Before copying a guard, state what it guards against and check that the hazard exists
on the new path. Both defects were invisible to the analogy and obvious the moment the
premise was written down.

**Infra:** none. All three dispatches returned clean verdicts with no wrapper faults, no
`no_verdict`, and no reaped runs.

**Mechanizable:** one, and it is the one that would have saved the most rounds.

**A guard offered as a class closure was never itself scored, and the reviewer scored it
instead.** §4.0.3's registry-plus-scanner was built in round 2 as the structural answer to a
recurring class. Round 4 ran executed mutants against it and found it fails OPEN on four

`React["useState"]` access — plus a key-alias hole where two declarations sharing a name
inherit one row and one sweep decision. The scanner recognised only a bare `CallExpression`.

Every one of those is exactly what `pnpm mutation:guards` exists to find, and AGENTS.md's
convergence criterion already says enrolment precedes review for a guard surface. I wrote the
cover, called it a cover, and shipped it into review unscored. The reviewer then did by hand,
across a paid round, what a mutation run does in about ninety seconds.

declined: `LIM-UNSCORED-GUARD-OFFERED-AS-CLOSURE`, a guard shipped as a class closure without
being mutation-scored first, so its own fail-open cases surface as review findings instead of
as survivors. Parked rather than filed: the rule it violates already exists in AGENTS.md
(convergence criterion bullet 4, enrolment precedes review), so this is a third measurement of
that rule and not a new one — which is where the other two went. The 2026-08-25 process mint
freeze declines it independently: its done condition is a property of the tooling, not a number

**Judgment:** three rounds were spent on one task's RED, and the honest answer was available
the whole time.

Task 9 is a transition audit. Round 2 rejected its first justification ("no test enumerates the
pairs") because a missing test is not a production defect — correct. My round-2 repair claimed
the overlay animates inside the gallery's presence subtree; round 3 refuted it by reading, since
the only `AnimatePresence` wraps the lightbox and the cell ternary sits outside it. My round-3
repair claimed the exit-window buffer lacks a retry-outcome path; I refuted that one myself
before the round-4 dispatch, because `routeAnnouncement` pushes ANY message into the buffer and
is message-agnostic.

Three inventions, each plausible, each refuted by reading the code they claimed to describe.
The truth was structural and boring: **by the time that task runs the implementation is already
correct, so the audit is a GUARD and has no natural red.** The repair that finally worked is
the one Task 8 had used since round 2 — plant the defect, observe the red, revert, observe the
green — and it was available at round 2.

The general form, for the next arc that finds itself inventing a red: **if two attempts to name
a production defect for a task both fail on reading, stop inventing a third and ask whether the
task has one at all.** An audit over correct code is a guard. Saying so costs one sentence;
not saying it cost three rounds here.
