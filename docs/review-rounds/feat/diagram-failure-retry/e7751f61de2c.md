**Judgment:** two of the nineteen findings landed on repairs made in the immediately previous
round, and both are worth naming because they share a mechanism: repairing by ANALOGY with an
existing code path, without checking whether the analogy's premise holds.

Round 1's repair had the retry write `demotedRef`, by analogy with the ratified demote path
which writes it. `demotedRef` has no clear path anywhere in the component and
`markZoomIntent` early-returns on it, so that would have made the re-pinch the spec promises
permanently impossible for the rest of the lightbox session. The analogy failed because
`demotedRef` guards a mid-gesture fetch loop, and no gesture can be live on the retry path —
a failed slide does not mount the zoom wrapper at all.

Round 2's repair specified the in-flight control as `disabled`, by analogy with
`components/admin/RetryWatchButton.tsx:42`, which is correct at ITS site. The analogy failed
because that button is never the focus origin and this one always is.

The general form: **an analogy transfers a mechanism, not the premise the mechanism rests
on.** Before copying a guard, state what it guards against and check that the hazard exists
on the new path. Both defects were invisible to the analogy and obvious the moment the
premise was written down.
