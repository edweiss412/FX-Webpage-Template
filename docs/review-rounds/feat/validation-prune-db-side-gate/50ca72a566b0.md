# Review-round economy — `feat/validation-prune-db-side-gate` @ `50ca72a566b0`

## spec — 4 rounds

**Examined:** every finding across the four spec rounds, plus what the repair for each one changed.
R1 BLOCKING (2), R2 NEEDS-ATTENTION (2), R3 BLOCKING (3), R4 BLOCKING (2). Nine findings on a document
whose subject is a five-line SQL function — and the shape of that number is the point: two findings were
against the design, seven against the document's own claims and test design.

**Mechanizable:** two of the seven, both of a shape a checker could own.

- **Stale prose surviving a design change (R2 P2).** One sentence describing the deleted two-table seed
  survived because it said "prune gate" with a space while the author's sweep grepped `prune_gate`.
  **declined: a lint here is a recognizer over prose, and prose recognizers are this repo's measured
  losing move** — the sweep set would have to model every case-and-separator variant of every removed
  identifier, and the corpus already carries an arc that grew a 1207-line detector one grammar corner
  per round. The durable form is the author-side rule, not a checker: a removal is swept by the CONCEPT,
  and the cheap mechanical proxy is a case-insensitive grep with separators collapsed, run once. Cost of
  the miss was one finding, not one round — R2 carried two findings and would have run regardless.
- **Bare `N/A` in a completeness matrix (R2 P1) — filed as `BL-SPECLINT-MATRIX-BARE-NA`.** The
  spec-self-review rule already says every cell is an action or an `N/A — reason`. Twenty-one cells said
  bare `N/A`, and two of them were false — the falsehood hid behind the missing reason, because writing
  "N/A — the tables carry no trigger" forces the author to check. The check is a cell equal to `N/A`
  with nothing after it, inside a table block; no grammar, no recognizer growth. Incident: this arc's
  R2 P1, corpus row `docs/review-rounds/feat/validation-prune-db-side-gate/50ca72a566b0.jsonl` round 2.

**Judgment:** seven of the nine were design findings that no checker reaches, and they are the reason
the rounds were worth their cost.

- **R1 P0 killed the design, not a detail.** Two rows encoding one fact can disagree; the reviewer
  produced three lifecycle states where they do, permissively. The repair was subtraction — the second
  table is gone — and that is a strictly better artifact than any patch to the seed would have been.
- **R3 P0 was the sharpest finding of the arc.** The acceptance criteria, written to catch a broken
  gate, would have performed the global deletion they existed to detect, on the live validation project.
  Nothing mechanical finds that: it requires reading the criteria as a program and asking what happens
  when the thing under test is broken rather than when it works.
- **R1 P1, R3 P2 ×2, R4 P2** were citation-fidelity findings against live state (parity compares
  signatures not bodies; `sync_log` retains SELECT behind `admin_only`; D4's boundary is
  PostgREST-scoped; `service_role` holds direct DELETE so the prunes are not the only delete path). Each
  is a claim the author could have probed and did not, and each was settled by the reviewer's probe in
  one round. The corrective that actually worked was §3.10 — deriving the grant/RLS state from a command
  instead of recalling it — and it should have been drafted before round 1, not after round 3.
- **THE SAME AXIS RAN THREE ROUNDS: R3 P0, then R4 P0.** Both said the acceptance probes could commit
  the deletion they exist to detect. The R3 repair was per-instance (wrap the default call; declare one
  limb harmless because a 100-year window is empty) and R4 broke exactly that argument — the emptiness
  was checked in a separate autocommitted statement, so it bounds nothing under concurrent traffic. The
  R4 repair is structural instead: EVERY call to either prune, in every criterion, probe and script,
  is inside a rolled-back transaction, and no call may be exempted by an argument that it cannot delete.
  Two limbs replaced three. The rule that generalises: when a safety argument about a specific call is
  refuted twice, stop arguing about calls and make the safety a property of the harness.

**Infra:** none. All four dispatches returned a verdict on the first attempt — no reap, no
`no_verdict`, no retry ladder, no `CONVERGENCE_ACK` override. Reviewer probes ran against the local tree
only: the sandbox cannot resolve the validation pooler host, so every claim about the live validation
project in this document rests on the author's transcripts in §3, not on reviewer re-measurement. That
limit is recorded here because an APPROVE is bounded by what the reviewer could execute.

**What the author would do differently, stated as a rule rather than a regret:** probe the acceptance
criteria the way the implementation is probed. Three of the four rounds' most expensive findings were
against the TEST design, not the design — the ACs were prose about what would be asserted, while the
implementation had already been dry-run against a real database twice. The asymmetry is the whole story
of this arc's round count.
