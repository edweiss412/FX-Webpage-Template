**The repair that converged it was a REMOVAL.** Three defeats of one recognizer, each by a different
member of an open class — every way to make an async callback resolve without throwing, times every way
to name a client — is the arms race this repo's round-economy rule names, and its prescribed answer is
to narrow rather than to widen a fourth time. So the recognizer was deleted. The property was never
"the source contains a throw"; it is "this suite left nothing behind", and that is closed over a finite
set: the rows this run wrote. A check that never reads spelling cannot be defeated by a spelling. AC-3,
the one transaction whose commit erased its own evidence, got a dated-now witness row the prune cannot
touch, so a commit strands it where the check finds it.

**Judgment:** the axis is one choice made in the spec, and it is worth naming.

- **AC-9 proves channel-independence STATICALLY because it cannot prove it behaviourally.** Spec §4.7
  settled that: a PostgREST `rpc` request cannot be enclosed in a transaction the probe controls, so a
  REST limb would COMMIT whatever a broken gate let through — the one exemption the arc's rollback rule
  forbids. Choosing a static proof was correct. But a static proof over a program's TEXT is a
  recognizer problem, and it drew three rounds while every other part of the diff drew none.
- **The behavioural cases caught all three mutants; the static pin caught none of them until repaired.**
  That is the measurement worth keeping. R3's mutant genuinely neuters the gate, and the refusal cases
  went red on it immediately. The static pin exists to cover the ONE channel those cases cannot reach,
  and it is the weakest assertion in the arc for exactly the reason it exists: it is the only claim here
  that cannot be settled by running something.
- **The rule that generalises**, and it is narrower than "prefer behavioural tests": when a criterion
  must be proven statically because its channel cannot be executed, expect its cost to land in review
  rather than in CI, and budget rounds for it accordingly. Three of this arc's four diff rounds went to
  the one assertion that could not be run. Nothing was wrong with the choice; what was wrong was
  treating that assertion as though it were as cheap to get right as the ones a database answers.

**The stage converged twice, and the second time is the one that counts.** R7 returned APPROVE with

used — the criterion did not move to reach the verdict. Across spec, plan and diff this arc ran twenty

**What the second half cost, and what would have avoided it.** Three rounds went to a pin guarding a
test, on a branch whose product change never moved. Two things would have collapsed them. Running the
required test tier before declaring a stage converged would have surfaced both guard failures before
R4 rather than after it. And reaching for the runtime observation FIRST — asking what the database
would look like if this went wrong, rather than what the source should say — would have skipped both
recognizer generations, since the check that finally converged is simpler than either pin it replaced.
The general form: when a property is about what a program DOES, prefer observing the effect over
recognizing the text, because the text has an open grammar and the effect does not.
