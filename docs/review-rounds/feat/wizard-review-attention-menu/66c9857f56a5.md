## spec — 4 rounds

**Examined:** R1 NEEDS-ATTENTION (8 findings), R2 BLOCKING (6, one refuted),
R3 NEEDS-ATTENTION (4), R4 NEEDS-ATTENTION (4). Twenty-two findings, none

What each round bought. R1 was structure: the frame extraction as drafted would
have invalidated every path-keyed registry row, and the reviewer found the
line-keyed rows the spec had not read. R2 was the round that mattered: I-1 (pill
count is a superset of the badge count) was false for a persisted warning with
no `severity` field, because the badge skips only `"info"` while the routing
helper accepted only `"warn"`. That is a real defect in the design, found by
reading two predicates side by side, and the repair (one exported predicate at
seven sites) is a better design than the draft. R2 also moved the published jump
anchor from the section block to the card, which is where the operator expects
to land. R3 and R4 were test-coverage completeness on the repairs R2 introduced:
per-site severity cases, both sides of each cap, a total contract for a
parallel-array prop, a second byte baseline for the dirty state. Real, small,
and each one a case the plan would have had to write anyway.

Rounds 1-2 bought design correctness; rounds 3-4 bought test enumeration on the
round-2 repairs, at one dispatch each.
