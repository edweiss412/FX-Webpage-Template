**Mechanizable:** the round count has ONE root cause, and it is the brief, not the reviewer.

**The consequence bound this arc shipped was not closable.** It read: "every input is either
handled correctly or silently NOT flagged — never flagged wrongly." Quantified over all
possible input, for a line-based counter reading two other grammars, that is an infinite
space. Every corner CommonMark or the JavaScript lexer owns is then an admissible finding,
forever, and each one is genuinely real — so the reviewer complies with the contract, files a
correct finding, and the round count is set by the size of the grammar rather than by the
state of the code. AGENTS.md's own template bound is deliberately weaker ("a conservative
demote plus a surfaced signal is a DOCUMENTED LIMIT, not a finding"); this arc ratcheted it to
parser-grade precision and then paid for it thirteen times.

The measurement: **thirteen of the twenty-one rounds (R6, R8-R19) are one class — a hand-rolled
lexical approximation of JavaScript, inside a Markdown linter, being wrong about JavaScript.**
Escaped backticks, regex literals, `${}` nesting, reserved words, `for await`, postfix `++`,
`)` disambiguation. Each supplied one more construct, each repair was correct, and the next
round found the next construct. The detector reached 1207 lines and its suite 1992 — the same
trajectory as the 2929-line shell-grammar parser AGENTS.md already cites as the failure
exemplar. The mutation gate could not stop it: the surface IS enrolled and the score DID hold
at 1.0000 every round, because the gate bounds "the suite pins the code", not "the code
matches CommonMark" — and the brief then pointed the reviewer at exactly that uncovered axis
and called it the remaining high-value attack, which is an invitation to round 17.

**The repair is to the ADMISSIBILITY BAR, not to the recognizer, and it is already finite and
committed — with one calibration R21 paid for and is worth copying.** This arc ships a corpus probe that lints all 1052 tracked docs and writes every
advisory to `docs/superpowers/specs/probes/2026-08-11-speclint-corpus-scan.survivors.txt`. So
the bound becomes: **a false advisory counts only if it fires on the live corpus.** That set is
finite, enumerable, and re-derivable by one command; "the corpus scan is clean" is a closable
convergence criterion in a way that "no input escapes" never was. A constructed input no
tracked doc contains files as a DOCUMENTED LIMIT under the threat fence the brief already
carried — the fence existed from round 1 and went unenforced because nothing made it
checkable. R20's own `- - -` fixture is the illustration: no doc in this repo writes a
thematic break under a two-item list, so under the corpus bar it is a limit, while the five
peers its sweep turned up DID fire on real documents and were repaired, taking six false rows
out of the shipped population. Same sweep, two dispositions, decided by a command rather than
by argument. The calibration: a corpus bar needs its SECOND clause stated in the same breath as its
first, or it swings too far the other way. "A false live-corpus advisory is admissible" alone
makes the arm's own ratified false-positive population admissible — and for a detector that
ships ADVISORY precisely because it mixes true and false rows, that is every row somebody
dislikes. The bar is: a corpus row that is wrong for a mechanism the classification record does
NOT already carry. The record is what makes the difference checkable, and an arc without one
cannot use this bar. Likewise, "the corpus scan runs clean of false rows" is not a command:
the scan asserts severity and non-vacuity: nothing decides truth mechanically. State the
closable conditions as what actually runs — mutation gate green, corpus population equal to
the committed one, classification buckets summing to it.

Promote to `docs/agents/adversarial-round-economy-2026-07-31.md`: **when a detector arc owns a
corpus probe and a classification record, the corpus is the admissibility bar and the record is
its exclusion set; state both in round 1.**

A second durable rule, subordinate to the bound above: **when a guard must read a second
LANGUAGE, do not approximate its grammar — either parse it with the real parser, or reduce the
read to a question the language cannot invert.** Both exits were available here and both are cheap. The repo already depends on a
JavaScript parser; and the arm only ever needed "is this line a live top-level declaration",
which the R9 duplicate-declaration net answers WITHOUT a lexer — it is why the arm's worst
case stayed a missed advisory even while the lexer was wrong. The lesson is that the second
mechanism, the one that made every lexer bug survivable, was added at R9 and should have been
the WHOLE design at R6. A lexer that is only a performance optimisation over a safe fallback
does not need thirteen rounds of correctness review; one that is load-bearing does.

Three narrower shapes, all real and all worth keeping:

1. **An equivalence argument of the form "condition C is unreachable because it would force
   property P", where P does not actually follow** (R1, R2, R12). A set operation that
   discards information — multiplicity, the difference between a marker width and an indent —
   reasoned about as though it preserved it. The registry is already the mechanization: it
   turns each argument into a claim with a decidable counterexample, so the reviewer's job is
   bounded refutation. What is NOT mechanized is the SWEEP; a checker flagging every `reason`
   string containing "requires", "forces" or "unreachable" would have pointed at all three
   before dispatch. Filed as a candidate, not built here — it needs a corpus of arguments
   across surfaces to calibrate, and this is only the sixth enrolled surface.
2. **An enrolled surface can score 1.0000 with an empty unaccepted set while its ACCEPT-SET
   is wider or narrower than its spec** (R4, and R10 for the same reason). No declared
   operator perturbs a regex's alternation set or swaps a case-sensitive pattern for a
   case-insensitive one. The gate bounds "does the suite pin what the code DOES" and says
   nothing about "does the code do what the spec SAYS". The durable form is a brief
   instruction, not a checker: when the subject is enrolled, state the score and then point
   the reviewer at accept-set-versus-spec, because the score has already answered the rest.
3. **An EXCLUSION that removes inputs from a comparison, applied to one side of a pair**
   (all three R7 findings, and R17). The exclusion did not merely fail to fire — it
   MANUFACTURED a finding, the one direction an advisory arm may never take. The rule: an
   exclusion is a property of the COMPARISON, not of one operand, so a line that loses any
   quantity leaves the comparison entirely. That is now how all three arms behave, each
   direction pinned by fixture.

And one observation cheap enough to just state: **a written limit is a CLAIM, and R6's was
wrong in the expensive direction.** "This approximation can only miss, never mis-fire" is
exactly the sentence a reviewer should attack, and R8 attacked it with a five-line script.
Where a limit asserts a DIRECTION of error, the fixture pinning it should be the one that
fails if the direction inverts — not the one that shows the miss.
