## spec — 4 rounds

**Examined:** the declared-limit pin collision arm — the pin grammar (§3.1), the Files-declaration span
(§3.2), the obligation and its two finding codes (§3.3, §3.4), the disposition registry and its derived
cover (§5), the documented-limits set (§8), and the acceptance criteria (§10). Twelve findings across four
returned rounds: 3 BLOCKING at r1, 4 at r2, 2 HIGH at r3, 3 at r4 (two HIGH). Every one was accepted; none was
refuted.

**Mechanizable:** three of the nine are shapes a check could have caught before any dispatch.

1. **A superseded number surviving elsewhere in the artifact pair.** Twice — r1 F3 (the corpus
   cardinality was normative and already stale, because this arc's own plan grew the corpus) and r2 F3
   (AC-2 still carried the pre-r1 prose-only population). Both times the sweep that missed it was
   keyed on a PHRASE (`48-plan`), and the survivor used the same number in different words. The repair
   was to make the sweep DERIVED: extract every integer from both documents with its line and read each
   against its source. That pass also caught what no phrase sweep could — that inserting two
   documented-limit items had renumbered the tail while four `§8 item N` cross-references still pointed
   by number. This is the same defect class as `BL-SPEC-CLAIM-SWEEP-AFTER-REASONING-FINDING`, which
   this arc's own second PR exists to mechanize; measured here at two rounds.
2. **A `red=` that cannot express a verdict.** Task 7 named `pnpm vitest run
   tests/mutation/guardSurfaces.gates.test.ts`, and that file is in `NIGHTLY_ONLY_EXCLUDES`
   (`vitest.projects.ts`), so every default project excludes it: the run collects zero tests, exits 0,
   and is green from birth. `spec:lint --exec-red` already probes vitest-shaped `red-state=live`
   commands for collectability; this marker was `red-state=authored`, which is not probed, so nothing
   looked. An authored red whose command cannot collect on the CURRENT tree is a static defect and is
   mechanizable at the same seam.
3. **An authored red that fails on an unresolved import.** Every one of this plan's six created-module
   tasks asserted a red of the form "the module does not exist, so the suite cannot import it".
   `docs/agents/writing-plans.md` already rules that invalid by construction — it goes green when the
   test file changes, not when the implementation lands — and the rule was read at drafting time and
   applied to none of the six. The repair creates each module as a typed STUB so the suite resolves and
   fails on its ASSERTION. A marker-level check could ask whether a `red-target=` names a file the task
   itself creates and require the stub step.

**Judgment:** the remaining nine findings are design calls a check cannot make, and they cluster on ONE
axis — where the recognizer's boundary sits. r1 F1 (the stated Files grammar and the calibration probe
disagreed, dropping a real advisory), r1 F2 and r2 F1 (substring matching on paths, and source-versus-
decoded spelling of titles: two different false-advisory shapes, each one ordinary edit from a live
input), r2 F2 (the read seam is tracking-blind, so an untracked suite reads fine and reports "no pins"),
r3 F1 and F2 (a line matcher cannot see block-comment or template state; a skipped blank let an inline
declaration absorb the checklist below it), and r4 F1 and F2 — the second of which is the sharpest of
the arc: every proof exercised the PURE CORE with test-supplied prepared lines, so a shipped adapter
passing RAW lines, or never injecting the surface table, satisfied all of them while `0 hard` stayed
green because the arm is advisory-only. Presence-versus-adequacy inside the proof harness. The repair
runs the shipped CLI as a real subprocess and asserts both failure directions. Three consecutive rounds on one axis, so the r3
repair took the standing direction — NARROWING, not predicate growth: the core stopped deciding what is
code at all and now scans text the adapter prepared with the TypeScript parser as the oracle, and an
inline declaration became complete on its own line. Both repairs DELETE analysis. The measured effect is
the point: the narrowing removed two of five previously-measured advisories, both false, without
touching any advisory a Files declaration actually earns.

**Infra:** one round was recorded as `no_verdict` that was neither Codex nor the reaper — a polling Bash
call held a ten-minute wait, its timeout killed the process group, and `result.json` recorded
`error: "signal SIGTERM"`, `durationSecs: 0`, and `endedAt` exactly ten minutes after `startedAt`.
Reading those four fields before attributing the status is what identified it; `setsid` then turned out
not to exist on Darwin, so the working shape is `nohup … & disown` with polling in SEPARATE short calls.

**Nothing was lost, and that is established rather than asserted.** `no_verdict` has at least three
causes — reaped, killed, genuinely empty — so the status alone settles nothing, and picking the
convenient one is a fail-open reading. The session rollout survives independently of the out-dir:
`~/.codex/sessions/2026/08/20/rollout-2026-08-20T00-24-23-01a01da0-….jsonl`, 185 records, THREE
assistant messages, none carrying a `VERDICT:` or `FINDINGS:` line. The row now carries that cause in
its `label` field, because an intentional kill and an infrastructure death produce byte-identical rows.

**And the recovery paid for itself.** Those three progress messages named a defect no later round
raised: the §2.1 shape calibration had been produced by a FENCE-UNAWARE probe, while §3.2 reads only
non-fenced lines. Re-measuring fence-aware — and against the no-blank-skip rule round 3 shipped, which
had stranded the table a second way — moved every figure in it: 2567 headers rather than 2559, 642
inline rather than 636, and 1666 immediately-followed-by-a-list rather than 2136 under the draft that
skipped a blank. The generalisation is the one worth keeping: when the evidence is a status field,
check whether that status has exactly one cause.


## plan — 4 rounds

**Mechanizable:** declined: no ledger row, and the reason is the arc's own evidence rather than
