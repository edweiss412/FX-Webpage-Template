# Review-round economy — `feat/m2-ui-cluster` (M-wave 2 unit W-UI)

Corpus: `876cbd06c156.jsonl`. Split tight-scope briefs per the large-diff rule —
A (z-index bands + guard), B (row-slot vocabulary + icon-only colour), C
(timing scanner + font pipeline).

## diff — 8 rounds

**Examined:** eight distinct counted rounds across three briefs — A r1-r4 then a confirming r6
(2 + 2 + 4 + 4 + 3, every one P1), B r1-r2 plus a confirming r7 (4, 3, 4), C r1 plus a
confirming r8 (2 then 3, both BLOCKING). Twenty-seven findings, **zero refuted**. That is worth stating first, because the usual
round-multiplier in this repo's corpus is a reviewer relitigating a ratified
decision, and none of that happened here.

**Mechanizable:** the dominant cost was ONE shape, repeated: *a guard whose green
state is compatible with the thing it claims to prevent.* Eight of the ten
findings are instances.

- A r1: the scanner anchored on a bare token boundary, so `focus:z-50` hid; and
  it required module scope, so a function-local `cn("… z-10 …")` hid.
- A r1: a typo'd band emits no `z-index` at all, and the census — which only
  hunts numerals — stays silent.
- A r2: the repair was `@theme`-scoped STRING PRESENCE, which cannot tell a live
  declaration from a commented-out one, a duplicate, or a `:root` override.
- A r2: one exemption row keyed on file + token covered every identical site in
  that file.
- A r3: four more variant idioms, plus a compiled-value parser that accepted
  `50px` as 50 and read the first rule rather than the effective one.
- B r1: the border contract asserted the INITIAL render only, and a re-scan
  result is bordered chrome that only appears after interaction.

**Each repair widened a hand-written pattern, and the next round found the next
idiom.** That is the ratchet the round-economy rule names: enumeration over an
open class does not terminate, and three rounds is where it became undeniable.

**What actually closed it** was giving up on recognizing source and reading the
COMPILED stylesheet instead. Tailwind's own extractor sees exactly what reaches
the DOM, so the criterion stops being "have I thought of every idiom" and becomes
"does the emitted CSS contain a non-band z-index" — closed, machine-checked, and
parsed with postcss rather than a regex, because a regex cannot see a rule's
parent and v4 emits variants as nested at-rules. Fourteen mutants, all killed,
including every idiom review had named across three rounds.

**The lesson to carry:** when a guard's subject is "what the toolchain does with
this source", the toolchain is the oracle. Reimplementing its extractor by hand
is the thing that took three rounds. This should have been round 1's design.

**The three findings that were mine rather than the guard's**, recorded because they are the
transferable part. C's BLOCKING finding was an enrolment I had half-completed — the surface was in
the registry but absent from the gate's exhaustive `EXPECTED_LEDGER_KINDS` map, whose assertion is a
set equality, so the gate could not pass for ANY surface. B r2's P1 was four byte-pinned assertions
broken by a border removal, because the suite was not re-run after the fix. And a `/s` regex flag the
repo's TS target rejects shipped because the verification chain was `pnpm typecheck 2>&1 | tail -2 &&
…`: a pipeline's exit status is the last command's, so `tail` returned 0 and the `&&` continued past
a failed typecheck. **Verifying through a pipe is not verifying.**

**Where the thread ended, and why it ended rather than continuing.** Round 4 returned four more P1s;
three closed outright and the fourth is filed as a documented limit in `_zIndexScan.ts`'s header with
its consequence stated: candidate discovery must read source, because a typo'd band emits no CSS to
read, so a class assembled through a form no static reading resolves is not discovered — and its
worst case is LOUD, an element with no z-index and an overlay visibly behind its content. The silent
failure is closed by the compiler. Twenty-seven mutants across the four rounds, all killed. A fifth
round of recognizer-widening would have bought nothing the compiler does not already guarantee.


**The confirming rounds were not a formality, and that is the honest headline.** Each of the three
returned MORE findings, and two were severe enough to change the product rather than the guard:

- **A r6 F1** — the value check and the name check were INDEPENDENT. "50 is some band's value" and
  "`z-overlay` is some band's name" were both true after retuning `--z-index-overlay` to 40, so every
  overlay in the app could silently move a band while the guard stayed green. The mapping IS the
  contract, and it was the one thing four rounds of hardening had never asserted. Fixed by asserting
  the correspondence; the mutant now reads `z-overlay compiles to 40, but the band is 50`.
- **C r8 F1** — not a guard gap at all. The `ms` disposition claimed the delay was "dictated by the
  SERVER's Retry-After header", which is true only when that header arrives and parses. A missing or
  malformed header lands on a client-owned 5000 ms, so the disposition was suppressing a timing this
  project chooses. It is now `AGENDA_RETRY_FALLBACK_MS` with its own §5.5 row, and the reason names
  both paths. A reasons-required registry is only as good as the reasons.

**Judgment:** two decisions were genuinely arguable and were settled in the file
rather than by another round. `self-start` and `shrink-0` stay ignored by the
treatment signature — they say how a parent PLACES a control, not what it looks
like — while `w-full` and `flex-1` do not, because both change the control's own
width; the strip is now a reasons-required registry whose entries must be in use,
and its first run deleted one nobody used. And the `flat` row drops its FILL as
well as its border, because `--color-surface` against `--color-surface-sunken`
measures 1.11:1 and the fill-separation reasoning was simply wrong.

**Infra:** none. Every dispatch returned a verdict; no reaped runs, no
`no_verdict`. Both reviewers reported the same sandbox limitation — scoped
Vitest could not create its temp dir under a read-only sandbox — and both said so
plainly instead of reporting a test result they did not have, which is the
behavior the admissibility contract asks for.

**Two findings came from neither reviewer**, and both from the same habit of
checking a claim rather than re-reading it: computing the contrast pair that a
commit message asserted (1.11:1, killing it), and checking the PR body's own
count of archived entries (five claimed, four archived — the fifth still carried
an in-progress marker that would have merged to main).
