**Examined:** all dispatches
(`docs/review-rounds/feat/review-infra-gates/61281c23e8ce.jsonl`), their briefs, and
every disposition in `docs/superpowers/plans/2026-08-06-arc-b-review-infra/closeout.md`

Verdicts: R1 BLOCKING (9), R2 BLOCKING (6), R3 BLOCKING (6), R4 BLOCKING (5), R5 split
(5 + 5), R6 split (9 + 5), R7 split (5 + 2),
R8 split (5 + 3). **Sixty-five findings, sixty-five accepted, zero refuted.**

That last number is the headline and it is not a compliment to the implementation. Eight
rounds, every single finding real — this arc built two new guard surfaces from scratch,
and a from-scratch guard is where this corpus's review economy is genuinely earned rather
than burned.

**R5 was SPLIT after the whole-diff form timed out.** The first R5 dispatch was killed at
1462s by the wrapper's attempt cap, and a retry with `--attempt-max-secs 3000` was
rejected outright (`ATTEMPT_MAX_SECS exceeds max 1380`) — which the implementer did not
notice for 45 minutes, because it polled `result.json` instead of reading the wrapper log
the dispatch had already written. **Check the wrapper log immediately after dispatch;
a rejected dispatch and a slow one look identical from the output directory.** Splitting
into two file-scoped reviews (gate, parser) is the documented remedy for exactly this, and
both returned in minutes.

### Two failures were mine, and both are mechanizable

**A string replace that does not match is a silent no-op, and a success message printed
after it proves nothing.** This happened TWICE — R2 finding 4 (caught by R3) and R3
finding 4 (caught by R4) — and in both cases the commit message described a change the
commit did not contain. The second time had a subtler mechanism worth writing down: the
edit script asserted its anchor, but a LATER assertion in the same script failed, and
because the script writes once at the end, the earlier successful edit was discarded
along with it. The assertion was not the problem; the write granularity was.

**Mechanizable, and cheap:** after any scripted source edit, grep the TREE for the new
content before reporting success. The reviewer caught both by running the mutant against
the tree instead of reading the diff summary — which is exactly what the finding-3 brief
line now asks for explicitly ("verify against the TREE, not against this description").

### R6: fourteen findings, and the shape finally separates cleanly

Nine on the gate, five on the parser, and the split is the useful part:

- **Three were real MISSES** with concrete consequences — code after an import on the same
  line was dropped with the line; comments were masked BEFORE strings, so the `//` in a URL
  string blanked the rest of it; and interpolation braces were counted without recognizing
  strings, so a `}` inside one ended the interpolation early. All three were the same root
  cause: masking done as a CHAIN of independent passes, where every ordering is wrong
  somewhere. Replaced with one tokenizer.
- **Six were UNPINNED behavior** — correct code, no case that would notice its removal.
- **Five were parser edge cases**, each with an exact reviewer message, each leaking an
  EXAMPLE verdict: indented code directly after an ATX heading; `2.` interrupting a
  paragraph when only `1.` may; a bare `>` not popping a stale list frame; an open fence
  ignoring the end of its container; and a TAB-indented `***` read as a thematic break
  because the check counted characters rather than columns.

**On the round count.** Six rounds and fifty findings is not convergence by any reading,
and the honest diagnosis is not "the reviewer kept moving the goalposts" — every finding
came with a mutant or an exact message, and every one was accepted. It is that TWO new
recognizers were built from scratch in one arc, and a recognizer's defect surface is only
visible from outside. The enrollment this arc should have had from the start is the
source-mutation registry: a declared operator set makes "the guard does not pin what it
claims" a computed score rather than a reviewer's enumeration, which is exactly the
open-ended shape that produced rounds 4 through 6.

### R8: eight findings, and the parser's three were all ONE construct

Every parser finding in R8 was HTML-block state — a construct added late, in R6, and
therefore never subjected to the container/boundary rules the fence path had already been
taught over four rounds. **A construct added after the invariants were established does
not inherit them**, and nothing in the suite noticed, because each rule had been pinned
against fences specifically. That is the most transferable lesson of the arc: when a
guard learns a rule, the rule belongs to the guard, not to the case that taught it.

Nine mutants run this round; two reported SURVIVED and neither was a real gap. One was a
probe defect — the anchor did not match, so the edit was a silent no-op, the THIRD time
that exact failure appeared here. The other is a genuinely equivalent mutant.

### R7: the curve finally bends — 14 findings to 7

Three of the seven were false positives on VALID code, which is the failure mode that gets
a gate switched off rather than fixed: `UNCHECKED_INDEX` scanning raw text so a string
literal and a comment both fired; a multiline aliased import leaving its source name
looking free; and an interface method SIGNATURE, which has no body, so the body-brace
discriminator could not see it. Two more were unpinned generator properties (the identity
FIELD, and recursive traversal — every earlier fixture used one directory). One was a
parser miss introduced by R6's own repair: closing a fence when its container ends
CONSUMED the dedented line, so a root fence opening on that same line was never seen.

Two of the round's own new pins then survived their mutants and had to be repaired
before the repairs could be trusted — a multiline-import fixture whose bound name was
also a registry name (so it discriminated nothing), and the whole-statement mask itself,
whose `(?:;|$)` alternative is useless under `/m` because `$` matches an end of LINE.
**Both were caught by running the mutant, not by reading the code.**

### R5: ten findings, and nine were UNPINNED behavior

Both halves of the split returned the same shape the arc has been returning since R2 —
correct code with no case that would notice its removal. The gate's five were all of that
kind; the parser's five were live misclassifications, each with an exact reviewer message
(`- - -` read as nested markers, a bare `>` not counting as blank, `search` missing from
the type-6 set, a tab-width closer measured from column zero, and a bare `-` not ending
its list). Every one leaked an EXAMPLE verdict — the expensive direction.

One of the ten repairs' own pins then survived its mutant: the attribution-bound case used
a seven-line gap, which is unattributed under both the correct bound and the loosened one.
Only a gap of exactly six discriminates. **A boundary test that does not sit ON the
boundary is not a boundary test**, and it took running the mutant to see it.

### The dominant finding shape: a repair that closes its instance, not its class

R2 found three (an unplaceable check testing the raw line; a fail-open ceiling parse; a
`not-ui` token removed from suppression but left out of targeting). R4 found four
UNPINNED repairs — correct code with no case that would notice its removal. Both are the
same defect at different altitudes: **the fix was aimed at the reported example rather
than at what the example was an example of.**

**Mechanizable:** the class-sweep rule already covers the first half. The second half —
"every repair ships a case that fails against the pre-repair code" — is not written down
anywhere as a rule, and it is what R4 spent its entire round on. Five mutants were run
after R4 and all five died; that step should have preceded the round, not followed it.

### Judgment, not mechanizable

R1's finding 9 (baseline identity keyed on absolute line numbers turning one inserted
blank line into 44 offenders) and R3's finding 6 (the ordinal fix being order-dependent
in the opposite direction) are design critique. No tool infers "this identity scheme has
the wrong invariance". Notably R2 and R3 pushed the same field in OPPOSITE directions and
the resolution satisfies both — summing counts per content identity — which only became
visible because both rounds happened.

**Infra:** one. R5's whole-diff dispatch exceeded the 1380s attempt cap and its
longer-timeout retry was rejected by flag validation. Both were operator errors against a
documented limit rather than upstream faults, and both are recorded above because the
second cost more wall-clock than the first.

### Note on the briefs

Every brief carried the consequence bound with the literal "never silently wrong", a
threat-model fence, an explicit rejection of the closure-set framing, and — from R2
onward — the surviving-mutant admissibility standard for guard findings. The reviewer
applied it as stated: every finding in R3 and R4 arrived with a concrete mutant, and R4
explicitly distinguished the four unpinned-repair findings from operator proposals.
