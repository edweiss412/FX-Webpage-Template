## diff — 6 rounds

**Examined:** all six counted diff rounds on the guard surface (2 / 2 / 1 / 1 / 1 findings through

**Judgment:** every finding was correct. Not one was refuted, and that is the honest headline —
this was not a reviewer relitigating a fenced decision, it was a guard that genuinely did not pin
what it claimed, four times over.

Rounds 1-2 were structural and worth their cost. The census had silently lost 31 of 51 members
(a Shape-G call carries no route text, so adopting REMOVED a site from its own census), and the
member rules were count-free on a rationale — "recognizing the adopted shape is self-evidencing" —
that a probe refuted in one edit. Those are design defects, found by exactly the mechanism reviews
exist for.

**Rounds 3-5 are the arc's own same-axis recurrence, and the AGENTS.md rule applies to me.**
Each landed one comment-or-activation corner: whole-line comments (round 3, via CI rather than the
reviewer), split activations (round 4), inline comments beside live code (round 5). Three
consecutive rounds each widening the same recognizer by one input family is precisely the shape the
repair-direction rule names, and I was the one widening it.

What broke the pattern was changing the KIND of repair rather than adding a fourth corner. Round
5's fix is not "handle inline comments too"; it is a statement of what each scan is asking —
"does this NAVIGATE / has this ADOPTED" is about CODE and reads the STRIPPED line, "does it declare
an EXEMPTION" is about a COMMENT and reads the RAW line. That subsumes every comment spelling at
once, including ones nobody probed, and it is smaller than what it replaced. Had I reached for it
at round 3 instead of `startsWith("//")`, rounds 4 and 5 would not have existed.

**Round 6 is a different vector, and it is the one worth naming.** It found the mutation ledger
stale at HEAD: a siteId is `operator:LINE:column:from>to`, so my own previous commit relocated the
accepted id and the gate would report a stale-ledger-row for an id no generated site has. That is
the SECOND time the same shape landed — round 2's finding was the same ledger disagreeing a
different way — and it is the same class as the exemption inventory I had already repaired earlier
in the arc by re-pinning it on FILE + CLASS instead of `file:line`. Line-keyed pins churn under
edits to the file they describe. The siteId format is the harness's, so the repair here is not a
re-key but a stated discipline recorded beside the rows: the ledger is a measurement OF A REVISION,
re-run in the same commit as any source change.

**Mechanizable:** two, and both were already available.

- **The single-source comment rule is enforced, and I broke it anyway.**
  `tests/cross-cutting/_metaStripCommentsSingleSource.test.ts` exists to stop exactly the
  hand-rolled `startsWith("//")` that caused rounds 3 and 5. It caught me — but in CI, on
  `unit-suite-db` shard 3, after the local suites I ran were green. The rule is mechanized; my
  pre-push verification was the gap. Tracked by `BL-PLANLINT-RECONCILIATION-AND-MARKER-CITATIONS`
  only by analogy, so filed properly here: the mechanizable step is running the shard that owns a
  guard you are editing, not the suites you happen to remember.
- **The mutation ledger contradiction was mechanically detectable and was not detected**, because
  the gate that compares `EXPECTED_LEDGER_KINDS` against the registry's `accepted[]` is
  mutation-project-only and its harness never completed here. The reviewer found it by static
  probe in seconds. A default-project assertion of that same equality would have caught it at
  authoring time; the gate does not need to RUN the mutants to check that two declarations agree.

**Infra:** the heavy semaphore dominated this arc's wall clock more than review did. Two slots
against eight concurrent arcs; the full `mutation:guards` harness is 138-300 minutes; a run scoped
to this one surface waited ~2h for a slot and then held one for 2h05m without finishing, and was
killed when a merge changed the registry files it was reading. The score was obtained instead by
applying the harness's OWN operators directly — 57-62 mutants, one scoped suite run each, a few
minutes — which is what should have been done first. Separately, round 3 was lost to an
account-wide Codex usage limit (`no_verdict` / `attempts_exhausted`), which is recorded in the
corpus as honest evidence of the outage and correctly does not count toward this threshold.
