# Review-round economy — `test/modal-wait-helper-adoption` @ `119895a7c756`

## spec — 4 rounds

**Examined:** all four spec rounds (2 / 2 / 2 findings, BLOCKING at R1–R3; R4's verdict
recorded in the sibling `.jsonl`), their briefs, and the repair commits `904954e15`,
`cea13d308`, `2b1ff1f9b`, `829ec89f6`.

**Judgment:** every one of the six findings was a real design gap, and five of the six could
only have been found by reading the corpus against the mechanism — not by any sweep the
authoring rules already mandate. That makes this arc's round count mostly irreducible, with one
sharp exception recorded under **Mechanizable** below.

The six, by what they cost:

- **R1-1 / R2-1 / R3-1 are one vector — census completeness — seen three times.** Each round
  found a different way for a test to reach `/admin?show=` that the previous derivation could
  not see: a FILE-keyed census hiding nine sites inside four specs (R1), a `page.reload()` that
  writes no URL for any URL-keyed grep to match (R2), and two sites whose skeleton-tolerant
  wait means the helper would return on the skeleton and hide the fault rather than surface it
  (R3). Three rounds on one vector is exactly the trigger AGENTS.md defines, and the response
  was the mandated one: comprehensive re-analysis plus a structural defense in the third
  repair, not a fourth patch. The re-analysis went at the census from the PRODUCT side —
  enumerate every surface whose href or `openHref` targets the route (eight, across six
  components), then ask which any spec touches — and it added **zero** members. That null
  result is the useful one: the earlier derivation happened to be complete, but nothing about
  it said so, and a reviewer had been the only thing standing between the table and the tree.
- **R2-2 and R3-1 were both mechanism findings a probe settles and prose cannot.** Playwright's
  `isVisible`/`waitFor` are strict, so a multi-match ready selector throws an exit naming
  neither the boundary nor the server signature; and the Suspense skeleton renders through the
  same shell with the same `testIdBase`, so it WINS a modal-or-boundary race. Both were
  confirmed from source in minutes once named. Neither was reachable from the spec text alone.
- **R1-2 is the one finding with real leverage.** The guard's file-level import predicate would
  have shipped a false-negative machine: one adopted site silences every other site in the same
  file. It was refuted with a live escape (`published-review-modal.interactions.spec.ts` adopts
  at 103, its naked 389 goes quiet) and the repair changed the design rather than the
  predicate — adding a URL-taking entry point so no spec writes the navigation at all, which
  lets the guard be a flat per-site ban instead of a heuristic.

**Mechanizable:** one, and it is the census unit rather than any individual miss.

The arc spent three rounds discovering that a hand-maintained table of open sites drifts from
the tree, which is the same defect shape the class-sweep rule already names ("sweep to a
derivation, not a longer list"). The first draft's derivation WAS two greps, and each round
added one more grep. What closed it was not a fifth grep but making the enumeration executable:
AC-2b now has the guard's predicate module export the candidate set and the meta-test assert
the spec's tables against it. Authoring that at draft time — a derivation that runs, rather
than a table a reviewer audits — would have collapsed R1-1, R2-1 and R3-1 into a single round.
The generalizable rule: when a spec's central artifact is an enumeration OVER THE TREE, the
enumeration belongs in code from the first draft, and the prose table is its rendering.

Counter-note against over-learning this: the R3 exclusions (the two skeleton-tolerant sites)
would NOT have been caught by an executable enumeration. They are members by every mechanical
test and are excluded on a semantic judgment about what those two tests assert. No derivation
finds those; a reviewer did.
