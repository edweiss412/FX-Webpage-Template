# Review-round economy — `chore/heavy-orphan-reaper` @ `994b21dd4f64`

## spec — 10 rounds

**Examined:** all ten spec rounds (5 / 6 / 3 / 2 / 1 / 1 / 1 / 1 / 2 / 0 findings; BLOCKING ×3,
NEEDS-ATTENTION ×5, BLOCKING, APPROVE), their briefs, and every repair commit from `a44ce9cf8`
through `7976d1a19`.

**Mechanizable: twelve of the twenty-two findings are ONE class** — a normative claim restated in
prose contradicting the table it summarizes — and it appeared in nine of the ten rounds (R1 F1/F4,
R2 F2/F5, R3 F1/F2, R4 F1/F2, R5, R6, R7, R8, R9 P1). Nothing about the subject made it hard. The
document stated each behavior twice and the copies drifted at every repair.

**Rounds 4 through 8 each returned exactly one instance, and each was in a region the previous
repair's sweep could not see.** In order: §4.4's own preamble; a verb set built only from
paraphrases already known; the inside of fenced code blocks; a single-line JSDoc that a hand-audit
had waved through as a type description; and the rows of a DIFFERENT table, because the sweep
assumed table rows are sources when only §4.4's three are. Each repair was correct, and each was
followed by another instance — the signature of a recognizer widened one input family at a time,
which is exactly the shape `AGENTS.md`'s repair-direction rule says to stop widening.

**What stopped it was narrowing plus publication, not another sweep.**

- Round 3 assigned every §4.4 condition an ID (C1-C8, R1-R5, K1-K5) and made §6.2 and §8 cite them.
- Round 7 eliminated the surface rather than re-scanning it: no multi-line prose comment survives in
  §5, and every field comment cites a row ID instead of describing one.
- Round 9 put the scan COMMAND into the spec alongside the five categories a hit is permitted to be
  (citation, pointer, term definition, historical note, section-owned claim). That converted an open
  hunt into a bounded adjudication, and round 10 ran it, classified all 13 hits, and APPROVE'd with
  zero findings.

**The scan should have been written and published in round 1.** It is ten lines. It is the only
artifact in the arc that made the class closable rather than merely smaller, and every round from 4
to 8 was spent re-deriving by hand what it does mechanically. The rule for the next spec of this
shape: (a) assign row IDs in the first draft, (b) state that only those tables are sources, and
(c) ship the scan that checks it. Doing (a) alone still cost five rounds, because a rule that is
practised but not published gets re-derived by every reader, including its author.

**Second mechanizable class, 1 finding:** R3's BLOCKING F1 was a claim contradicted by this
document's OWN quoted probe — the identity check required `etime` unchanged, while §1.3's P4 probe
in the same file shows `etime` advancing `00:27 → 00:51`. The self-consistency sweep at
`docs/agents/spec-self-review.md:18` compares claims against other claims; extending it to "claims
against the probe outputs this document itself quotes" would have caught it at draft time for the
cost of one pass.

**Judgment:** four findings were irreducible design gaps, and they justify the whole review.

- **R1 F2** — the design did not bound what it claimed to. Its only automatic trigger was a `Stop`
  hook, and a session that CRASHES runs no `Stop` hook of its own. The repair added a pre-admission
  trigger in `package.json`'s `heavy` script and restated the bound honestly as "ceiling plus the
  interval to the next trigger" (L-2).
- **R1 F3** — the `classify` signature could not express the reporting §4.4 promised, in seven
  enumerated ways.
- **R2 F1** — the worker recognizer matched on containment, so `tail -f …/forks.js` was reapable.
  Refuted by probe rather than argument: over 679 live rows containment matched 14, one of which was
  a `zsh -c` wrapper that merely mentions the path.
- **R9 P0, the sharpest of the arc** — K2's identity check is not atomic with the signal, so a pid
  recycled between the final read and the `kill` reaches an unrelated process silently, while L-8
  claimed that residue was observable. No sweep or checklist finds that; it needed a reviewer
  reasoning about syscall ordering. L-8 now states the exposure plainly and §9's consequence bound
  is scoped to processes the reaper actually classified.

Note what the four have in common: each changed the deliverable, and three of the four landed in
rounds 1-2. The tail of this review was not design work.

**Infra:** the reviewer's sandbox denied `ps` (`zsh:1: operation not permitted: ps`) and had no
network for the whole arc. Round 1 therefore could not verify the six nightly durations §4.3 derives
its ceiling from; supplying the raw `gh run list` output inline in the round-2 brief closed that
permanently, and it is worth doing from round 1 on any spec whose numbers come from a network-bound
command. One dispatch was killed by this session and re-issued after a `spec:lint` failure (two
em-dashes) that a pre-commit lint would have caught; it left no corpus row. Every other dispatch
returned a verdict on the first attempt: no `no_verdict`, no reap, no retry.
