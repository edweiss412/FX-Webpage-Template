# Review-round economy — `chore/heavy-orphan-reaper` @ `994b21dd4f64`

Two stages, 38 rounds, 62 findings. Both stages ratcheted, in the same shape and for the same
reason, and both were ended by a stated bound rather than by another round. The numbers below are
read off the corpus in this directory, not retyped from memory.

## spec — 22 rounds

**Examined:** all 22 spec rounds (5 / 6 / 3 / 2 / 1 / 1 / 1 / 1 / 2 / 0 / 1 / 1 / 2 / 0 / 1 / 1 / 0
/ 2 / 2 / 0 / 3 / 0 findings; BLOCKING ×4, NEEDS-ATTENTION ×13, APPROVE ×5), their briefs, and every
repair commit from `a44ce9cf8` through `74f2aa79b`.

**Mechanizable — the dominant class, 12 of 37 spec findings:** a normative claim restated in prose
contradicting the table it summarizes. It appeared in nine of the first ten rounds, and rounds 4
through 8 each returned EXACTLY ONE instance, each in a region the previous repair's sweep could not
see: §4.4's own preamble; a verb set built only from paraphrases already known; the inside of fenced
code blocks; a single-line JSDoc a hand-audit had waved through; and the rows of a DIFFERENT table,
because the sweep assumed table rows are sources when only §4.4's three are.

What closed it was narrowing plus PUBLICATION, not another sweep: row IDs in round 3, elimination of
§5's prose comments in round 7, and — the one that actually worked — **shipping the scan command
inside the spec** in round 9, together with the five categories a hit is permitted to be. Round 10
ran it, classified all hits, and APPROVE'd. **That scan is ten lines and should have been written in
round 1.** Rounds 4-8 were spent re-deriving by hand what it does mechanically.

**Second mechanizable class, 6 findings:** an enumeration updated in one place and not the others.
Adding R5 in round 20's delta left the scan's row regex at `R[1-4]`, §4.4's identity paragraph on the
old capture model, and §5's `UnparsableRow` comment excluding the case R1 had just been given —
found across rounds 18, 19 and 21. A spec that carries a row inventory needs the inventory derived,
or every addition costs a round.

**The re-opening pattern is its own finding, and it is mine.** The spec APPROVED at rounds 10, 14,
17 and 20 and I changed it after each one, four times, always because a PLAN-review finding forced a
correction. That is not waste — three of those corrections were real design defects, below — but it
means "spec APPROVED" was never a terminal state until the plan stopped moving. **A spec whose plan
has not been written is provisional, and pretending otherwise cost four re-review cycles.**

**Judgment — the findings that justify the whole review, all four in rounds 1-2 or forced by
implementation:**

- **R1 F2** — the design did not bound what it claimed to. Its only automatic trigger was a `Stop`
  hook, and a session that CRASHES runs no `Stop` hook of its own. Produced the pre-admission
  trigger and the honest bound in L-2.
- **R1 F3** — the `classify` signature could not express the reporting §4.4 promised, in seven
  enumerated ways.
- **R2 F1** — the worker recognizer matched on containment, so `tail -f …/forks.js` was reapable.
  Refuted by probe: over 679 live rows containment matched 14, one a `zsh -c` wrapper that merely
  mentions the path.
- **R9 P0** — K2's identity check is not atomic with the signal, and L-8 claimed the residue was
  observable when it is silent. No checklist finds that; it needed a reviewer reasoning about
  syscall ordering.

**Two more design defects came from EXECUTION rather than review**, and are the strongest argument in
this filing for running a plan's code at plan time: clause (c), the slot-membership exemption every
draft through round 10 called "what makes this safe", was **unreachable** — found by running the
classifier the plan specifies, whose clause-(c) case failed. And the classification-time identity was
captured after classification, binding K2 to neither the process classified nor the one signalled —
found the same way.

**Infra:** the reviewer's `ps` was sandbox-denied and its network unavailable for the entire arc, so
round 1 could not verify the six nightly durations §4.3 derives its ceiling from. Pasting the raw
`gh run list` output into round 2's brief closed that permanently and is worth doing from round 1 on
any spec whose numbers come from a network-bound command. One dispatch was killed and re-issued after
a `spec:lint` failure a pre-commit lint would have caught; one was killed by this session at the
convergence directive. Neither left a corpus row. Every other dispatch returned a verdict on the
first attempt.

## plan — 16 rounds

**Examined:** all 16 plan rounds (6 / 4 / 6 / 6 / 4 / 2 / 3 / 1 / 1 / 0 / 1 / 1 / 2 / 1 / 2 / 1
findings; BLOCKING ×14, APPROVE at round 10, NEEDS-ATTENTION at round 16), their briefs, and every
repair commit from `ff09cdc69` through `e5f14c772`.

**Judgment — rounds 1-9 were worth every dispatch.** They found defects no checklist reaches:

- **R3 F1**, the sharpest of the arc — the end-to-end kill cases fed `main()` fixed pids 4242-4244
  while `main()` calls the REAL `process.kill`, so a suite run could have SIGKILLed whatever owned
  them. Repairing it honestly (tests spawn their own orphans) surfaced two further real defects: a
  SIGKILLed direct child becomes a zombie that `kill(pid, 0)` reports alive, and SIGKILL is
  asynchronous — so K4's re-scan was reporting `partial` for targets it had just killed.
- **R1 F1** — the mutation control was tautological: the suite imported `DEFAULT_MIN_AGE_SECONDS` for
  its own boundary values, so it ADAPTED to the mutant and both the control and the `+1` integer
  mutant would have survived Task 5's required empty survivor set.
- **R7 F1** — the `red-target=` markers EXPIRED at execution time. A path-only target is legal only
  while its path is untracked, so every marker was valid at plan time and invalid the moment its task
  committed the file it named.
- **R4 F2**, **R9**, **R14** — three separate cases where the CLI's behavior was decided by the wrong
  read, or a parse fell back to a shifted offset, each caught by running the code.

**Mechanizable — the ratchet, and why it ended the arc.** Rounds 11 through 16 returned 8 findings,
**every one on a single axis: a case that named a §6.2/AC-6 reporting guarantee it could not
observe.** The repair each round was WIDENING — more cases, more fixture modes, more decline kinds —
and the suite went from roughly 40 cases to 87 while **not one of those six rounds found a behavior
that was actually wrong.** The finding rate stayed flat (1, 1, 2, 1, 2, 1). That is precisely the
shape `AGENTS.md`'s round-economy block measures, and its prescribed repair is narrowing.

**The arc was ended by a stated bound rather than round 17.** Spec §1.2 now carries the consequence
bound (the worst case of an unclassifiable input is a conservative no-kill plus a surfaced signal;
a wrongly-killed live phase is the only outcome treated as a defect), the probe domain (this
machine's process table, `package.json`'s `heavy` script, `scripts/with-heavy-slot.py`,
`tests/mutation/**`), and the threat fence (ordinary orphaning; adversarial process manipulation is
out). The reporting-observability axis is fenced as L-9 and filed as
`BL-HEAVY-REAP-REPORT-OBSERVABILITY`, whose first scheduled step is a MUTATION RUN over the
reporter rather than more cases — a closed operator set that terminates, in place of an enumeration
that does not.

**Mechanizable, second class, 2 findings — my own repairs that silently did nothing.** Rounds 8 and
12 each re-raised a finding whose claimed repair was absent, because an unasserted `str.replace`
found no anchor and the working file was deleted before anyone compared it to the document. Both
were my error and both are covered by a rule already in my own notes. Every replacement in this arc
now asserts its anchor, and the outcome is verified in the DOCUMENT.

**Infra:** the reviewer's `ps` was denied throughout, which cost nothing once every probe output was
quoted inline. One dispatch (round 17) was killed at the convergence directive and left no corpus
row.

### What this arc should change for the next one

1. **Run the plan's code at plan time, before the first dispatch.** It found two spec-level design
   defects and several plan defects that 38 review rounds' worth of reading did not.
2. **A spec is provisional until its plan is written.** Four post-APPROVE re-openings, every one
   forced by a plan finding.
3. **If the normative content lives in tables, ship the scan in round 1.** Ten lines against five
   rounds.
4. **When a review stage returns the same axis three rounds running with no behavior defect, fence
   it.** Here that recognition arrived at round 16 and could have arrived at round 13.
