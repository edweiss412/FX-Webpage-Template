## Decisions this plan makes

Each is the plan's reading of the spec where the spec leaves a choice; none amends it.

1. **Entitlement and membership are two predicates.** Spec §5.2's refresh row (line 258) keeps a sheet open on a section that left membership, but closes it when the viewer lost the entitlement to see it. So lib/crew/crewSections.ts gains `crewSectionEntitled(id, data, viewer)` beside `crewSectionsFor`: `billing` is entitled iff `financialsVisible` (`lib/visibility/scopeTiles.ts:140`); `transport` iff the viewer is an admin, `transportTileVisible` (`lib/visibility/scopeTiles.ts:180`) holds, or the viewer has their own flight; `agenda` iff the viewer's dates are not suppressed; every other id always. Membership is entitlement plus one content rule (spec line 240): `agenda` is listed only when the viewer has an agenda link with a file. So `agenda` is the one id that can be entitled and unlisted. `transport` is not: a viewer who loses both the gate and their flight has nothing the section may show them, and an empty state there would claim no transport exists when it is only withheld, so that sheet closes to home like a lost entitlement. `resolveActiveSection` resolves `s` against entitlement (spec line 242: "non-entitled id resolves to home"), and the shell builds a body for every member plus the open section when it is entitled but not a member, so the controller's existing rule (a body keeps the sheet open, no body closes it, `components/crew/CrewSections.tsx:330-335`) needs no change. The wide stack renders every body the shell built, in nav order; the nav and the list show members only.
2. **Nav order is registry order, with `gear` in the Gear group's slot:** `venue`, `crew`, `contacts`, `schedule`, `agenda`, `hotels`, `transport`, `gear`, `billing`, with no group headings until PR C (spec line 239). Labels for moved ids are the registry's; `schedule` keeps "Schedule" and `gear` keeps "Gear" until PR C's AC-10.
3. **Icons for moved ids are the registry's** (the same Lucide glyph the admin rail shows), read by the nav, the list, the sheet and the crew panel card's chip; `today`, `schedule` and `gear` keep their crew glyphs (`components/crew/sectionIcon.ts:20`) until PR C.
4. **Panel card titles are the registry label** of the section (the admin card's label, spec line 290): "Show crew" becomes "Crew", "Key contacts" becomes "Contacts", "Getting there" becomes "Transport" (spec line 403), "Budget" becomes "Billing & docs" (spec line 405), "Where" becomes "Venue" (spec line 402). Crew-only blocks below or above a shared body (Venue's Facilities and Status, Transport's "Your flight") keep their own cards and titles.
5. **Card ids do not change** (spec line 328): `budget-main`, `venue-where`, `venue-facilities`, `venue-status`, `crew-roster`, `crew-contacts`, `travel-flight`, `travel-getting-there`, `travel-hotels` keep their `CARD_REGION_MAP` rows (`lib/sheet-links/buildSheetDeepLink.ts:177`). A card id is stored in a report's `fieldRef` (`components/shared/CardReportTrigger.tsx`), so renaming one would split a card's report history.
6. **Render-fault tile ids are kept where a successor exists.** The sweep resolves an alert only for a tile id that rendered clean this request (`lib/crew/sweepTileRenderAlerts.ts:80-84`), so a renamed id would leave its open alerts unresolvable forever. `crew:budget:rows` moves with the Billing body, `crew:travel:transport` with the Transport body, `crew:crew:roster` stays on Crew; Hotels, Contacts and Agenda get new ids (`crew:hotels:list`, `crew:contacts:list`, `crew:agenda:schedule`).
7. **Old links are canonicalized at the allow-list.** One function, `canonicalSectionParam(raw)` in `lib/crew/resolveActiveSection.ts`, maps an alias to its id and drops an unknown value; every redirect allow-list calls it, so a redirect carries the current id (spec line 242, "applied everywhere `s` is resolved"). `gate` is untouched by it.
8. **Crew roster actions.** Spec line 303 gives the crew roster "call and text actions" under the `digitsOnly` gate; today's crew row has Call and Email (`components/crew/primitives/PersonRow.tsx`). PR B renders Call and Text under the `digitsOnly` gate and keeps Email under its sentinel gate, so no crew action is lost and the spec's Text is added. The Text action uses the drawn icon the home's "Who to call" Text button uses (`components/crew/CrewQuickFacts.tsx:300`).

## Shared body contract

Binding for Tasks 4 to 10. Spec §6.1 is the source; this is how each task applies it.

- **Field inventory first.** Before writing a body, the task lists the union of fields the admin body renders and the crew card renders today (the crew side read from its row helper, e.g. `gettingThereRows` at `components/crew/sections/travelRows.ts:319`), in the commit body. Every field in the union is a body feature behind a prop. Admin props reproduce the admin markup byte for byte (Task 1's golden); crew props reproduce exactly the crew field set (spec §6.2: "each surface keeps exactly the fields it shows today").
- **Hooks stay with the admin.** A body is a hook-free function of its props. Where an admin body calls a hook today (`useState` and `useEffect` in `CrewBreakdown`, `components/admin/wizard/step3ReviewSections.tsx:1752`; `useId` twice in `HotelCard`, `components/admin/wizard/step3ReviewSections.tsx:2971`; `useContext` in `HotelsBreakdown`, `components/admin/wizard/step3ReviewSections.tsx:2846`), the admin keeps a component of the same name and tree position that calls the hook and passes the value in as a prop or slot, so `useId` values and effect behavior are unchanged.
- **Admin names stay exported.** `VenueBreakdown`, `ContactsBreakdown`, `TransportBreakdown`, `OpsBreakdown`, `CrewBreakdown`, `HotelsBreakdown`, `CrewUnderRowStack`, `contactBlocks`, `FieldRowList`, `CREW_CAP` and `HOTELS_CAP` remain exported from `components/admin/wizard/step3ReviewSections.tsx` (wrappers or re-exports), so every admin suite that imports them stays unmodified, and `tests/components/admin/review/sectionFreshnessCss.test.ts` (which requires the caps to come from that file) stays green. Caps are props; the constants do not move.
- **Search markers are props.** A body takes an optional per-line target map and emits `data-search-target`, `data-search-skip` and `data-search-group` only from it; the admin passes none, so its DOM gains no attribute. The crew index builder for that section derives its ids from the same row helper the crew props come from, and `tests/search/indexRenderParity.test.tsx` proves index equals render for the section's id.
- **Test ids.** Prefixed ids use `testIdPrefix` (admin `wizard-step3-card-${dfid}-breakdown`, crew `crew-panel`). An id the admin body emits unprefixed (for example `venue-dock`, `hotel-stay-check-in`) stays unprefixed on both surfaces; crew specs select inside the section root `section-<id>`. Each crew test id a move retires is found by PR A's retirement rule (`rg -o 'data-testid="[^"]+"' <old file>`, then `rg` over `tests`) and every hit migrates in the same commit.
- **Crew-side wiring.** The crew section file calls the body as a function inside its `WrappedSection` callback (`components/crew/WrappedSection.tsx:86-110`), wraps it in the crew panel card with the card's existing `cardId` and header actions, and computes every gated input on the server before the call. The panel card carries `data-card-id` on its root, because the search parity harness takes a line's region from the nearest `data-card-id`.

## Admin DOM invariant: how it is proven

Spec line 505 forbids any change to the admin popup's rendered DOM. The PNGs under `tests/e2e/section-header-visual.spec.ts-snapshots/` cover the section header row only (the harness builds its pages from rendered header markup, `tests/e2e/section-header-visual.spec.ts:109-135`), so they cannot see a body. Four layers, each run before and after every admin-touching task (Tasks 2, 4 to 10):

1. **Golden DOM (Task 1).** tests/components/admin/wizard/adminSectionDom.test.tsx (new) renders the seven sections through `ShowReviewSurface` (`components/admin/review/ShowReviewSurface.tsx:1120`, the chrome provider) for a staged fixture (`buildStagedSectionData`, `components/admin/review/sectionData.ts:117`) and a published one (`buildPublishedSurfaceProps`, `tests/helpers/publishedSurfaceProps.tsx:267`), and each registry `render(d)` bare (the no-chrome `BreakdownSection` branch), and compares each section subtree's `outerHTML` with a committed file in a new `__golden__` directory beside the test. The goldens are written once, in Task 1, on the unmodified tree. From Task 1's commit on, `git diff --exit-code <task-1-sha> -- tests/components/admin/wizard/__golden__/` must pass at every commit; a golden diff is a defect, never a re-baseline.
2. **Admin rendered-output suites stay unmodified.** The suites that import the moved admin bodies (sweep D4 below) and assert rendered output are run in each task and may not be edited: the same `git diff --exit-code` over the D4 files that are not in the source-pinned set.
3. **The section-header PNGs.** `git diff --exit-code origin/main -- tests/e2e/section-header-visual.spec.ts-snapshots/` at every commit. The comparison itself runs only in CI, in the pinned image, on every PR (`.github/workflows/section-header-visual.yml:26-27`).
4. **Admin layout specs.** The standalone specs that render a moved body (`hotel-stay-stub.layout`, `published-review-modal.layout`, `step3-review-modal.agenda`, `attention-anchor-placement`, `section-header-reconcile.layout`, `warning-card-layout`, `warning-card-flows`, through `tests/e2e/standalone.config.ts:86`) and `control-outline-dimensions.layout` (mobile-safari, `playwright.config.ts:84`) run in the gate of the task that moves the body they render. Each harness that builds its CSS from an `@source` list naming `step3ReviewSections.tsx` or `components/admin` gains `components/show-panels` in the task that moves the first class out (sweep D5), or its harness CSS would silently drop the moved classes.

## E2E harness rules

Carried from PR A (`docs/superpowers/plans/2026-10-26-crew-page-redesign-pr-a.md`, "E2E harness readiness"), unchanged unless stated:

- **Production build.** Local Playwright runs use the server CI uses: `CI=1` on the command selects `pnpm build && pnpm start` (`playwright.config.ts:290`), and `--retries=0` keeps a flaky retry from exiting 0 over a real regression. Dev-mode rendering hid a defect PR A's production runs found.
- **Readiness gate:** await `data-crew-controller-ready="true"` before the first assertion; never `networkidle` alone.
- **Viewer per case:** a crew identity goes through the admin preview route (`app/admin/show/[slug]/preview/[crewId]/page.tsx`); a plain admin through the share route.
- **Clock:** server `today` pinned with the authenticated frozen-time headers and the browser clock pinned to the same instant before hydration.
- **WebKit animations:** an installed page clock stalls framer `AnimatePresence` under mobile-safari; cases that drive an animation use `page.clock.setFixedTime`.
- **New: sample a CSS animation only by seeking it.** On CI's Linux WebKit a composited CSS keyframe animation reports its first keyframe to `getComputedStyle` until it ends, so a live sample passes on macOS WebKit and fails on CI (`docs/review-rounds/feat/crew-page-redesign/d8d1ab3904ba.md:11`). Any e2e that samples an animation reads `element.getAnimations()`, pauses each, sets `currentTime`, samples, then calls `play()`, as PR A's copy-toast case does after commit `337bea7d3`.
- **Shared DB.** Specs share the local `dev.*` state; a task that changes what the seed produces, or runs a spec that mutates seeded rows, reseeds with `pnpm db:seed` before its gate run, and per-test shows come from `tests/e2e/helpers/seedShowWithCrew.ts`.
- **Crew e2e oracle:** a task that adds, removes, retitles or skips a case in a spec on the `crew-e2e.yml` run line (`.github/workflows/crew-e2e.yml:219`) updates `scripts/check-crew-e2e-executed.mjs` counts from the observed run and the titles pinned by `tests/cross-cutting/picker-flow-e2e-ci-wiring.test.ts`, in the same commit. PR B adds no spec file.
- **Projects:** compact cases in `tests/e2e/crew-section-toggle.spec.ts` and `tests/e2e/crew-page.spec.ts` (mobile-safari, `playwright.config.ts:84`), wide cases in `tests/e2e/crew-wide-nav.spec.ts` (desktop-chromium, `playwright.config.ts:98`); every command passes both projects.
- **Filter words:** every case a task adds carries that task's `-g` word in its title.
- **Client props and payloads:** every crew panel's props are built on the server from already-gated data; a task that moves a section serializes the props its crew body receives and searches them for what each viewer is withheld (dates for a suppressed viewer, transport fields for a viewer the transport gate excludes, financial values for a viewer `financialsVisible` excludes).
- **Heavy phases:** every non-interactive Playwright command and every full or directory-wide Vitest run goes through `pnpm heavy`.
- **CI-only workflows.** `lifecycle-layout-e2e`, `standalone-e2e`, `screenshots-drift` and `section-header-visual` run on a branch only once its PR opens, and PR A's first CI run found defects no local gate saw (`docs/review-rounds/feat/crew-page-redesign/d8d1ab3904ba.md:11`).
