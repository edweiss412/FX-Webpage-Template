## T4 — post-CI: measure, decide, record (after the first COMPLETED real-CI run, before merge)

Scheduled after the run COMPLETES, whatever its outcome — the revert branch exists precisely for the not-green case, and gating on green would make it unreachable. The steps are ordered so that measurement happens BEFORE classification, because spec §7.4 requires the figures recorded either way.

1. **Measure first, unconditionally.** Run `legfix <PR run id>`, `legfix <baseline run id>`, and `legwall` on both (baseline chosen by spec §7.1's rule). Record in the PR body: both run IDs, both `jobs=`/`legs=` counts, both medians, and both **max legs** — max leg is TOTAL job wall clock from `legwall`, NOT the max fixed overhead `legfix` reports; the authority records 91s fixed overhead against a 245s max leg on the same run and requires the latter. Both functions are TOTAL over every outcome by construction (spec §7.1): a leg whose combined step failed has no vitest step, so its fixed overhead is `NA` rather than an error or a silent drop, and each function still prints a summary line on stdout before exiting. Read the exit status as three-way, not boolean — **0** a complete comparable measurement, **1** a real but PARTIAL run whose printed figures are real and go in the PR body labelled as partial, **2** `TRANSPORT-FAIL`, meaning the API could not be read and there is NO measurement. Only exit 0 on both runs can feed step 2's accept conjunction; exit 2 in particular must never be read as "zero legs", which is how a transient auth or rate-limit failure would otherwise fabricate a revert.
2. **Decide by a CLOSED CONJUNCTION, then by two exits. This structure replaces the branching decision tree that stood here through review rounds 4-10.**

   Six consecutive adversarial rounds landed on that tree, and each repair introduced the next round's defect: a branch gated on green made the revert unreachable; making it total re-opened an infinite re-run loop; closing that produced overlapping branches on multi-cause runs; per-cause classification made the revert non-sticky; the run-level completeness check that fixed no-failing-step outcomes re-opened the multi-cause hole. That is the shape this project's three-round rule names, and the response it prescribes is to remove the vector rather than patch it again.

   **Why the tree was the wrong instrument.** It tried to decide, from a run's job conclusions, questions that are not measurement questions at all: whether a regression belongs to this branch, whether a red context on `main` should block this merge, whether an infrastructure shape is worth another dispatch. Those are scope-and-authority calls, and this project's autonomy contract puts them with the user — autonomy covers execution, not the user's decisions. So the procedure decides only what the measurement actually determines, and stops everywhere else.

   - **ACCEPT** iff ALL THREE hold. A conjunction needs no enumeration of the ways it can fail:
     1. every REQUIRED job — the 8 `unit-suite-db` legs, the 3 `unit-suite-nodb` legs, the `unit-suite` aggregator — is present in the job list and concluded exactly `success`;
     2. the leg-median fixed overhead dropped by **≥8s** versus the baseline, from a `legfix` that exited 0 on BOTH runs (exit 2 is `TRANSPORT-FAIL` and is not a measurement; exit 1 is a partial run and is not the accept figure);
     3. the boot log is present in all 8 db legs — `gh run view <id> --log | grep -c 'Started supabase local development setup'` is exactly 8 (spec §7.1 criterion 1; the token was chosen by probing main run 30783618781, where it appears exactly 8 times).
   - **REVERT** iff condition 1 holds but 2 or 3 does not, OR the combined step itself failed in any db leg (`gh api .../jobs --jq '.jobs[] | select(.name|startswith("unit-suite-db")) | {job: .name, step: (.steps[] | select(.name|startswith("Boot local Supabase")) | {name, conclusion})}'`). These are the only two shapes the measurement itself settles: the change did not earn its place, or the change is what broke. Go to step 4. **The revert is STICKY and TERMINAL for item 1** — afterwards the accept path is closed for the rest of the branch, no re-measure and no graduation, because there is no overlap left to measure and runner noise on a reverted tree could otherwise "clear" a threshold for a change that is gone.
