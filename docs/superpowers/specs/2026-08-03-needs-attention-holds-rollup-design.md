# Needs-attention holds rollup — design

**Date:** 2026-08-03. **Backlog:** `BACKLOG.md` § `BL-NEEDS-ATTENTION-HOLDS-ROLLUP` ("pending MI-11 holds do not surface on the needs-attention page"). **Origin deferral:** `docs/superpowers/specs/v1-pre-deployment-amendments/2026-06-10-mobile-needs-attention-design.md` §11.

Pending MI-11 identity holds (`sync_holds`, `kind='mi11_pending'`) are visible only inside the show they belong to (the per-show changes feed). The needs-attention rollup — the `/admin/needs-attention` page, the dashboard inbox, the AdminNav badge, and the digest email — does not know they exist. An unopened show can therefore sit on a held identity change indefinitely with zero cross-show signal. This spec adds the missing cross-show holds read and rolls open holds into all four surfaces.

## 1. Goals

- An open MI-11 hold surfaces as a card in the needs-attention item list (page + dashboard inbox), counts toward the AdminNav badge, and appears in the digest email, until it is approved or rejected.
- Approve/reject stay where they live today (the per-show changes feed inside the `?show=` modal); the rollup only announces and deep-links.
- No DB changes: no migrations, no new RPCs, no RLS edits, no new mutation surfaces.

## 3. Design decisions

| # | Decision | Rationale |
| --- | --- | --- |
<!-- spec-lint: ignore — the D1 row names the planned new file lib/admin/identityHolds.ts -->
| D1 | **New pure grouping core + one thin read per caller.** A pure `groupHoldRows` (in the new `lib/admin/identityHolds.ts`) turns flat hold+show rows into per-show groups; `loadOpenIdentityHolds` (same file) is the PostgREST reader used by `loadNeedsAttention` and `loadNeedsAttentionCount`; the digest reuses `groupHoldRows` over rows from its own `sql` query. | One grouping/copy semantics for all four surfaces; the reader stays swappable per client type (PostgREST vs raw SQL) without forking the semantics. |
| D2 | **The holds read is a full bounded read, not rows+head-count.** Read up to `HOLDS_ROW_CAP = 200` rows ordered `created_at desc`; the stream total = number of distinct show groups in the read. No separate head-count probe. | The stream total must count SHOWS (R7); PostgREST cannot head-count a distinct column. The table is structurally small — unique `(show_id, domain, entity_key)` bounds rows to crew-size × shows at FXAV scale (tens). §10 documents the cap-overflow limit. |
| D3 | **`loadNeedsAttention` and `loadNeedsAttentionCount` construct a service-role client for the holds leg only**; the existing cookie-client legs are untouched. Client construction failure or any holds-leg fault follows each helper's existing infra posture (§8). | R5. Precedent for a server-only admin read on service-role: `readShowChangeFeed` (`lib/sync/feed/readShowChangeFeed.ts:37`). Both helpers already run strictly server-side behind admin gating. |
| D4 | **Builder input is pre-grouped.** `buildNeedsAttention` gains optional `identityHolds: NeedsAttentionIdentityHoldInput[]` + `totalCounts.identityHolds`; both default to `[]`/`0` so existing callers (including the digest before its Phase-3 change and the `needsAttention` unit fixtures) are byte-identical. | Mirrors the `syncProblems` optionality contract (`lib/admin/needsAttention.ts:67-70`). Grouping in the builder would force the digest's raw-SQL rows through a PostgREST-shaped interface. |
| D5 | **Card `sortKey` = the group's newest `created_at`, raw string.** | Same convention as every other stream (raw ISO-ish timestamptz strings compared with `localeCompare`, `lib/admin/needsAttention.ts:271-275`); a show's card floats to where its most recent hold landed. |
| D6 | **Disclosure is client-side expand/collapse of already-loaded summaries — no lazy fetch.** The loader always carries every group's per-hold summaries (bounded by D2's row cap). | At ≤200 rows total there is nothing worth a second round-trip; keeps the inbox a pure render of `NeedsAttention`. |
| D7 | **No new instrumentation.** All new code paths are reads; the only mutation surfaces in the feature's orbit (`mi11_approve_hold` / `mi11_reject_hold` RPC callers) are untouched. | Invariant 10 applies to mutation surfaces; there are none here. Invariant 2 (advisory locks) likewise N/A — no writes to locked tables. |

## 4. Read path (`lib/admin/identityHolds.ts`, new)

```ts
export type HoldShowRow = HoldRow & { show_id: string; slug: string; title: string | null };
// HoldRow re-used from lib/sync/feed/shapeHoldEntry.ts:11-18

export type IdentityHoldGroup = {
  showId: string;
  slug: string;
  title: string | null;
  holdCount: number;             // = summaries.length
  summaries: string[];           // newest-first, each from shapeHoldEntry(row).summary
  newestCreatedAt: string;       // raw created_at of the group's newest hold
};

export const HOLDS_ROW_CAP = 200;

export function groupHoldRows(rows: HoldShowRow[]): IdentityHoldGroup[];
export async function loadOpenIdentityHolds(): Promise<
  { kind: "ok"; groups: IdentityHoldGroup[] } | { kind: "infra_error"; message: string }
>;
```

- **Query** (service-role client, `createSupabaseServiceRoleClient` at `lib/supabase/server.ts:79`):
  `from("sync_holds").select("id, show_id, entity_key, held_value, proposed_value, base_modified_time, created_at, shows!inner(slug, title)").eq("kind", "mi11_pending").eq("shows.archived", false).order("created_at", { ascending: false }).limit(HOLDS_ROW_CAP + 1)`.
  Every await destructures `{ data, error }`; returned-error and thrown-error both map to `{ kind: "infra_error" }` (invariant 9). Registry row in `tests/admin/_metaInfraContract.test.ts`.
- **Row guard.** A row whose `shows` embed is missing `slug` is skipped with a `log.warn` (mirrors the sync-problem embed guard, `lib/admin/loadNeedsAttention.ts:264-276`). A row whose `proposed_value` lacks a recognized `disposition` cannot exist under the shape CHECK (`20260608000000_sync_holds.sql:30-37`); defensively, `shapeHoldEntry`'s removal fallback arm (`shapeHoldEntry.ts:79-84`) already renders such a row, so no throw path exists.
- **Overflow.** If `rows.length > HOLDS_ROW_CAP`: `log.warn("sync_holds row cap exceeded", { source: "admin.loadOpenIdentityHolds" })`, drop the sentinel row, group what was read. Consequence documented in §10 — never an error, never silent (the warn is the signal).
- **Grouping (`groupHoldRows`, pure).** Group by `show_id` preserving the query's newest-first order: first row of a group supplies `slug`/`title`/`newestCreatedAt`; each row contributes `shapeHoldEntry(row).summary` in order. Groups therefore order newest-first by construction, and `summaries[0]` is the newest hold's summary. Empty input → `[]`.

```ts
export type NeedsAttentionIdentityHoldInput = IdentityHoldGroup; // structural re-export

```

- `BuildNeedsAttentionInput` gains `identityHolds?: NeedsAttentionIdentityHoldInput[]` and `totalCounts.identityHolds?: number` (defaults `[]` / `0` — D4).
- Merged entry: `sortKey = newestCreatedAt ?? ""`, `id = showId` (tie-break axis), one entry per group. Defensive skip (with nothing rendered, no log — pure function) for a group with `holdCount < 1` or empty `summaries`.

- Output `NeedsAttention` gains `identityHoldTotal: number` (mirrors `syncProblemTotal`, `lib/admin/needsAttention.ts:131`); `totalCount` adds the stream total (§6).

## 6. Count semantics (lockstep across surfaces)

Single definition: **the identity-holds stream total is the number of non-archived shows with at least one open `mi11_pending` hold** (R7).

| Surface | Source of the number |
| --- | --- |
| Page / dashboard `totalCount`, `overflowCount`, `identityHoldTotal` | `loadOpenIdentityHolds().groups.length`, threaded as `totalCounts.identityHolds` |
| AdminNav badge (`loadNeedsAttentionCount`) | Its own service-role read: `from("sync_holds").select("show_id, shows!inner(id)").eq("kind","mi11_pending").eq("shows.archived", false).limit(HOLDS_ROW_CAP + 1)` → `new Set(show_id).size`. Same filters as §4 (lockstep contract, mirroring the loader/count-helper lockstep note at `lib/admin/needsAttentionCount.ts:49-53`). Overflow: same warn-and-proceed posture as §4. |
| Digest | `groupHoldRows(sqlRows).length` (not surfaced as its own number; groups just join the item list) |

The badge helper does NOT reuse `loadOpenIdentityHolds` (it needs no summaries — shaping every hold's copy for a count would be waste), but its query filters MUST stay lockstep with §4; the test in §9 pins both query shapes.

## 7. UI: cards + disclosure (`components/admin/NeedsAttentionInbox.tsx`)

New `identity_hold` branch, modeled on the `sync_problem` card (`NeedsAttentionInbox.tsx:113-135`): bordered tile, `CardHeader` `status="warn"` `label="Held change"` (plural "Held changes" when `holdCount > 1`), title line `title ?? slug`, then:

- **Single hold (`holdCount === 1`).** Copy line = `summaries[0]`. Footer `Link` to `/admin?show={slug}` — text `Review →` (matches existing card link copy), `aria-label` `` `Review held change for ${title ?? slug} (${slug})` `` (slug discriminator per the WCAG 2.4.4 note at `NeedsAttentionInbox.tsx:123-125`). No expansion affordance.
- **Multiple (`holdCount > 1`).** Copy line = count line: `` `${holdCount} held changes waiting` ``. A toggle button (`aria-expanded`, `min-h-tap-min` tap target) expands the card in place; expanded content = the `summaries` list (each its own line, `text-sm text-text-subtle`) followed by the same footer `Link` (`Review →`, same `aria-label` shape). Collapsed state shows no summaries. The footer link is present in BOTH collapsed and expanded states — disclosure reveals detail, never gates navigation.
- **Cap on disclosure length.** A pathological group renders at most `HOLD_SUMMARIES_RENDER_CAP = 10` summaries followed by a literal line `` `and ${holdCount - 10} more` `` (bounded-list rule; unreachable at FXAV scale, cheap to pin).

**Guard conditions.** `title` null → `slug` renders (both lines above already state the fallback). `summaries` shorter than `holdCount` (impossible from `groupHoldRows`, which derives `holdCount` from `summaries.length`) → render what exists; never index past length. `activityAt` null → the relative timestamp is omitted (existing `CardHeader` behavior for null `activityAt`). Empty `slug` rows never reach the builder (§4 row guard).

**Mode boundaries.** The card has exactly two modes, gated on `holdCount`: single (no toggle, no summary list — the copy line IS the summary) and multi (toggle + count copy + collapsible list). Shared elements across both modes: tile frame, `CardHeader`, title line, footer link.

## 10. Documented limits

- **Row cap.** Beyond `HOLDS_ROW_CAP = 200` open hold rows (unreachable at FXAV scale — the unique constraint bounds rows to crew-count × show-count for two domains), the read truncates: groups derived from the newest 200 rows, older holds temporarily invisible in the ROLLUP ONLY (the per-show feed remains complete), `log.warn` emitted. Never silent, never corrupting.
- **Badge/page skew window.** The badge and page read at different instants; a hold approved between the two reads can skew the badge by one until the next badge refresh. Identical to the existing pending-streams skew; not new.
- **Digest timing.** A hold created and cleared entirely between two digest sends never appears in any digest. Intended (R2): the digest reports open holds at send time, not hold history.
