A source-scanning structural guard that fails-by-default when a NEW childless, unpainted, growable flex item lands anywhere under `components/` or `app/`. The five phantom-spacer sites repaired by PR #605 are covered by two layout oracles (`tests/e2e/pusher-alignment.layout.spec.ts`, `tests/e2e/section-header-layout.layout.spec.ts`) and the phantom-gap probe mounts; none of those instruments sees a SIXTH site written tomorrow. This guard closes that gap.

## 1. Problem and mandate

The prior attempt (spec §6 above) burned three adversarial rounds without converging: its prose rule selected 27 candidates while its prototype selected 17, because "childless" and "growable" hide real static-analysis ambiguity (conditional-`null` children, painted growables, `style={{flex}}`). The backlog entry mandates the revival order: **write the walker first, run it over the live tree, and let the actual output define the rule** — an allowlist of accepted shapes, not a leak hunt. That census has now been run twice (§2; the v2 rerun repaired a harvesting hole the R1 adversarial review found in v1), and this spec is written from its output.

Design principle, inlined for cross-CLI reviewers (this is the lesson that converged PR #592's new-tab guard after three rounds of the opposite approach): a static guard over TSX that tries to *prove an element is broken* is unsound by construction — spreads, computed values, and imported identifiers make the bypass space unbounded. The sound inversion is a **shape allowlist**: every growable candidate must match one of a small set of approved shapes; everything unresolvable fails closed with a message naming the approved shapes. The same inversion applies INSIDE each predicate: growability is "prove the grow factor is zero, else growable" (§3.1), and paint is an explicit token set, not a prefix family (§4.2). The false-positive cost (one exemption comment or one reviewed set/registry addition on a correct-but-unusual shape) is accepted explicitly; a false negative ships the exact bug class this guard exists to prevent.

## 3. The banned shape

A JSX element is a **violation** iff ALL of the following hold — in particular, a candidate matching ANY §4 shape is NOT a violation, so a painted DOM candidate is approved even when its growability comes from an opaque style value. The reason discriminant for elements that ARE violations, in order: component tag not registered → `unregistered-component`; growable SOLELY via an opaque style value (no growable className token) → `opaque-style-grow`; otherwise — including when an explicit growable class token coexists with an opaque style — → `unpainted-childless-dom`.

1. **Growable — "prove the grow factor is zero, else growable."** Growability is decided over the statically-harvested className tokens (harvesting rules below) plus the `style` attribute (style rules below).
   **Token grammar.** Normalize in this order: strip variant prefixes FIRST (everything up to the last colon character at zero bracket/paren depth, so `[&>*]:`, `min-[480px]:`, and `flex-(--x)` survive intact), THEN strip one leading or trailing important marker (the `!` character) — variant-first order is what makes the legacy form `sm:!flex-1` normalize to `flex-1` rather than escaping recognition. Then:
   - Layout/basis/shrink tokens are outside the family: `flex`, `flex-row`, `flex-col`, `flex-row-reverse`, `flex-col-reverse`, `flex-wrap`, `flex-nowrap`, `flex-wrap-reverse`, `basis-*`, `shrink`, `shrink-*` — never growable.
   - **Zero proof for the CSS `flex` shorthand is unitless-aware, and the numeric partition is TOTAL.** A `flex` shorthand's first segment proves grow 0 ONLY when it is a bare unitless number equal to 0 (`0`, `0.0`): CSS treats a one-value length/percentage (`0px`, `0%`, `10rem`) as flex-BASIS with implicit grow 1, so any unitful or non-numeric first segment is growable. Provably zero: `flex-none`, `flex-initial`, `flex-0`, `grow-0`, `grow-[v]` with v a bare unitless 0, and `flex-[v]`/`[flex:v…]` whose first `_`/space-separated segment is a bare unitless 0. **Negative values are provably NOT growable** on every surface (`grow-[-1]`, `flex-[-1]`, `[flex-grow:-1]`, `[flex:-1]`, negative style values): a negative flex-grow is an invalid CSS declaration, the rule is dropped, and grow stays at its initial 0.
   - Growable — everything else in the family: `grow`, `flex-auto`, `flex-<n>` for unitless numeric n > 0, fraction forms `flex-<a>/<b>` for ANY numerator including 0 (Tailwind emits `flex-0/1` as `flex: calc(0/1 * 100%)` — a one-value percentage basis with implicit grow 1), `grow-<n>` for n > 0, and fail-closed: custom-property forms `flex-(--x)`/`grow-(--x)`, arbitrary values whose decided segment is not a bare unitless number (`flex-[0px]`, `grow-[calc(1)]`, `flex-[var(--x)]`), and arbitrary properties `[flex-grow:v]`/`[flex:v…]` with unitful, unparseable, or positive v (e.g. `[flex-grow:junk]` is growable fail-closed).
   - **Style attribute — the resolution is TOTAL over TSX expression kinds.** Type-only wrappers are transparent and unwrapped: parentheses, `as` assertions, `satisfies`, and non-null (`!`) expressions (angle-bracket assertions are not valid TSX syntax and impose no scanner obligation). Conditionals and the logical operators `&&`/`||`/`??` resolve BOTH operands/branches (a branch that is `null`/`undefined`/a boolean guard contributes nothing). An object literal contributes growability if a `flex`/`flexGrow` property (identifier or string-literal key) has a value that is a positive unitless number or a string whose first segment is one (`"1 1 0%"`); a string value whose first segment is unitful (`"0px"`) is growable (basis shorthand, implicit grow 1); an unparseable value under one of those keys, a spread inside the object, or a computed key makes the element growable fail-closed (`opaque-style-grow`). EVERY other expression kind — identifier, call, member access, and anything not named above — is INVISIBLE to the scan by the default clause: residual hole (§7), not a candidate.
2. **Statically childless.** Self-closing; or zero children after dropping whitespace-only `JsxText` (with or without line terminators — a lone space paints nothing) and empty `JsxExpression` nodes (`{/* comment */}`); or every remaining child is a `{null}` / `{undefined}` literal expression.
3. **Unpainted** (evaluated for DOM tags only; component tags are decided solely by the registry, §4.3). No statically-harvested token (after important/variant stripping) is a member of the `PAINT_TOKENS` set (§4.2) — or a member IS present but so is a negator of that member's family (§4.2), in which case the element is conservatively unpainted.
4. **Not registered** (component tags — capitalized identifier or member expression — only). The tag name is not in `APPROVED_GROWABLE_COMPONENTS`.
5. **Not exempted.** No `childless-growable-ok: <reason>` exemption comment binds to the element (§4.4).

**Static harvesting** collects, recursively at EVERY level of the className expression (not only inside call arguments): string literals; no-substitution templates; the static parts of template expressions; array-literal elements; call-expression arguments AND the receiver expression of a property-access call (so `["h-px flex-1", cond ? "bg-a" : "bg-b"].join(" ")` harvests the array); both branches of conditional expressions; both operands of every binary operator (`&&`, `||`, `??`, `+`, and any other); parenthesized expressions; and object-literal keys (the clsx object form). Harvesting is fragment-wise, NOT constant-folding: a growable token deliberately assembled ACROSS fragment boundaries — `"flex-" + "1"`, `` `flex-${1}` ``, `["flex", "1"].join("-")` — yields fragments none of which is a growable token, so the element never becomes a candidate. This is an accepted residual (§7 row 7): the guard targets accidental reintroduction, and split-token assembly is deliberate authorship indistinguishable from the unbounded opaque-identifier space. Any non-static part encountered marks the className *partially opaque*. **Fail-closed note (the decision that killed the prior attempt, now resolved by census):** a growable, childless element whose statically-visible tokens include no `PAINT_TOKENS` member IS a violation even if an unresolvable dynamic part might paint at runtime. Opacity does not launder a candidate. The census (§2) measures today's cost of this posture at zero sites.

**Elements the scanner cannot see are out of the banned set by construction** (growability invisible): className supplied entirely via spread or identifier with no static growable token, `style` supplied as an identifier/call/member. These are the documented residual holes (§7), covered by the runtime instruments — NOT reasons to widen this guard into unsoundness.

## 4. The allowlist

Every growable candidate must match one of four shapes:

1. **Possibly-childed.** Any static JSX/text child, or any expression child other than a bare `{null}`/`{undefined}` literal — including `{cond && x}`, ternaries, `{children}`, `{label}`, `{items.map(…)}`, and `{""}`. The guard does not evaluate expressions; deciding runtime emptiness statically is the undecidable question that produced the 27-vs-17 census split, and it is framed OUT of this guard. Runtime-empty growables are the phantom-gap probes' jurisdiction.
2. **Painted childless (DOM tags only) — idiom membership, not pixel proof.** After three review rounds on paint soundness (prefix families → color-only members → geometry/transform/currentColor corners), the `docs/agents/spec-self-review.md` 3-round cap applies, and the claim is now scoped honestly: matching this shape certifies that the candidate matches the repo's ratified decorative-rule IDIOM; it does NOT prove rendered pixels — pixel truth is the runtime instruments' jurisdiction (§7 row 9). The shape requires BOTH:
   (a) **A paint member:** at least one statically-harvested token (after variant/important stripping) in `PAINT_TOKENS`, an explicit exact-match set exported by the scanner, seeded from the census: `bg-border`, `bg-accent`, `border`. (`bg-border-strong` was a founding member, retired 2026-08-10 under §6.3's dead-member rule when the wizard step connector — its last growable candidate — was resized off `flex-1` and re-ramped to text tokens per DESIGN.md §1.2a; its remaining live uses are non-growable 3px dots, which are not candidates. Re-adding it requires a live growable candidate that harvests it, same as any new member.) Membership is exact — no prefix families, so non-painting utilities (`bg-cover`, `bg-clip-*`, `border-solid`, `ring-inset`, …) can never satisfy it, and color-only utilities (`border-accent-edge`) are deliberately NOT members. A matched member is cancelled by a family negator anywhere in the harvest — `bg-transparent`/`bg-none` (bg family), `border-0`/`border-none`/`border-transparent` (border family; families with no set member define no negator list) — or by a global neutralizer `opacity-0`/`invisible` (variant-prefixed forms cancel conservatively, §7 row 8). Cancellation is per-family and order-blind: `border bg-transparent` stays painted via `border`; `bg-border border border-0` stays painted via `bg-border`. The negator/neutralizer lists are cheap hardening, DELIBERATELY non-exhaustive (§7 row 9) — enumerating every zero-pixel combination is the unbounded model this spec rejects.
   (b) **Provably-positive cross-axis extent:** at least one harvested token proving nonzero extent on some axis. Extent tokens normalize exactly like every other token (variant prefixes stripped first, then one important marker). The grammar is a CLOSED lexical partition: `self-stretch`; and for prefix ∈ {`h`, `w`, `min-h`, `min-w`, `size`, `py`, `px`} — `<prefix>-px`; `<prefix>-<n>` with bare unitless n > 0; `<prefix>-[<v>]` where v matches an UNSIGNED positive number followed by one unit from the closed list `px`/`rem`/`em`/`vh`/`vw`. Every other form is NOT extent — signed values, decimal-zero, percentages (`h-[50%]` of an auto parent is 0), unitless arbitrary values, unknown units, `calc(…)`, `var(…)`, and any other token. The failure direction is conservative: unproven extent means the candidate misses the painted shape and FAILS, costing at most one exemption comment. An auto-height childless span paints nothing even with a background; every live hairline carries explicit thickness (`h-px` ×3, `h-1.5`), so this requirement is free today and closes the auto-geometry corner statically.
   Growing the set is a reviewed one-line change; a new paint token used by a legitimate new hairline fails the guard with a message naming the set, and the author adds the token in the same PR. This is an approved shape precisely so that no exemption comment ever appears on a hairline (the backlog entry, header cite).
3. **Registered component.** EVERY childless growable component tag must appear in `APPROVED_GROWABLE_COMPONENTS`, regardless of what className tokens are visible at the call site — a className is a prop, not a guarantee of what the component renders, so the painted shape never applies to component tags. Registry rows carry a reason and `file:line` citation. Ships with exactly two rows: `Skeleton` (renders a painted div, `components/layout/Skeleton.tsx:15`) and `FilterTextInput` (renders an `<input>`, `components/admin/telemetry/EventFilters.tsx:20`). A NEW childless growable component tag fails closed with a message naming the registry. Matching is by tag name (member-expression tags use the full dotted text); accepted imprecision, noted in §7.
4. **Exemption comment.** `childless-growable-ok: <non-empty reason>` in a comment, with the same mechanics as the new-tab guard's exemption: marker constant at `tests/styles/_newTabScan.ts:49`, reason-required parsing (jsdoc decoration stripped) around `tests/styles/_newTabScan.ts:2835`, position-based binding with same-line/preceding-line adjacency and claiming as implemented at `tests/styles/_newTabScan.ts:2854`–`2910`. Template semantics adopted verbatim: the first following candidate CLAIMS the exemption and marks it used BEFORE its own compliance is decided — so an exemption sitting above a candidate that is independently compliant is consumed silently, not reported (it surfaces as unused only when the candidate disappears entirely). An UNUSED exemption (no following candidate claims it) is itself a test failure — dead exemptions may not accumulate. **TSX only:** exemption comments are NOT supported in MDX (§5 — compilation hoists comments away from their elements); an MDX growable that needs exempting is restructured or moved to a TSX component.

## 5. Scanner module — `tests/styles/_childlessGrowableScan.ts`

Follows the `_newTabScan.ts` template: TypeScript compiler API parse (`ts.createSourceFile`, TSX script kind), directory walk matching the repo idiom in `tests/styles/_classScanUtils.ts`, and a `scanSource(source, fileName)` seam exported so synthetic self-tests can drive every accept/reject branch without touching the live tree.

**MDX.** `.mdx` files are compiled to JSX via `@mdx-js/mdx` `compileSync` before scanning (same stack as `tests/styles/_newTabScan.ts:2445`). Two MDX-specific contract points, forced by compilation: (a) violation diagnostics in MDX report the source FILE with the compiled-output position explicitly labeled approximate — compiled positions do not map to author lines; (b) exemption comments are not honored in MDX (`compileSync` hoists adjacent comments into module boilerplate, so position-binding cannot see them) — the §6.4 matrix probes both behaviors. Zero MDX growables exist today (§2), so this contract is currently cost-free.

Exports: `scanSource(source, fileName, opts?)` (returns `{ violations, exemptions }` with positions, tag, matched tokens, and the §3 reason discriminant per violation; `opts.registry` substitutes a probe registry for `APPROVED_GROWABLE_COMPONENTS` — the ONE injection mechanism, used by the §6.4 dotted-name probe; `opts.paintTokens` likewise for paint-set probes needing hypothetical members), `walkLiveTree()` (files under `components/` + `app/`, extensions `.tsx` + `.mdx`), `APPROVED_GROWABLE_COMPONENTS`, `PAINT_TOKENS`, and the growable/paint/extent token predicates (so self-tests can probe them directly).

Line terminators: reuse the template's `LINE_TERMINATORS` class (`tests/styles/_newTabScan.ts:45`) — LF-only handling produced three separate findings on the #592 guard; do not re-derive that class.

## 6. Meta test — `tests/styles/_metaChildlessGrowable.test.ts`

Runs in the unit suite via the existing `tests/styles/**/*.test.{ts,tsx}` glob (`vitest.projects.ts:73`); no CI wiring changes.

1. **Live-tree gate:** walk `components/` + `app/`, assert zero violations. 2. **Unused-exemption gate:** assert zero unused exemptions in the live tree.
3. **Registry and set hygiene:** every `APPROVED_GROWABLE_COMPONENTS` row and every `PAINT_TOKENS` member must be LIVE, where liveness means OCCURRENCE — the registry row's tag appears as a childless growable component somewhere in the tree, and the paint token occurs in the harvested token set of at least one live painted-childless candidate (occurrence, not sole-decider: union-harvested members on a multi-token candidate all count, which is satisfiable by the §2 census — `bg-border` via both hairlines, `bg-accent` and `border` via `RightNowHero.tsx:549`; `bg-border-strong` satisfied this via `OnboardingWizard.tsx:196` until that candidate retired 2026-08-10, and this gate firing on the retirement is what removed the member from §4.2a). Anti-tautology: every reject probe asserts the violation's reason discriminant and location, not just a count; every accept probe runs against a source that ALSO contains a known violation, so an accidentally-empty scan cannot pass it. Concrete failure mode each self-test catches: a scanner edit that silently narrows harvesting (probe: the join-array shape v1 actually missed), widens paint (probe: `bg-cover`), or breaks exemption ownership (probe: consumed-by-compliant-candidate).
