## §1 Problem

A step that runs `echo "PATH=/fake-bin:$PATH" >> "$GITHUB_ENV"` (an env-file variable assignment) or `echo "/fake-bin" >> "$GITHUB_PATH"` (an env-file PATH-component prepend) mutates the environment of every LATER step in the same job. A textually clean `pnpm exec playwright test …` step downstream then runs a fake pnpm that exits 0 — green step, no tests. (R1 probe honesty: a GITHUB_PATH entry is a path COMPONENT, not an assignment — the BACKLOG charter's `PATH=/fake:$PATH >> $GITHUB_PATH` illustration would prepend a literal `PATH=/fake` component; the predicate is mention-based so both forms red identically, but every example and fixture in this arc uses the semantically corrupting forms above. The green-step/no-tests runtime effect was demonstrated by the R1 reviewer's executable probe: `runtime.downstreamExit=0, runtime.testsRan=false`.) R12 (arc `feat/ci-dark-descoped-guards`) closed the WITHIN-run-block shell-state class in both layers; the CROSS-STEP variant stayed open because neither layer models job-scoped state:

- The **invocation census** (`tests/ci/_metaSpecRegistration.test.ts`, `runBlocksOf` ~line 265) flattens every job's steps into one `RunBlock[]` with no job identity. The poisoning step mentions no playwright token, so it contributes nothing and raises nothing; the later clean block auto-classifies.
- The **workflow-coverage scanner** (`tests/ci/_workflowCoverageScan.ts`, `scanWorkflowCoverage` ~line 213) qualifies each step independently: the whole rejection chain (`if:`, `continue-on-error`, `suppressesExit`, `UNMODELLED_SHELL_RE`) sees only the claiming step's own text.

## §2 Design

One shared predicate, two layer-specific groupings. Both layers keep their existing architecture (typed-YAML walk for the census, regex-on-YAML for the scanner) — the change is state threading, not a parser rewrite.

### §2.0 The poison predicate

A text "writes env" when, after dropping full-line `#` comment lines, it contains the substring `GITHUB_ENV` or `GITHUB_PATH` (case-sensitive — the runner exports exactly these names; bash variables are case-sensitive).

- Census form: a small helper inside `tests/ci/_metaSpecRegistration.test.ts` applied to `run:` strings.
- Scanner form: the same regex applied to the step CHUNK (everything the step-splitter produced, minus full-line-comment lines). The chunk includes `name:`/`with:`/`env:` lines — chunk-level matching is deliberately broader than the census's run-block matching (§5 L5); broader is the safe direction.
- Comment stripping mirrors the layers' existing posture (census skips full-line `#` lines because they never execute; the scanner already strips them from `cmd` — and its step-splitter glues BETWEEN-step comment prose onto the preceding chunk, so prose mentioning GITHUB_ENV must not poison; F6 pins this).
- No write-shape grammar (`>>` vs `>` vs `tee -a` vs heredoc): mention = poison. Distinguishing writes from reads or from mentions requires shell modeling, which is the losing game every prior round retired. This makes F2 (write-pattern narrowing) structurally impossible to reintroduce without failing the F2 fixtures.

### §2.1 Census: `runBlocksOf` gains job grouping + composite splice

`tests/ci/_metaSpecRegistration.test.ts`:

- `RunBlock` (~line 259) gains `poisoned: boolean`.
- `runBlocksOf(doc, localActions?)` — new optional second parameter `Record<string, unknown>` mapping a local `uses:` ref exactly as written (e.g. `./.github/actions/setup`) to that action's parsed YAML doc.
- Per workflow job, walk `steps` IN ORDER with an `envPoisoned` flag (fresh per job), via ONE shared recursive walker:
  - `run:` step → emit `{ run, guarded, poisoned: envPoisoned }`, then if the run text matches the poison predicate → `envPoisoned = true`.
  - `uses:` step with a `./`-prefixed ref (the census reads the PARSED doc, so YAML quoting around the ref is already resolved) → splice is permitted ONLY when the ref resolves in `localActions` AND the action declares `runs.using: composite` AND the ref is not already on the current resolution path:
    - **Walkable (composite, known, acyclic)** → SPLICE: recurse into the action's `runs.steps` with the same walker; each run step emits `{ run, guarded: jobGuarded || every if: on the use-chain || actionStep.if !== undefined || customShell(actionStep), poisoned: envPoisoned }`; a nested `uses: ./…` step recurses again (R1 escaping mutant #2 — a composite may delegate to another local composite). Poison flows BOTH directions: an earlier workflow write poisons spliced action blocks, and an action (or grandchild) write sets `envPoisoned = true` for the rest of the action AND the rest of the workflow job.
    - **Opaque (fail-closed poison, R1 BLOCKING):** ref ABSENT from `localActions`; OR the action is NOT `using: composite` (a javascript/docker action has no `runs.steps`, and its entry code can `core.addPath` / `core.exportVariable` / write env files with nothing for a YAML walk to see — presence in the map is NOT "modeled"); OR the ref is already on the current resolution path (cycle — GitHub rejects cyclic actions; the walker must neither hang nor fail open). The cycle guard is PATH-scoped: sequential reuse of one action within a job is legit and stays clean.
  - `uses:` step with a non-`./` ref → classified by the SHARED `usesKind` (spec §7 R10-R14): a well-formed `owner/repo[/path]@ref` is trusted and changes nothing; anything else (refless, `docker://` in any form, Git-invalid ref, non-string) is INVALID and poisons fail-closed. A step carrying BOTH `run:` and `uses:` makes the whole workflow schema-invalid, so every job in the file is treated as unreachable (§7 R15).
- Standalone composite-doc walk (`runs.steps` when `runBlocksOf` receives an action doc directly): the same walker, so internal ordering and nested local `uses:` resolve identically (with no map supplied, a nested local ref is opaque and poisons). Manifest walkability is decided by the shared `validatedCompositeSteps` narrow-accept profile, not by textual inspection (§7 R8/R9), and a job whose `runs-on` is not one of the schedulable shapes never executes, so its blocks start poisoned — decided by the shared TYPED `validRunsOn` (§7 R16/R17), which the scanner also calls against the parsed document.
- `censusInvocations` item type gains `poisoned?: boolean`. The `contextWhy` chain (~line 562) gets a new branch — after `guarded`, before control-flow — with why-string: `environment poisoned by an earlier same-job GITHUB_ENV/GITHUB_PATH write`. Registry-or-loud, identical routing to every other context: a poisoned block's classifying lines must appear in `COMPLEX_INVOCATION_REGISTRY` with human-declared contributions, else the census reds. Non-classifying lines in a poisoned block stay silent (same rule as `guarded`).
- Config-set tripwire (~line 1199): build the `localActions` doc map from `.github/actions/**` up front (keyed `./<dir>` — the shape `usedActionDirs` already computes); pass it to every workflow's `runBlocksOf` call; DELETE the separate "append used-action blocks" push (spliced blocks now arrive per use site, correctly guarded and poisoned per job). R2 BLOCKING refinement: ONLY the GitHub-recognized manifest (action.yml preferred, action.yaml fallback) keys the map — keying every yml under the dir let a supplemental clean YAML overwrite the parsed manifest under the same key. Non-manifest YAML under an action dir never executes, so playwright text there is dead text posing as surface: forbidden outright (extends the R9 G1 unreferenced-action rule, which itself now iterates manifests only).

Duplication note: `./.github/actions/setup` is used by ~20 jobs, so its `pnpm install --frozen-lockfile` block is now censused once per use site instead of once total. Harmless by construction: `invoked` is a Set, `problems` only fire on classifying/problematic text, and that block contains no playwright token.

### §2.2 Scanner: per-job poison flag + `localActions` opt

`tests/ci/_workflowCoverageScan.ts`:

- `Opts` gains `localActions?: Record<string, string>` (local `uses:` ref → raw action YAML text).
- Inside the per-job loop of `scanWorkflowCoverage` (~line 262), thread `envPoisoned` across the step iteration. For EVERY step chunk (before the `run:`-presence early-continue, which today skips non-run steps entirely):
  1. Qualification first: a claiming step evaluated while `envPoisoned` is true rejects every claim with the new reason `earlier same-job step writes GITHUB_ENV/GITHUB_PATH`, inserted in the chain directly after `unmodelled execution override` (both are "the execution environment cannot be trusted" classes; before the path-filter/if/coe reasons).
  2. Then bookkeeping: if the comment-stripped chunk matches the poison predicate → `envPoisoned = true`. A `uses:` ref is resolved through the SHARED helpers rather than textual inspection: `usesKind` classifies the value (local / trusted remote / invalid, §7 R10-R14) and `validatedCompositeSteps` decides whether a local manifest is walkable at all (narrow ACCEPT profile: exact `using: composite`, array `steps`, per-step-kind key allowlists, scalar value shapes — §7 R8/R9). A local ref poisons fail-closed when it is absent from `localActions`, cyclic (path-scoped seen-set), or fails that profile; a walkable manifest poisons when its text matches the predicate, and its child `uses:` refs recurse through the same helpers. Trusted remotes change nothing. Invalid values poison. Beyond the per-step gates, two conditions are FILE-level because GitHub rejects the workflow outright: document markers/directives (§7 R3 audit) and a step carrying both `run:` and `uses:` (§7 R15). The unmodelled-SPELLING refusals are deliberately NOT file-wide — they are evaluated on the pre-jobs head, each job head, and each step's metadata (§7 R4), since run BODIES legitimately contain the shell characters those anchors match. A job whose `runs-on` fails the shared typed `validRunsOn` claims nothing (§7 R16/R17).
  - Order (qualify, then poison) means a step that both invokes and writes poisons only LATER steps — its own within-block write is the R12 class (`$GITHUB_ENV` trips `UNMODELLED_SHELL_RE` if the block classifies).
- Caller `tests/ci/_metaE2eWorkflowCoverage.test.ts`: build `localActions` by walking `.github/actions/**` for action manifest files (action.yml / action.yaml basenames), keyed `./<dir>`, and pass it. (Today that map has two entries: `./.github/actions/setup`, `./.github/actions/assert-pnpm-sources` — neither text matches the predicate, verified by the live-green acceptance gate §4.3.)

### §2.3 What deliberately does NOT change

- `UNMODELLED_RE` / `UNMODELLED_SHELL_RE` / `controlFlowRe` / `cmdPos` — untouched (R12 closure, §1.1). (The comment-stripping single-source registry DID gain one reasoned row for the scanner's `stripCommentLines`, recorded in §6 and in the plan's meta-test inventory — it is a registry row, not a new stripping mechanism.)
- Workflow/job-level `env:` blocks — a different (static, not cross-step-state) vector; §5 L3.
- `suppressesExit`, whole-config literal rule, alias resolution — untouched.
- No live workflow or action file changes; zero-writer state means no allowlist/registry rows are added.

## §3 Mutation-family closure set

The review converges against exactly these families. Each is pinned by named fixtures in both self-suites (census fixtures inside the census `it`-blocks of `_metaSpecRegistration.test.ts`; scanner fixtures in the self-suite describes of `_metaE2eWorkflowCoverage.test.ts`). A NEW family requires a live escaping mutant against the shipped guard (`docs/agents/writing-plans.md`).

| Family | Mutant | Pinning fixture(s) |
| --- | --- | --- |
| **F1 grouping deletion** | drop job identity (re-flatten); or poison globally across jobs | positive: write-then-invoke in ONE job reds both layers. Precision twin: write in job A, clean invocation in job B → B stays covered/clean (per-job flag, not per-file) |
| **F2 write-pattern narrowing** | detection narrowed to one redirect shape | three write forms all red: `echo … >> "$GITHUB_PATH"`, `tee -a "$GITHUB_ENV"`, `echo … > "$GITHUB_PATH"` (substring predicate cannot pass one and fail another; fixtures make narrowing loud) |
| **F3 ordering inversion** | poison applied to earlier instead of later steps (or order ignored) | write AFTER the invocation step → invocation stays covered/clean; write BEFORE → reds. Both directions pinned |
| **F4 composite blind spot** | `uses: ./…` splice dropped or unidirectional | local action whose step writes `GITHUB_ENV`, later workflow step invokes → reds both layers; census twin: earlier workflow write + action step carrying a classifying line → action block poisoned; action-internal ordering (action step 1 writes, action step 2 classifies) → poisoned |
| **F5 unknown-local-action fail-open** | unresolvable `./` ref treated as clean | `uses: ./ghost` (absent from `localActions`) before an invocation → reds both layers; quoted-ref twin (scanner): `uses: "./ghost"` reds identically |
| **F6 comment/prose false-positive** | predicate matches comment prose (precision loss) | full-line `#` comment mentioning `GITHUB_ENV` between steps (scanner comment-glue) and inside a run block (census) → does NOT poison; clean multi-step job stays green |
| **F7 non-composite opaque action** (R1 escaping mutant #1, live probe: `census.classified=true, scanner.covered=true, runtime.testsRan=false`; refined at R2 with two bypass instances) | a KNOWN javascript/docker local action treated as modeled — including masquerading via a `using: composite` line in description prose (scanner), or a supplemental same-dir YAML overwriting the manifest in the doc map (census tripwire) | `uses: ./js` with `using: node20` before an invocation → reds both layers; masqueraded-description manifest → reds (scanner), prose-bearing REAL composite stays clean; map keyed by action.yml/action.yaml only + non-manifest action-dir YAML is dead-text-forbidden (census tripwire, structural) |
| **F8 nested local-composite resolution** (R1 escaping mutant #2, same probe shape) | recursion dropped, or cycles hang/fail open | parent composite `uses: ./child`, child writes → reds both layers; clean chain stays green; self-cycle → reds fail-closed; sequential same-action reuse stays clean (census) |

F1's precision twin and F3's negative direction are as load-bearing as the positives: an over-poisoning guard that reds everything forces reason-free allowlist rows and trains humans to rubber-stamp them (the false-positives-are-not-safe lesson).

## §5 Documented limits

Consequence bound, stated per limit (R1 correction — the earlier draft claimed a uniform fail-closed bound, which L3 does not satisfy): L1/L2 under-poison only where the write itself is adversarial repo content, with the §4 run-report comparator + `PLAYWRIGHT_` sweep + real-CI observation layer as independent mitigations; L4/L5 err in the over-poison (fail-closed) direction; **L3 is a genuinely fail-OPEN residual** — pre-existing, outside this charter, and now FILED rather than hand-waved.

- **L1 Marketplace/remote actions are trusted.** `actions/setup-node` writes `GITHUB_PATH` by design; `actions/github-script` can call `core.exportVariable` with no literal `GITHUB_ENV` anywhere. Modeling remote action internals is out of universe (same boundary as the census collector and the `PLAYWRIGHT_` sweep). A repo-controlled attack via a NEW remote action is a PR-reviewable diff line (`uses:` addition). LOCAL javascript/docker actions are NOT trusted — they poison fail-closed (§3 F7, R1).
- **L2 Constructed-name evasions escape the substring family.** `E=$GITHUB""_ENV`, `tr`-case games, globbing the runner temp path (`…/_runner_file_commands/set_env_*`). Ratified axiom: perfect obfuscation detection is impossible; enumerated families are what review produced. Admissible as a finding only with a live escaping mutant probe — and any such line in a CLASSIFYING block already trips the `$`/backtick refusals.
- **L3 Static `env:` blocks at workflow/job/step level are a FAIL-OPEN residual of the scanner at large** (R1 probe: a job-level `env: PATH: fixtures/fake:…` before a plain invocation yields `covered`, `rejected: []`). It is a different vector — no cross-step ordering, no state to thread — and predates this arc; `standalone-e2e.yml` pins no-`env:` at every level for the surface where the reporter-path pair matters, and `PLAYWRIGHT_*` text is swept in `.github/actions`, but the general scanner does not model `env:`. Deliberately out of this charter; filed as `BL-CI-STATIC-ENV-INJECTION` in repo-root `BACKLOG.md` with the R1 probe as its measurement.
- **L4 Reads poison like writes.** `cat "$GITHUB_ENV"` (rare, legit) poisons later steps. Deliberate: distinguishing read from write is shell modeling. Cost: one reasoned registry/allowlist row if it ever occurs.
- **L5 Scanner chunk-level matching is broader than census run-block matching.** A `name: dump GITHUB_ENV` line poisons in the scanner, not the census. Asymmetry accepted: each layer errs conservative within its own parse universe; the layers already differ this way (regex chunks vs typed YAML).
- **L6 A poisoning FINAL step (nothing after it) poisons nothing.** Correct by construction — env mutation affects only later steps.
- **L7 The composite ACCEPT profile is narrower than GitHub's full action schema (R9).** A manifest that is genuinely valid but uses a construct outside the profile — a step key GitHub adds later, a non-scalar `with:` value, an expression-typed `continue-on-error` — reads as OPAQUE and poisons its job fail-closed. That is the deliberate direction: the residue is refused-but-valid (one reasoned allowlist row, plus a profile widening if the shape becomes common), never accepted-but-invalid. The two live local actions are on-profile, and the profile covers every documented composite step key.
- **L8 The `uses:` classifier accepts only conservative reference shapes, and refuses the `docker://` family WHOLESALE (R10-R13).** Accepted: a local `./…` ref, or `owner/repo[/path]@ref` where the ref matches a NARROW allowlist (alphanumeric-leading tag/branch of alphanumerics, dots, hyphens and underscores with no `..`, no trailing dot, no `.lock` ending — or a full 40-hex SHA). A valid but slash-bearing ref such as `release/v1` is refused; the live set is v1/v4/v7, so nothing live is affected (R14). Refused: everything else, including every well-formed docker image reference. Rationale: R12 replaced a permissive check with a hand-written image grammar and R13 immediately produced four more Docker-invalid forms it accepted (hyphen-edged registry labels, over-long tags, over-long repository paths, bare 64-hex names) — Docker's reference grammar is its own specification with length and character rules, and re-implementing it is the losing game this arc retired twice already. Zero live workflows use `docker://`, so the refusal costs nothing today and a reasoned allowlist row if one ever appears. Same direction as L7: refused-but-valid is a conservative refusal; accepted-but-invalid would be silent false coverage.
