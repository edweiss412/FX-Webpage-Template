# Round-economy enforcement pair: guard-surface dispatch gate + Mechanizable ledger parity

**Date:** 2026-08-15 · **Ledger rows:** `BL-CODEX-GUARD-ENROLMENT-PRECEDES-DISPATCH`, `BL-FILING-MECHANIZABLE-LEDGER-PARITY` (both `BACKLOG.md`) · **Branch:** `chore/round-economy-enforcement-pair`

Two enforcement halves, one arc, both mechanizing prose rules the round-economy corpus measured failing as prose:

- **Half A** — `scripts/codex-guard.mjs` refuses (exit 2, before any tokens burn) a round-1 `--stage diff` dispatch whose brief declares its subject a guard surface but states neither its mutation score + unaccepted-survivor set nor a cannot-express disposition. Mechanizes followups-2 promotion P2 (`docs/superpowers/specs/ci/2026-08-09-round-economy-followups-2.md` §2 P2), whose §5 non-goals deliberately excluded enforcement; this spec is that scheduled enforcement.
- **Half B** — `tests/docs/_metaReviewRoundEconomy.test.ts` additionally requires a NEW filing's non-none `**Mechanizable:**` entry to cite a resolvable `BL-`/`DEF-` id or decline explicitly (`declined: <reason>`), plus a one-time backfill dispositioning the enumerated stray candidates already merged.

## §1.1 Resolved scope — do not relitigate

1. **Trigger is an opt-in declaration line, not inference.** Half A fires only on a brief carrying a `GUARD SURFACE:` line. An undeclared guard-surface brief passes unchecked — a DOCUMENTED LIMIT (§5), same posture as the convergence hook's `PROBE DOMAIN:` line (AGENTS.md, convergence-criterion bullet 2): the declaration convention binds authors via the prose rule; the gate enforces the declared case. NLP-detecting "this brief is about a guard" is the recognizer-growth failure mode the round-economy corpus documents (speclint-prose-count-parity, 20 flat rounds) and is out of scope. Ratified by the ledger row itself: "Detection heuristics, override mechanics, and whether the declaration is a brief line or a flag belong to the implementing arc" (`BACKLOG.md`, `BL-CODEX-GUARD-ENROLMENT-PRECEDES-DISPATCH`).
2. **Round-1 diff only.** The row's title and body scope the gate to "a round-1 `--stage diff` dispatch". Spec/plan/task stages and rounds ≥ 2 are exempt by design — the AGENTS.md contract puts the score statement in "the round-1 brief" (convergence-criterion bullet 4).
3. **Entry-level granularity for Half B.** The row's gate half reads "a filing's non-none `**Mechanizable:**` entry must contain a resolvable `BL-`/`DEF-` id OR an explicit decline marker" — per entry, not per candidate. A block listing three candidates and citing one id passes (§5).
4. **Filings are immutable evidence; the existing corpus is grandfathered as-is** (corpus contract, `docs/superpowers/specs/ci/2026-08-04-review-round-economy.md`; restated in the ledger row). No retro-edit of any merged filing, including the five stray candidates' filings. Grandfathering is a frozen path list (§3.3), a closed historical set — legitimately enumerated, never grown.
5. **The per-machine review-convergence hook is untouched.** The row fences it: "The per-machine review-convergence hook cannot carry this (it lives outside the repo and P2's arc fenced it off)". Enforcement lands only in tracked files.
6. **Row-vs-decline for each backfill candidate is this arc's call**, per the row's delegation ("the implementing arc decides which, per the ledger filing bar"). Dispositions in §4 are final for this arc; a reviewer disputing one argues against the ledger filing bar's own admissibility terms, not this spec.
7. **The score arm is a hygiene check on the declaration's existence and well-formedness, never a re-derivation of gate truth (ratified after spec R4).** Rounds 1, 3, and 4 each landed a finding on this one recognizer; per the repair-economy rule (`docs/agents/writing-plans.md`, "when consecutive rounds keep landing on ONE function, the mechanism is answering the wrong question"), the arm's final question is "did the author state their enrolment evidence in the one canonical shape" — §2.1's single anchored regex plus the two impossibility checks. Value-judgment probes (below-floor, accepted-row consistency, staleness of the stated run) file to §5.8, not to a round; an admissible new finding on this arm must show a CANONICAL declaration accepted with impossible accounting, or a conforming declaration rejected.
8. **`codex-guard.mjs` itself is cannot-express for the source-mutation registry**, measured not argued: the runner overlays a target only when a Vitest suite imports it, and every suite in `tests/codexGuard/*.test.ts` spawns the script as a child process (e.g. `tests/codexGuard/happyPath.test.ts`) — no import edge exists. Same shape class as the measured un-enrollable CLI oracle recorded in `tests/mutation/source/registry.ts` (the `phantomGapExecuted` row's header comment: enrolled whole, the sibling one-file CLI scored 0.27 with 18/19 survivors unreachable). The lib half (`lib/reviewRounds/filing.ts`, `corpus.ts`) IS expressible; `corpus.ts` and `count.ts` are already enrolled (`reviewRoundCorpus`, `reviewRoundCount` rows) and this arc enrols `filing.ts` (§6.3).

## §2 Half A — codex-guard guard-surface dispatch gate

### §2.1 Behavior

At config-validation time — after `--brief` is read (`scripts/codex-guard.mjs`, `cfg.briefText` at the `--brief unreadable` guard) and before lock/dispatch, alongside the existing exit-2 usage guards (`usageError`, `scripts/codex-guard.mjs:45`; missing `--stage`/`--round` already exit 2 naming the flag):

1. Applies only when `cfg.stage === "diff" && cfg.round === 1`.
2. Compute `scanText = stripCodeBlocks(cfg.briefText)` (`scripts/codex-guard.mjs:626`) — the existing CommonMark-hardened fence eliding, so a brief QUOTING a marker inside a fenced block neither triggers nor satisfies the gate (use-vs-mention, the convergence gate's measured lesson).
3. If `scanText` has no line matching `/^\s*(?:#{1,6}\s+)?GUARD SURFACE:/m` — no check. Done. The optional ATX marker was added 2026-08-22 after a corpus sweep found 24 heading-form declarations the original trigger never read (jurisdiction spec §2.2, `docs/superpowers/specs/ci/2026-08-22-mutation-score-jurisdiction-gap.md`).
4. **Per-line contract (spec R1 findings 1–2): each `GUARD SURFACE:` line declares ONE surface and carries that surface's own disposition on the SAME line.** A multi-surface arc writes one line per surface. Every line the item-3 trigger matches must have a remainder (text after the first colon) satisfying the arm its markers select. **Marker precedence (jurisdiction spec §2.2):** a remainder carrying `MUTATION SCORE:` in any shape is a score declaration, decided by the canonical score arm plus the `OPERATORS:` check, and is never consulted against the cannot-express arm, valid or not — otherwise a non-canonical `0/0` or a valid score missing its operator set would be rescued by a `CANNOT-EXPRESS:` tail beside it. The cannot-express arm decides only marker-free remainders:
   - **Score arm (canonical anchored grammar; final form after R1/R3/R4 all landed on this recognizer — the repair-economy narrowing, not another widening):** the remainder matches ONE regex binding marker, fraction, and survivor phrase adjacently: `/MUTATION SCORE:\s*(\d+)\s*\/\s*(\d+)\s*[,;—–-]?\s*(?:0|no)\s+unaccepted\s+survivors?\b/i`, with the captured `<killed>/<total>` satisfying `total >= 1` and `killed <= total` (the shipped authority's `no-mutants` and `unaccounted-mutants` conditions, `tests/mutation/source/gate.ts`). Adjacency is load-bearing (R4 `unrelated_fraction` probe): a floating fraction elsewhere in the line — a date, a "last run 12/12" aside — cannot satisfy the arm, because the fraction must directly follow the literal `MUTATION SCORE:` marker and the zero-unaccepted phrase must directly follow the fraction. "MUTATION SCORE: 82/84, 0 unaccepted survivors" satisfies it; "2 unaccepted survivors" is a declared non-converged surface and is rejected — dispatching on it is exactly what enrolment-precedes-review forbids. A remainder that satisfies the score regex must ALSO contain `/\bOPERATORS:\s*\S/` (2026-08-22): the comma-separated declared operator names, or `all` for a full-set row. A score is complete over the operators it ranges over and over nothing else, so a score without that set is a number without its jurisdiction. Presence is checked, membership is not (§5 item 9).
   - **Cannot-express arm:** the remainder contains `CANNOT-EXPRESS:` with a non-empty tail — the honest re-disposition citing its probe (the step3 pattern, `docs/superpowers/specs/2026-08-09-quick-wins-2-mech.md` §1.1.4). Content of the citation is the author's; the gate checks presence, not prose quality.
5. Any nonconforming `GUARD SURFACE:` line → `usageError` (exit 2). The message enumerates EVERY nonconforming line (line number + first 80 chars), not only the first, and names both arms: `each GUARD SURFACE: line in a round-1 diff brief must carry its own MUTATION SCORE (<killed>/<total> plus "0 unaccepted survivors" plus OPERATORS: <declared names, or all>) or CANNOT-EXPRESS: <probe citation> — see AGENTS.md convergence-criterion bullet 4`.

Why per-line rather than the drafted brief-global arms: probed against this arc's own round-1 brief shape (spec R1 findings 1–2, both in-domain and inside the accidental-author fence), a brief-global check let one surface's `CANNOT-EXPRESS:` silently absorb a deleted `MUTATION SCORE:` line, one surface's score silently cover a second enrolled surface, and a declared NON-empty unaccepted-survivor set pass. Binding score to survivor-emptiness on the same declaring line closes all three with no new recognizer over prose.

Accept-set, stated positively: the gate ACCEPTS (a) briefs with no line-anchored `GUARD SURFACE:` marker outside fenced blocks, (b) declared briefs in which EVERY `GUARD SURFACE:` line carries a conforming score arm or cannot-express arm in its own remainder, (c) any brief at stage ≠ diff or round ≠ 1. Everything else at the trigger point is rejected by name (the exit-2 message). Markers are case-sensitive SHOUTY, matching the existing brief-marker family (`VERDICT:`, `FINDINGS:`, `PROBE DOMAIN:`).

### §2.2 Non-interference

- No change to the recovery ladder, result contract, heartbeat, or row emission — the check runs entirely inside the existing pre-dispatch validation phase, so a rejected dispatch writes no result artifact, takes no lock, and appends no corpus row (identical to today's missing-`--stage` behavior).
- `--fallback` rescue dispatches pass through the same check (they carry `--stage`/`--round` already); a rescue of a round-1 diff review re-presents the same brief, which by then conforms.

## §3 Half B — Mechanizable ledger parity

### §3.1 Parse contract (`lib/reviewRounds/filing.ts`)

`FilingSection` gains a `mechanizable` field:

```ts
mechanizable: {
  /** the marker paragraph's remainder begins `none` (word-bounded) */
  isNone: boolean;
  /** a structural decline declaration exists (marker remainder or block item) */
  hasDecline: boolean;
  /** BL-/DEF- ids cited inside the Mechanizable block (text + inline code only) */
  citedIds: string[];
  /** how many canonical Mechanizable markers the section holds */
  markerCount: number;
} | null;   // null = no canonical **Mechanizable:** marker in the section body
```

**The Mechanizable analysis is derived from the section body's markdown AST** (`remark` + `remark-gfm`, both direct dependencies in `package.json`; the `tests/docs/_ledgerMdast.ts` walker is the in-repo precedent for pinning prose guards to parsed properties instead of line regexes — adopted here at spec R8, whose finding demonstrated that every line-level recognizer in the earlier drafts read fenced code, indented code, and HTML comments as live content). Content that CommonMark does not render as prose — `code` blocks (fenced AND indented, with the parser deciding the context-dependent indented case a line scanner cannot), `html` nodes (comments included), and `inlineCode` where noted — is structurally invisible to every decision below, and so are `delete` (GFM strikethrough) descendants (spec R11 finding: `~~none~~`, `~~declined: …~~`, and `~~BL-…~~` are visible RETRACTIONS and must not satisfy `isNone`, either `hasDecline` location, or `citedIds`; the in-repo precedent already drops `delete` descendants in claim mode, `tests/docs/_ledgerMdast.ts:176`; one fixture per manifestation is mandated), closing false-accepts (a fenced `declined:` example, a commented-out id) and false-rejects (a phantom marker in a fence counting as a duplicate, an example bold field closing the block early) in one move:

- **Marker**: a top-level paragraph whose first child is a `strong` node with text exactly `Mechanizable:`. `markerCount` is the number of such paragraphs; the analysis reads the FIRST. (The colon-less `**Mechanizable** —` spelling has no such strong text and parses as `mechanizable: null` — for NEW filings that spelling already fails the existing `hasDisposition` requirement unless another disposition line is present; the parity rule adds no spelling recognizer.)
- **Top-level only, enforced loudly (spec R12 finding):** a `Mechanizable:` field paragraph that is AST-visible but NOT top-level — nested under any `listItem`, whatever the marker form (`-`, `*`, `+`, `1.`, `1)`; all five are pinned as fixtures) — would render for the reader while `markerCount` stayed zero and parity was never consulted. A NON-grandfathered filing containing such a nested field is reported `filing_malformed` naming the nesting, instead of silently admitted; the canonical layout is the top-level field paragraph the whole corpus already uses.
- **Duplicate rule (spec R6 finding):** two or more markers in one section have no defined aggregation — probed across both orderings, every singular projection silently loses an untracked block in at least one ordering — so `checkCorpus` reports `markerCount > 1` on a NON-grandfathered filing as `filing_malformed` ("nothing says which is the entry", the `duplicate_section` precedent). Both orderings are mandated fixtures.
- **Block**: the marker paragraph plus following AST siblings up to (excluding) the next FIELD paragraph — any paragraph beginning with a `strong` node whose text ends in a colon — OR any `heading` node (spec R9 finding 2: the live corpus lays out `**Mechanizable:** …` followed by a `### Judgment, not mechanizable` subsection, `docs/review-rounds/feat/review-infra-gates/61281c23e8ce.md`, and ids or declines in prose under such a heading must not leak into the block; ATX and setext forms both derive to the same `heading` node, so this is closed by node type) (spec R5 finding 2: the live corpus carries `**Carry-forward:**`, `**Diagnosis of the residual:**`, and four sibling spellings; a derived any-field boundary closes them all where an enumerated closer re-opens per spelling). Multi-line candidate lists belong to the block as `list` nodes.
- **`isNone`**: the marker paragraph's text after the strong node, trimmed, matches `/^none\b/i` — accepts `none`, `none.`, `none — all judgment-shaped` (`**Mechanizable:** none` is the existing legal form, meta-test fixture `FILING_OK`, `tests/docs/_metaReviewRoundEconomy.test.ts:151`).
- **`hasDecline`**: TRUE when the marker paragraph's remainder text begins `declined:` with a non-empty reason (spec R7 finding 1: 79 of 88 live canonical markers carry their value on the marker line), OR when any block paragraph or `listItem` — ANY CommonMark list-marker form, `-`/`*`/`+`/`1.`/`1)`, closed by node type rather than a marker-character enumeration (spec R8 finding 2) — has its first text content beginning `declined:` with a non-empty reason. A `declined:` inside `inlineCode`, `code`, or `html` is a MENTION and never a declaration (the R5 finding-1 protections, now by node type: `not declined: …` still fails the begins-with test; a prose mention of the form still sits mid-sentence).
- **`citedIds`**: `CITED_ID` (`lib/reviewRounds/filing.ts:24` — no second recognizer) over the block's `text` and `inlineCode` content only — backticked citations like `` `BL-FOO` `` count, examples inside `code`/`html` do not. Block-scoped on purpose: a Judgment paragraph citing a `BL-` row must not satisfy the Mechanizable entry's duty.

- **AST-visible field duty (spec R9 finding 1):** `parseFiling` additionally exposes `astDispositions` (which of `Mechanizable`/`Judgment`/`Infra` exist as AST-visible field paragraphs) and `astExamined` (same for `Examined:` — swept in because it is the same shape: a raw line scan satisfied only by content inside a fence, an indented block, or an HTML node while the AST sees nothing). For NON-grandfathered filings, `checkCorpus` satisfies the existing disposition and Examined duties from these AST-visible sets — a filing whose only `**Mechanizable:**`/`**Examined:**` lines live in non-rendered content is reported `filing_malformed` naming the non-rendered-only field, instead of being silently admitted by the raw scan with parity never consulted (the probed mismatch: raw `hasDisposition: true`, AST `markerCount: 0`, accepted). Grandfathered filings keep the shipped raw semantics untouched.

The EXISTING section-level checks (`hasExamined`, `hasDisposition`, section `citedIds`, heading grammar) keep their shipped line-based semantics unchanged — they are an enrolled scoreFloor-1 surface and out of this arc's scope; only the NEW `mechanizable` analysis is AST-derived.

### §3.2 Gate (`lib/reviewRounds/corpus.ts`)

New `ProblemKind`: `"mechanizable_untracked"`. In `checkCorpus`, for each section of a NON-grandfathered filing that passed the existing structural checks: if `mechanizable` is non-null, `!isNone`, `mechanizable.citedIds` is empty, and `!hasDecline` → problem:

```
<filingPath>:<line>: stage <stage> declares a non-none Mechanizable entry that cites no BL-/DEF- id and records no "declined: <reason>"
```

Resolvability spans BOTH id sets (spec R10 finding): the existing `unresolved_id` check keeps resolving the raw-scan section ids, AND every AST-derived `mechanizable.citedIds` value is checked against the same `resolvable` set, reporting `unresolved_id` when absent. Remark decodes backslash escapes and character references before `CITED_ID` runs, so an id spelled `BL\-NO-SUCH-ROW` or with a character reference decodes to a token the raw scan never saw — without this clause it would satisfy parity while resolution saw nothing and the corpus reported clean. Fixtures are mandated for both normalization families (backslash decoding, character-reference decoding) across both prefixes. Presence and resolution together are the parity contract.

## §5 Documented limits

1. **Undeclared guard surface (Half A).** A round-1 diff brief whose subject is a guard surface but which omits `GUARD SURFACE:` passes the gate. The declaration duty is the AGENTS.md prose contract (convergence-criterion bullet 4); the gate enforces the declared case only. Conservative under-check, surfaced here.
2. **Marker prose quality (Half A).** `CANNOT-EXPRESS: because I said so` passes. The gate is structural; probe quality is the reviewer's and orchestrator's ground, per the admissibility contract.
3. **Entry-level granularity (Half B).** A non-none Mechanizable block with N candidates and one cited id passes. Per-candidate parity was considered and rejected — it requires a candidate recognizer over free prose, the exact recognizer-growth shape §1.1.1 fences off.
4. **Judgment/Infra entries carry no parity duty.** Only Mechanizable names work someone should schedule; the other dispositions describe why rounds happened.
5. **Colon-less `**Mechanizable** —` spelling parses as absent** (§3.1). For new filings the existing `hasDisposition` structural check plus this rule make the canonical spelling the only conforming one when Mechanizable is the sole disposition; a new filing pairing the colon-less spelling with a conforming `**Judgment:**` line evades the parity duty. Accepted: the spelling recognizer costs more than the residual leak, and the README states the canonical form.
6. **A filing file deleted and re-created keeps its grandfather exemption** (path-keyed). Filings are immutable evidence; deletion is already a corpus-contract violation this gate does not police.
7. **A stale `none` exempts content later added below it (R7 finding 2 — fenced, not repaired).** `**Mechanizable:** none` followed by candidate lines passes: `isNone` reads only the marker-line remainder. Rejecting nonblank content under a none marker was probed against the live corpus and would false-reject the DOMINANT idiom — `docs/review-rounds/feat/ops-log-code-emits/61281c23e8ce.md` puts paragraphs and list lines under `none.` markers, `docs/review-rounds/feat/heavy-phase-semaphore/4a3be8baed76.md` wraps its none-rationale across lines — and separating "explanation prose" from "candidate list" needs exactly the prose recognizer §1.1.1 fences off. The accepting direction is pinned as an executable fixture (§6.2); the residual leak is the copy-forward author who appends candidates without touching the marker, and the round-threshold filing review is the human backstop.
8. **The score arm does not judge the declared value against the registry (R4 `below_floor` probe — fenced, not repaired).** `MUTATION SCORE: 0/1, 0 unaccepted survivors` is canonical, semantically possible, and passes the dispatch check even though both enrolled review-round surfaces carry `scoreFloor: 1`. Deciding floor-compliance at dispatch requires re-implementing registry semantics — per-surface `scoreFloor` plus accepted-row accounting live in `tests/mutation/source/registry.ts` and are verified by the gate's own multi-hour run — inside a plain-node CLI wrapper, which is the recognizer-growth failure mode the repair-economy rule exists to stop (three of four spec rounds landed on this one recognizer). The consequence bound holds without it: a below-floor declaration is LOUD — the value sits in the round-1 brief precisely so the reviewer reads it, and a reviewer facing "0/1" sees a red gate instantly. The dispatch gate forces the evidence to EXIST in canonical form; judging the stated value is the reviewer's and orchestrator's ground, like cannot-express probe quality (limit 2).
9. **The `OPERATORS:` tail is checked for presence, not membership (2026-08-22).** `OPERATORS: all` on a scoped row passes, and so does a tail naming an operator the registry row does not carry. Judging membership means re-implementing registry semantics — per-surface operator sets live in `tests/mutation/source/registry.ts` and `tests/mutation/source/operators.ts` — inside a plain-node CLI wrapper, which is the recognizer-growth shape item 8 fences for the identical reason. The consequence bound holds without it: the declared set sits in the round-1 brief the reviewer reads, so a scope narrower than the finding under argument is visible at the moment it matters. Contract: jurisdiction spec §4 L-A, `docs/superpowers/specs/ci/2026-08-22-mutation-score-jurisdiction-gap.md`.
